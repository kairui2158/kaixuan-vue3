# 意图语料成长路线图（单一登记项）

日期：2026-09-22  
状态：已确认执行；2026-09-22 已并入自动化对抗语料工厂（G0 加速器）  
成熟度：成熟（阶段可执行、指标可量化、关闭条件明确、失败路径和门禁完整）

## 1. 目标

把“语料积累不足”和“3 条 falseRejections”合并为一个登记项，并由自动化对抗语料工厂承担可合成的盲区发现与回归压力：

> 建立可持续的真实意图语料成长机制，先用 Silver 对抗集持续挖掘可复现盲区，再让路由校准从内置 28 条 trace 考卷，逐步切换到真实使用产生的 confirmed 考卷，并在数据充分后完成一次人工审核的阈值升级评估。

关闭后，该登记项不再存在，后续只保留常规版本回归，不再有“隐形新增登记项”。

> 版本定位更正：3.57.0 是“自动化工厂基础设施里程碑”，不是收敛交付。3.58.0 才是首个通过停止审计 S1-S6 的收敛交付版本；两个版本的角色必须分开登记，禁止用 3.57.0 的基础设施绿灯冒充收敛闭环。

## 3. 阶段设计

### Phase G0：自动化对抗语料工厂（已完成首轮）

已交付 `intentMutationEngine`、1000 字测试稿、工厂脚本与社区 Bronze 语料挖掘。首轮结果：seed 82、Silver 336、Bronze 1571；Silver 集写入安全硬约束为 0（writeFalseTriggers=0、missedRejections=0），长文档场景一致性 97.50%。

边界：Silver 永不进入 train/dev/test，也永不单独决定生产阈值；Bronze 只做盲区发现，必须经确定性变异或人工审核后才可升级为 Silver 候选。Gold 仍只来自真实用户 confirmed 样本。

### Phase G0-C：收敛 V2（3.58.0 交付）

3.58.0 通过停止审计完成收敛交付：账本末尾连续有效收敛轮为 18、19、20，三轮 Silver 五项失败指标全零；round-17 暴露的 `盘一盘` 标点变异缺口已在 round-18 修复，round-20 又新增 8 条真实扩库种子并保持全零。收敛身份采用“轮次报告 + corpus 输入 hash + Silver 指标 + 扩库动作 + 证据路径”组合账本，不把同输入集的行为修复轮重复计数。停止审计产物为 `_audit/intent-factory-stop-audit.json`，S1-S6 全部 PASS。

### Phase G1：真实使用采集（零客户额外成本）

客户正常使用应用即可。confirmed 样本只来自 fallback 气泡的显式选择；inferred 来自下一轮重述；observed 只做分布统计。

里程碑：

- G1-A：confirmed 样本达到 30 条（最小可用考卷规模）。
- G1-B：confirmed 样本达到 60 条时做一次分布健康检查；Silver 工厂已承担大量覆盖与回归压力后，Gold 校准需求降为 30 条，不再要求 60 条硬门槛。

判定方式：本地 `intent-corpus/manifest.json` + 导出语料包统计，不需要客户导出运行记录。

### Phase G2：语料包导出与真实校准

前置条件：G1-A 完成。

执行内容：

1. 导出当前项目语料包（schema：`shenyi.intent-corpus-package`）。
2. 用环境变量 `SHENYI_INTENT_CORPUS_PACKAGE` 接入校准脚本。
3. 完整重跑 `scripts/calibrate-intent-routing-thresholds.mjs`，产出真实语料校准报告。
4. 人工审核候选配置，不自动应用。

硬约束（继承 M52）：

- writeFalseTriggers = 0。
- missedRejections = 0。
- 禁止为降低 falseRejections 放宽写入安全阈值。

验收：

- 校准报告包含 train/dev/test 完整指标。
- 真实 confirmed 样本与影子语料零混入。
- 报告样本计数与导出包逐项一致。

### Phase G3：falseRejections 定性闭环

对 3 条既有误拒和 G2 新暴露的误拒逐条定性，分成四类处理：

| 类型 | 处理 |
| --- | --- |
| embedding margin 拦截 | 评估 margin-gate 异步 judge 是否启用，不直接调阈值 |
| 合理 ambiguous | 保留，不计为缺陷 |
| 语料覆盖缺口 | 扩充示例库，并按 M21 同步补正负样本 |
| 路由结构缺陷 | 修复路由结构，禁止用调阈值掩盖 |

关闭条件：每条 falseRejection 都有定性结论和对应处理；不允许出现“未分析先放宽阈值”。

### Phase G4：holdout 与 adversarial 持续集

建立固定 holdout 集，规则：

- holdout 不参与阈值选择，只做最终报告。
- 初始规模不少于 30 条，来源为真实使用样本，人工确认标签。
- adversarial 集继续从影子语料和真实误判中补充，只做盲区诊断。
- 每次示例库或阈值变化后，完整重跑校准和 Electron 验证（M47/M53）。

## 4. 总关闭条件

同时满足以下条件时，登记项正式关闭：

1. confirmed 样本不少于 30 条，四个意图类别尽量均衡；分布明显偏斜时先补充采样，不允许直接放宽阈值。
2. holdout 集不少于 30 条，且从未参与阈值选择；Silver 对抗集保持物理隔离，只做回归与盲区诊断。
3. falseRejections 全部定性完毕：写入安全硬约束保持为 0，未处理项为 0。
4. 基于真实语料的校准报告完整生成，候选配置经过人工审核。
5. 完整回归通过：专项测试、`type-check`、`build:vue`、Electron 八场景（含 1000 字手稿长上下文写入隔离场景）。

## 5. 执行节奏

- 日常：客户正常使用，无需任何操作。
- 每次 G1 里程碑达成：导出语料包，重跑校准。
- 每次校准：逐条审阅 falseRejections，更新定性表。
 - 每次阈值或示例库变更：完整跑 M47/M53 门禁，不使用旧证据。

## 6. 风险与防护

| 风险 | 防护 |
| --- | --- |
| confirmed 增长慢 | fallback 气泡保持轻量，不增加客户负担；G1-A 只需 30 条 |
| 样本分布偏斜 | Gold 校准需求已降为 30 条；达到 60 条时仍须做分布健康检查 |
| 语料污染 | 只有 confirmed 进校准；影子语料物理隔离 |
| 阈值过拟合 | holdout 独立，test 只报告不调参 |
| 安全回退 | 写入安全硬约束永久为 0 例外 |
| 证据过期 | 每次改动后完整重跑，不接受旧 baseline |

## 7. 当前缺口（透明列出，无隐藏项）

1. 真实 confirmed 样本数为 0，需要时间积累。
2. 应用内暂无“导出语料包到文件”的 UI 按钮，目前通过 Electron IPC 导出，后续可在设置页补一个导出入口。
3. holdout 集尚未建立，需在 G1-A 后从真实语料中人工确认。

这三项都在本路线图范围内，除此之外没有未登记的隐性缺口。
