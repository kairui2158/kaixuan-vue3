# 设定层分层语义约束方案（问题二）

## 1. 目标

把问题一交付的“锁定状态单源 + 四层统一投影”升级为“按层消费的语义约束”：

- 卷纲层拿到的是规划约束，服务卷结构、人物弧线、世界规则和卷级节奏。
- 章节层拿到的是章节规划约束，服务章节切分、剧情点、人物出场和场景选择。
- 正文层拿到的是执行约束，服务人物口吻、场景氛围、行为边界和事实连续性。
- 首页对话拿到的是共创上下文，服务用户当前讨论目标，不重复塞入三层流水线的完整约束。

本方案不改锁定语义本身：`draft | locked` 仍是唯一状态源；问题二只改变“锁定之后每层怎么消费”。

## 2. 承接判定

问题一已满足问题二的前置条件：

- 状态源已统一到 `settingsProjectionStatus()`，schema 4 迁移已完成。
- 卷纲、章节、正文、首页四个消费面都走 `getLockedSettingsForLayer()`。
- 旧的 `[绑定设定]` 重复通道已删除，trace 有 `settings-projection-composed`。
- 当前缺口是“分层只有名字，没有语义”：三层拿到同一份全量文本，首页还叠加触发词旁路。

结论：可以在问题一底座上继续做问题二，不需要推翻状态模型。

## 3. 现状缺口

1. `src/services/settingsProjection.ts` 只有 `volume | chapter | body` 三个枚举，实际输出完全相同。
2. `PipelinePanel.vue` 三处调用只换了 layer 名，prompt 中仍是同一个 `[设定]` 全量块。
3. `ChatPanel.vue` 注入 `body` 全量投影后，又用触发词另拼一份“触发匹配的设定条目”，存在双通道。
4. 设定分类是自由文本，没有规范化到语义类别，无法稳定判断“人物口吻”“场景”“世界规则”“物品”“风格”。
5. 正文层已有单元闭包与记忆上下文，但设定仍是全量数组，缺少与当前章节的相关性排序。
6. trace 只有数量与 hash，没有记录“为什么这项设定进入该层”，后续无法诊断漏注入或误注入。

## 4. 设计原则

1. **单源分层**：状态判定、分类规范化、层语义、相关性排序全部收敛在设定投影服务，禁止各层再自行拼装。
2. **SKILL 中立**：SKILL 只改变领域能力与提示词风格，不允许改变分层语义、执行协议或权限。
3. **不设固定字数/token 上限**：默认注入全部锁定设定；只有真实上下文预算不足时才做确定性裁剪，并写 trace。
4. **可解释**：每层 trace 记录策略版本、分类分布、入选/排除原因、裁剪原因和内容 hash。
5. **兼容既有产物**：不破坏 schema 4，不改变卷纲 `isBound/boundTo` 的卷-章节绑定语义。

## 5. 分层语义契约

### 5.1 卷纲层

输入：全部锁定设定 + 大纲 + 已生成卷事实。

语义块：

- `[设定规划约束]`
- 人物：核心身份、目标、关系、长期弧线约束。
- 世界观：不可违背的规则、边界、禁用设定。
- 势力/组织：卷级冲突与阵营约束。
- 主要场景：可用于卷结构布局的空间约束。
- 风格：卷级基调与叙事节奏约束。

输出要求：

- 卷纲必须在这些约束内分配卷数、字数、冲突升级和人物阶段。
- 不相关设定不强行注入；若预算不足，按“世界观 > 人物 > 势力 > 场景 > 风格”排序裁剪。

### 5.2 章节层

输入：全部锁定设定 + 当前卷纲 + 已生成章节事实。

语义块：

- `[章节规划约束]`
- 人物：本卷出场人物的目标、关系、行为边界。
- 场景：本卷可用空间与空间限制。
- 物品：关键道具的获取、使用、转移约束。
- 世界观：章节剧情不得违背的规则。
- 风格：章节节奏与叙事密度约束。

输出要求：

- 章节标题、剧情点、人物出场、场景选择必须遵守这些约束。
- 与当前卷无关的设定默认排除；若无法判断相关性，保守注入并记录 `relevance=unknown`。

### 5.3 正文层

输入：全部锁定设定 + 当前卷闭包 + 当前章节剧情点 + 上一章概要 + 记忆上下文。

语义块：

- `[正文执行约束]`
- 人物口吻：语言风格、说话密度、情绪表达、行为习惯。
- 场景氛围：空间感官、光线、声音、气味、动态元素。
- 事实边界：不可违背的世界规则、已发生事实、道具状态。
- 禁止项：不得提前揭示的终局底牌、不得漂移的人物关系。

输出要求：

- 正文对话与描写必须体现人物口吻，不允许所有角色同一腔调。
- 场景描写必须受场景设定约束，不允许空间漂移。
- 记忆与设定冲突时，以锁定设定为准，并在 trace 记录冲突。

### 5.4 首页对话层

输入：全部锁定设定 + 当前编辑目标 + 最近用户消息 + 当前选区。

语义块：

- `[当前上下文设定]`
- 只注入与当前讨论目标相关的设定。
- 保留人物、场景、世界规则的简明摘要。
- 不再叠加触发词旁路；触发词只作为相关性信号进入统一投影。

输出要求：

- 首页对话不承担流水线执行语义，只服务共创讨论。
- 当用户明确要求执行生成时，仍由对应流水线层负责，不在首页复制执行约束。

## 6. 实施步骤

### Phase 1：语义模型与投影服务

1. 新增 `settingsLayerSemantics.ts`：
   - 分类规范化：人物/角色、场景/地点、世界观/规则、势力/组织、物品、事件、风格、其他。
   - 层策略定义：每层的语义块标题、优先级、相关性信号、排除规则。
   - 相关性排序：基于分类、名称、触发词、当前目标文本、卷纲/章节剧情点。
2. 扩展 `settingsProjection.ts`：
   - 返回结构化 `blocks` 与 `text`。
   - 保留现有 `getLockedSettingsForLayer()` 作为兼容入口，内部委托新语义服务。
   - trace detail 扩展 `policyVersion`、`categoryDistribution`、`includedReasons`、`excludedReasons`、`trimmedReasons`。
3. 单测：
   - 分类规范化。
   - 每层语义块拼装。
   - 锁定过滤。
   - 相关性排序。
   - 预算裁剪与 trace 字段。

### Phase 2：四个消费面接线

1. `PipelinePanel.vue`：
   - 卷纲层改用 `volume` 语义块。
   - 章节层改用 `chapter` 语义块。
   - 正文层改用 `body` 语义块。
   - 三处 trace 使用同一新投影事件，不新增重复事件类型。
2. `volumeGeneration.ts`：
   - `settingsText` 改为语义投影文本，保持接口兼容。
3. `chapterExecutionPackage.ts`：
   - `settings` 接收语义化字符串数组，prompt 输出 `[正文执行约束]`。
4. `ChatPanel.vue`：
   - 删除触发词旁路拼装，触发词只进入统一投影服务。
   - 首页 system prompt 使用 `[当前上下文设定]`。

### Phase 3：trace 与可观测性

1. `settings-projection-composed` detail 增加：
   - `layer`
   - `policyVersion`
   - `lockedCount`
   - `draftExcludedCount`
   - `categoryDistribution`
   - `includedCount`
   - `excludedCount`
   - `trimmedCount`
   - `contentHash`
2. 新增 warning：
   - 设定分类无法识别。
   - 相关性无法判断。
   - 预算裁剪发生。
   - 记忆与设定冲突。

### Phase 4：验证

1. 单测与集成：
   - 四层 prompt 各自出现唯一语义块。
   - draft 设定被排除。
   - 触发词旁路清零。
   - trace 字段完整。
2. 全量回归：
   - `npm run test:services`
   - `npm run type-check`
   - `npm run build:vue`
3. 真实 Electron UI：
   - 真实点击锁定/解锁。
   - 真实运行卷纲、章节、正文、首页四条链路。
   - 断言每层请求 prompt 中出现对应语义块，且不出现其他层的执行语义。
   - 断言 trace 中包含新字段。
4. 真实用户路径证伪：
   - 王芳设定为“幽默、风趣、话痨”。
   - 正文生成后断言请求 prompt 含人物口吻约束，回复文本体现话痨风格。
   - 卷纲生成后断言请求 prompt 含规划约束，不出现正文执行措辞。
   - 首页对话后断言只注入相关设定，不重复注入触发词旁路。

## 7. 风险与边界

1. **分类自由文本**：旧项目分类可能不规范，需先做映射测试，未识别分类降级为“其他”并 warning，不阻塞生成。
2. **相关性误判**：默认保守注入，宁可多注入也不漏注入；只有明确无关才排除。
3. **上下文膨胀**：不做固定上限，只在真实预算不足时裁剪，且裁剪必须可追溯。
4. **SKILL 干扰**：语义块由应用单源生成，SKILL 不允许改写块标题和执行语义。
5. **外部 live 供应商**：默认用本地 OpenAI-compatible provider 验证应用链路；外部 live 矩阵如未执行，登记 `untested`。
