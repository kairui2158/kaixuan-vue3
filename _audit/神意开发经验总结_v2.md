## §1 改码纪律（M 系列 + 通用规则）

### M 系列：改动污染防御（最高优先级）

> 来源：A2 v-show 移除、C4 批量修复、08-30 ai-naming 整文件复制等多轮同模式失败。

- **M1 影响圈声明**：改任何文件前，用 `rg` 列出该文件被谁引用、该函数读写了哪些 store 字段。产出两个清单：「我打算改的」和「这个改动可能碰到的」。超出需求范围的字段/组件/事件一律不碰。
- **M2 整文件操作禁令**：禁止跨分支/worktree 整文件复制；禁止"重写整个文件顺手清理"。必须用 apply_patch 逐行精准编辑，每行 diff 能回答"这行为什么在这个需求里"。
- **M3 diff 自审门槛**：提交前 `git diff` 逐行过，每一行必须能归入本次需求。回答不了的行 = 污染，剔除或单独说明。
- **M4 隐藏状态保护**：改"显示/隐藏"逻辑前，先确认它是有意状态控制（v-show 导航）还是死代码。不确定时不动，标记 TODO。
- **M5 三面引用闭包**：删除类操作前，生产源码、测试脚本、历史资料三面搜索引用。引用未隔离前只关闭入口，不删实现。

### 通用改码规则

1. **行为等价**：新架构必须复现旧架构的行为语义，不只是代码语义。旧代码禁止直接复制。旧行为唯一基准：`C:\Users\凯瑞\Documents\New project 2\旧架构分析集`。
2. **新架构写法标准**：业务状态放 Pinia store，组件用 computed 读取，子组件通过 emits 通知父组件，联动靠 store 更新 + computed/watch。同一业务数据只有一份事实来源。
3. **一次一个闭环**：改码→构建→杀进程→重启→验证，闭环完成才进下一个。禁止批量改无关功能。
4. **先读代码再改**：用 apply_patch 编辑，验证后再声称完成。工具调用失败 2 次换方案。
5. **store 是唯一事实来源**：用户重新打开还需要的状态必须放 store 或 storage，禁止组件本地 ref 存业务数据。

## §2 脚本纪律（D/G/I/J 系列精选）

1. 选择器必须先诊断：用 `rg` 搜源码确认 ID/class 存在且唯一，禁止凭假设写选择器。ID 选择器必须加 `#` 前缀。（D3、I1、H1-H3）
2. 复杂脚本必须写 .cjs/.mjs 文件执行，禁止 PowerShell 内联嵌套引号/JSON/正则。超过两层嵌套直接写文件。（D5 + 08-31 三段式经验）
3. 所有写操作必须 try...finally cleanup，异常退出不留脏状态。检查脚本 100% 只读。（D1、D2）
4. `page.evaluate` 内 electronAPI 调用必须 async/await，返回值不能拼成 `[object Promise]`。断言持久化必须读真实业务字段。（J1）
5. CDP screenshot 必须设 3-15s 超时（`Promise.race`）并降级为视口截图，失败不阻塞状态断言。（D4、G4 + 08-30 screenshot 挂起）
6. 脚本执行后必须 `process.exit(0/1)` 显式退出，禁止依赖事件循环自然结束。（J 系列）
7. `v-show` 元素验证用 `getComputedStyle().display !== 'none'`，不用 `offsetParent`。`v-if` 元素条件不满足时不存在 DOM。（08-29 CDP 补充）
8. 每次切换会话/载体前，先确认上一个 Electron/CDP 实例是否存活。启动器 PTY 不能随意 Ctrl+C。（J2）
9. CDP 探针固定三段式：前置快照 → 业务操作 + 逐操作断言 → 恢复原状 + 清理核销（finally 段）。缺任何一段不算闭环。（08-30 CDP 探针三段式）
10. 每段结果写入同一个 JSON 输出文件，台账只引用 JSON 原始字段值。`allStepsOk` + `runtimeErrors:[]` 是最终 PASS 判据。（同上）
11. CDP 用 `Runtime.evaluate(async () => {...})` 包整段逻辑，返回值必须 `JSON.parse(result.result.value)`。（同上）
12. Node 侧没有 `document`——`Runtime.evaluate` 里的 DOM 代码是字符串模板由浏览器执行。写探针前分清 Node 跑什么、页面跑什么。（08-30 脚本教训）
13. Promise 未 await 排查法：先在探针里加 `await setTimeout(300)` 看是否好转——好转修探针，仍失败才升级为业务发现。探针时序问题不许顺手改业务代码。（08-30 Promise 排查法）
14. 溢出扫描从正确的滚动根上找元素：全页用 `root: body`，模态框用容器选择器。按 overflow 分三类，只有 `visible-vertical-overflow` 才算缺陷。（08-30 ancestor-scroll-clip）
15. monkey-patch 验证法：在 evaluate 里临时替换 `window.electronAPI` 方法，记录参数和返回值，finally 段还原。断言"调用发生过"用调用记录数组。（08-31 monkey-patch）
16. Playwright evaluate 只接受一个参数，多参数必须包成对象 `{ sel, key }` 传递。（G1）
17. 验证后必须 restore 原始配置，finally 中保证执行。真实 API 调用验证设 300s timeout，mock 与真实分开。（G2、G3）
18. 源文件 Electron 启动用仓库内完整路径 `node_modules\electron\dist\electron.exe`，参数 `. --remote-debugging-port=9227`，Hidden 窗口，启动后等 8 秒再连 CDP。（08-31 三段式经验第 2 条）
19. 流水线全屏面板关闭后必须显式点击 `#btn-close-pl` 再操作主页面，倒序关闭会被遮罩拦截。（08-30 脚本教训第 2 条）
20. 恢复项目时 store getter 同步但 IPC 持久化异步——`finally` 段读 `lastProjectId` 前要等恢复操作的 IPC promise 返回。（08-30 脚本教训第 3 条）
21. 多轮上下文探针的“当前轮次”必须读取最后一条 user 消息，禁止用整段 messages 拼接字符串包含历史标记来判定 phase；否则第二轮会被第一轮历史污染成第一轮。（09-01 P6 假失败根因）
22. mock AI 响应必须按 phase 显式映射，禁止根据“历史里是否包含某标记”返回内容；否则测试数据会反向污染业务断言。（同上）
23. 覆盖 aiService 心跳重试等待的 CDP 长事务超时至少 360s，短超时会把“仍在等待”误判成失败。（同上）
24. 上下文探针前后必须清理 `ctx-probe-*` 测试键和 `wa_lastProjectId` 残留；未恢复原项目时不得开始下一轮断言。（同上）

## §3 验证纪律（C/F 系列 + 规则 4/11 + 前置条件铁律）

1. **构建成功 ≠ 功能完成**：必须走真实 Electron + CDP 真实操作。代码能编译和运行时行为是两回事。（C2、C5、F1）
2. 验证必须递归：按钮存在 → 点击 → store 变化 → UI 响应 → 持久化。点击后检查弹窗、次级页面、返回。（C6、F3）
3. 没有证据的"已完成" = 未完成：必须引用 file:line 或命令输出。报告生成后读报告确认结论，不能只看 exit code。（C5、F4）
4. **验证作用域不扩大**：服务层测试不能当 UI 证据，受控 mock 不能当真实 API 证据。相同 class 可能出现在多个组件，测量必须限定作用域。（规则 11）
5. Vue 渲染等待：v-if 组件需异步渲染，CDP 检查前等 2.5s 或用 waitFor。点击后立即不存在可能只是时序误报。（规则 4 + 08-26 边界经验第 1 条）
6. 启动态清理：验证前先处理可见的遗留弹窗/面板，禁止盲点隐藏按钮。
7. 夹具检查：重启持久化验证必须先确认测试项目存在，否则结果是"夹具缺失"不是"功能失败"。
8. **生成前置条件铁律**：记忆抽取必须以真实已生成正文为输入。新建项目只有卷纲/章节概要时，编辑器 `disabled` 是合法空态。取消/失败重试/断点恢复必须在真实生成请求中核验。受控隔离项目可以验证入口但不能注入假数据制造通过证据。（08-26 规则 12）
9. **目标续验以当前轮新鲜证据校准旧日志**：发现历史记录与当前状态冲突时保留历史记录并在新日志中说明冲突，不得直接沿用旧结论或扩大范围。（08-26 补充规则第 11 条）
10. 安装包验证至少分三层：安装包生成 → 解包程序启动并可连 CDP → 真实页面入口/边界操作。最小烟测通过不能扩展为完整业务验收。（08-26 安装包边界）
11. 构建、类型检查、测试 runner、CDP 行为和安装包客户路径是五个独立验证门。一个门通过不得覆盖另一个门的未核销状态。（08-26 遗留核销补充规则第 4/10 条）
12. `start-electron.bat` 输出 `[OK] Application started` 不是进程存活证据。必须再检查实际进程、CDP 端口和页面 URL。（08-26 启动器续验第 1 条）
13. 阶段只有在前置条件、真实操作、DOM、store、持久化和下游联动均有本轮证据时才可勾选完成。（08-26 规则 12 第 5 条）
14. 验证报告写完后必须读报告确认结论行。多个测试按钮都要遍历检查，不能只检查第一个。（F3、F4）
15. 死 CSS 清理必须在模板改完后用源码搜索确认无引用再删。构建不会报 CSS 选择器无引用。（08-29 章节层 CDP 补充第 3 条）

## §4 删除纪律（规则 5 + M5 扩展）

1. 死代码清理先做三面引用闭包：生产源码、测试脚本、历史资料。引用未隔离前只关闭入口，不删实现。
2. 历史引用未隔离前不得删除旧模块，避免误删行为等价基准。（08-26 补充规则第 3 条）
3. Electron IPC handler、preload 暴露项先做引用闭包再删。dialog.js 旧 sync handler 不能直接删，preload 有引用。（08-25 效率优化第 9 条）
4. CSS 自动去重脚本禁止使用。每个删除必须手工确认。（A4）
5. 删除前确认用户要求的是"彻底删代码"还是"关闭入口"，默认后者。
6. 对被静态入口引用的动态 import，先判断它是否承担循环依赖隔离。没有等价性证据时不为消除构建警告而静态化或删除。（08-26 收尾补充第 4 条）
7. 删除死代码时优先从明确不可达分支开始。（08-26 收尾补充第 6 条）

## §5 UI 纪律（规则 7 + UI 快照提炼）

1. tokens.css 是唯一颜色/字号/间距变量来源，组件内禁止硬编码（组件级设计需除外）。（规则 7 + A3）
2. v-show 导航（流水线五层）是有意状态控制，禁止移除 v-show 改为 v-if 或全渲染。（A2）
3. 常驻 UI 卡片不能条件隐藏，空态显示"待 AI 分析"，不能整个消失。（08-21 风格卡修复）
4. 隐藏弹窗/未打开节点不能作为可见配色/布局证据，必须真实打开目标界面。
5. 死按钮扫描必须排除 v-show 隐藏区域。
6. 文字溢出验证必须逐弹窗、逐按钮、逐标签实测，不能只看一处通过就全量声明。（V1/V2-R1 复盘）
7. 弹窗递归验证三层：主页面 → 弹窗 → 弹窗内子弹窗。
8. flex 布局中标题类元素用 `min-width:0 + flex:1 1 auto`，禁止 max-width 固定截断。（08-20 P1-P5 第 2 条）
9. 页面级 `scrollWidth === clientWidth` 不等于内部控件没有溢出。必须递归扫描可见后代并读取矩形边界。（08-23 递归 UI 复查）
10. `scrollWidth > clientWidth` 不等于溢出：若同时有 overflow:hidden + text-overflow:ellipsis + white-space:nowrap，这是设计内省略，必须结合边界矩形和控件可见性判断。（08-25 设定层 P8-P9）
11. 小视口下 flex 子项被压缩为 0 是真实缺陷；overflow:hidden 会静默截断。应由明确滚动容器承载内容并保留可用最小高度。（同上）
12. 流水线进度弹窗的生成中可见性必须绑定"当前活跃层"，不能写成 `isGenerating || 本层日志存在`——其他层有历史日志时会跟着亮，形成跨层双弹窗。回归断言覆盖 `visible.length === 1`。（08-31 弹窗重叠修复）
13. 链式步骤的按钮语义决定作用域时，作用域必须在应用层双向强制：请求端 prompt 是"建议"，响应端必须按模式钳制数量（single=1 项、continue=剩余卷数），模型违反时截断并写日志。（08-31 卷纲逐卷生成）
14. 设定项多时采用紧凑列表 + 唯一当前项编辑区，避免框对框纵向拥挤。列表选择状态必须用稳定 `id`，不能用显示索引。（08-25 设定层 P3）
15. 大型列表必须有 `max-height` + `overflow-y: auto`，内容区用 `flex: 1 1 auto`。（08-25 设定层 P10 复核第 2 条）

## §6 交付纪律（规则 9 + 客户交付快照提炼）

1. 版本号按改动等级升级：bugfix → patch，新功能 → minor，重大架构 → major。
2. 封装前工作区必须干净（`git status --short` 为空或只有明确归档文件）。
3. 封装命令 `npm run build`，产出 `dist/神意助手-Setup-{version}.exe`。
4. 安装包未签名状态必须在交付说明中如实标注。
5. 客户实操反馈项必须明确列出，不能预标通过。
6. DEV_LOG 必须写明：已验证项 / 未验证项 / 客户实操入口。
7. 每次代码变动必须提交并推送 GitHub。提交前检查 `git status`，确认只包含本次变更。提交信息格式：类型: 组件 - 改动描述。（规则 9）
8. 收尾时不允许全局清理历史/用户文件。只删除本轮产生的临时探针，把未处理的工作区边界写入日志。（08-25 设定层 P10 第 6 条）
9. 临时探针删除后要用 `Test-Path` 或目录扫描复核。"已删除"不能只依赖编辑工具返回成功。（08-26 收尾补充第 8 条）
10. 只提交本轮改动的源文件 + 日志 + 经验文件。无关文件不暂存、不提交。（同上）

## §7 存储纪律（存储加固 + 持久化快照提炼）

1. **原子写盘四步**：写唯一 tmp 文件 → 旧主文件 rename 为 `.bak` → tmp rename 为主文件 → rename 失败时从 `.bak` 回滚。缺一不可，主文件永远是完整旧版或完整新版。（08-31 原子写盘）
2. 并发写同一 key 必须按 key 串行化（写队列 Map）。唯一 tmp 文件名只解决文件级冲突，不解决同 key 顺序冲突，两个都要。（同上第 2 条）
3. 读路径恢复语义：主文件 JSON 损坏 → 尝试 `.bak` → 恢复成功转正并写 `restored=yes` 日志。单代 `.bak` 恢复的是上一次保存版本而非最新版本。（同上第 3 条）
4. 验证损坏恢复必须制造真实损坏（直接改磁盘文件为非法 JSON），不能用 mock。重启后断言三点：数据从 `.bak` 恢复、`storage-corruption.log` 新增条目、读回值有效。（同上第 4 条）
5. **导入操作默认合并**，覆盖必须用户主动选择高级操作。（第三方检测反馈 + 08-26 记忆导入规则）
6. 项目数据隔离：不同项目的 storage key 必须含项目 ID（`wa_project_<id>`），禁止全局覆盖。
7. 旧配置兼容：读取时兼容老字段，保存后写新字段。
8. IPC 暴露三处同步：electron/ipc/*.js 注册 handler + preload.js 暴露 + renderer 调用。（08-21 S7-3）
9. 所有 IPC 从 sendSync 改为 handle + invoke 异步模式。同步 IO 改为 `fs.promises`。（08-25 效率优化第 1 条）
10. 异步化后调用方必须用 async 函数包裹 await。搜索所有调用异步 IPC 的文件逐一改。（08-25 效率优化第 2 条）
11. App.vue 启动时多个 store 初始化改为 `Promise.all` 并行加载，启动时间可减 30-50%。（08-25 效率优化第 3 条）
12. 跨重启持久化验证拆成 A/B/C 三段脚本，状态文件（`_audit/tmp/f_realops_state.json`）是段间记忆载体。（08-31 三段式）
13. 没有 `wa_project_*` 真实快照时，不得为了核验关闭重启而注入项目。正确结论是 `UNVERIFIED`。（08-26 遗留核销第 1 条）
14. 数据目录中存在 `wa_project_*.json` 只证明存在历史文件，不证明本轮客户项目恢复通过。必须有导入前/后配对快照和重启后的读取证据。（08-26 补充规则第 10 条）
15. `loadProject()` 必须信任磁盘状态，不得在加载时自动预建卷/章节/正文等业务数据；`ensureVolumesFromOutline()` 只允许在用户主动锁定大纲或创建项目等明确入口调用。（08-31 loadProject 占位卷修复）

## §8 AI 服务纪律（AI 层快照提炼）

1. 所有 AI 调用必须走 `aiService.callAi` 统一入口，禁止直接 fetch。SkillExecutionEngine 的 aiRequest 回调必须来自 aiService 适配器。（08-21 S5）
2. `provider.callApi` 保留为兼容壳但内部必须委托 aiService。删除旧入口前必须先做源码引用扫描。（08-25 统一入口收敛）
3. `stream` 默认值由统一服务层按用途决定，调用方只有在确有业务理由时才显式覆盖。统一入口不等于所有请求都强制流式。（08-25 统一入口收敛第 4 条）
4. 取消必须中止真实请求并清理空占位消息。统一 AI 入口必须在进入重试循环前检查外部 AbortSignal，已取消请求不得发出 fetch。错误路径测试必须同时断言错误分类和副作用（网络调用次数为 0）。（08-26 统一 AI 服务取消边界）
5. 流式/非流式超时分别配置。错误分类：network/timeout/http/json/auth/canceled，统一 error 对象结构。
6. aiService 重试策略：MAX_RETRIES 从 8 改为 3，RETRY_DELAYS 从 [2,4,6,8,10,12,15,20]s 改为 [1,2,3]s。用户 6 秒内获知失败，不能等 160 秒。应用层判失败后由供应商重试兜底，但必须有错误提示，不能静默失败。（08-25 效率优化第 5/10 条）
7. 诊断日志单路径写入：先写 executionLogStore.addLog，再写 DiagLogger.log + trackApiCall，禁止重复写。detail 必含 providerId/purpose/model/durationMs/skillId/result。（08-21 S7）
8. 诊断面板必须支持按 purpose 过滤。新增数据维度时必须同步在 UI 增加过滤入口。（同上 S7-4）
9. 链式步骤失败时明确区分 failed/skipped/fallback/continued，不伪装成正常完成。
10. 供应商用途必须是数组，支持一个供应商同时挂多个用途。卡片用途 UI 用 toggle 按钮组，编辑表单用 checkbox 组，禁止单选 select。旧配置兼容：string 自动归一化为 array。（08-21 S6）
11. "统一入口"必须按网络请求类型逐项列清：生成/验证/检测/模型获取/插件/MCP 不是同一语义。只有同一语义的网络调用才能合并。（08-26 补充规则第 1/6 条）
12. Pinia store 字段读取路径确认后再写验证脚本：getVerifyProvider() 读 verifyProvider ref，不是 providers 数组 purpose 字段。（08-21 S8-2）
13. 模型列表获取必须与生成调用统一到同一入口，错误边界一致。（08-26 P5 模型列表统一错误边界）
14. 上下文服务只能提供消息组装和会话存储，不得发起 HTTP；每个调用点必须同时核对请求参数、成功写回和失败副作用，服务层单测不能替代接入点证据。（09-01 上下文记忆 P1）
15. 上下文作用域至少包含 projectId、workspace、purpose 和 skillId；Agent 更换不能改变同一 SKILL 的会话键，chain 后续步骤的完整上一步输出必须使用独立上下文块传递。（09-01 上下文记忆 P1）
16. 失败、取消和空输出不得写入伪造 assistant 轮次；chain 失败必须明确停止或标记 skipped/fallback，不能把上一轮结果伪装成当前步骤成功。（09-01 上下文记忆 P1/P2 前置）

### 防无限回滚铁律（规则 12）

1. 每项任务完成勾选并经过 CDP 验证后，视为"终态闭环"，不可整体回滚重做。
2. 后续任务发现前期问题，只能在当前状态上做精准修复，不得回滚已完成的整个阶段。
3. 精准修复后必须重新验证该修复项，但不需要重新验证该阶段的其他已通过项。
4. 任何"我觉得可以做得更好"不是回滚理由。只有"功能行为与旧架构不一致"才是修复理由。
5. 回滚请求必须附带具体证据（哪个行为不一致、哪个按钮失效、哪个数据丢失），不得笼统回滚。
6. 已经通过 CDP 验证的截图和日志保留为不可推翻的证据，后续不得以"怀疑有问题"为由推翻。
7. 如果修复某功能导致新 bug，修复新 bug 即可，不需要回滚到修复前的状态从头来。
8. 勾选清单中的每一项一旦标记 [x] 并附带了验证证据，即视为永久完成，不可撤销。

### 经验回写铁律（规则 10）

1. 每次开发前必须读取本文件，确认已遵守全部规则。
2. 每次开发完成后必须更新本文件，记录新错误/新经验。新经验按区块归位，不追加尾部。
3. 每次开发完成后必须更新 DEV_LOG，按日期追加。
4. 经验总结和开发日志必须与代码变更一起提交 GitHub。
5. 禁止出现"改了代码但没更新文档"的未闭环状态。

