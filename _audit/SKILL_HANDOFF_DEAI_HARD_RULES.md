# 正文层去AI味硬规则交接说明（V2）

> 交接对象：第三方 SKILL 制作方  
> 适用范围：生成流水线「正文层」（step 4）与主页编辑器“去AI味”  
> 文档目的：说明 V2 硬规则模式如何工作、会改什么、不会改什么，避免 SKILL 设计时重复约束或与后处理冲突。

## 1. 一句话结论

正文层不是只靠 SKILL 降AI。应用内置两层机制：

1. **前置层**：API 调用前，把 17 条「降AI创作约束」追加进 system prompt，让模型生成时就遵守。
2. **后处理层**：API 返回后，按设置页的 `hardRuleMode` 决定“只检测报告”或“受控修复”。默认不会静默改写正文。

这两层都不依赖 SKILL 传入额外参数。SKILL 专注创作任务即可，不要在模板里重复写降AI规则。

## 2. 前置层：17 条方法论

- 来源：`src/services/de-ai.js` 的 `DEAI_METHODOLOGY_PROMPT`。
- 只在正文层生效，即 `step === 4`；大纲、设定、卷纲、章节层不注入。
- 文本 SKILL 与 folder SKILL 均覆盖。folder SKILL 执行时通过 `systemPromptSuffix` 注入。

## 3. 后处理层：三种硬规则模式

设置页「去AI味 → 硬规则模式」决定后处理行为，配置全局共享：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| `detect-report` 检测报告（默认） | 只检测问题，不改写正文 | 推荐。保留原始生成结果，先看报告 |
| `deep-fix` 深度修复 | 检测后调用模型做最小编辑，再过门禁 | 需要自动修复时使用；失败保留原文 |
| `legacy-auto` 兼容自动替换 | `processBody()` 白名单安全替换 | 兼容旧习惯；不会重组段落结构 |

### 3.1 检测报告模式

`detectBody()` 只输出报告，不修改输入文本：

```js
{
  findings: [
    {
      id: 'deai-freq-words',
      severity: 'blocking', // blocking=需处理，advisory=建议
      type: 'AI高频词',
      count: 1,
      perKilo: 37,
      samples: ['值得注意的是(1)'],
      suggestion: '改写为具体动作、具体事实或直接删除。'
    }
  ],
  metrics: {
    sentenceLengthCV,
    connectorDensity,
    protectedSpans: { total, hit, missing },
    retentionRatio
  }
}
```

blocking 通常包括：AI 高频词、禁用词、禁用句式超密度，破碎标点，保护片段缺失。advisory 通常包括：句长趋同、连接词偏高等。

### 3.2 深度修复模式

流程：

```text
检测报告
  ↓
提取保护片段（人名/对白/设定等）
  ↓
模型最小编辑（只修报告指出的问题）
  ↓
保护片段回对 + 完整性门禁
  ↓
通过 → 使用修复文本；失败/为空/API异常 → 保留原文
```

最小编辑提示词明确要求：最小修补、禁止整段重写、禁止回译、禁止压缩、禁止新增事实。

门禁包含：段落数不变、句末标点数不变、不新增破碎标点、长度比例 0.95-1.05、must 级保护片段不缺失。

### 3.3 兼容自动替换模式

使用 `processBody()` 与 `CLICHES_BODY_SAFE` 白名单。只做不会吞标点、不会删除内容、不会重组结构的替换；异常时由完整性门禁回滚原文。

## 4. 运行记录

流水线正文层生成时，运行记录会写入：

- `deai-detect`：完整检测报告 JSON。
- `deai-minimal-edit`：深度修复开始、失败回滚、完成与门禁数据。

用户可在「运行记录」面板按次查看或导出 JSON，第三方 SKILL 调试方可复现降AI处理现场。

## 5. 边界与安全机制

1. **默认不改写**：`detect-report` 模式下正文保持 API 原始输出。
2. **失败保原文**：深度修复 API 失败、结果为空、保护片段缺失或门禁不过，都会保留原文，不阻断正文保存。
3. **设置联动**：设置页 `hardruleEnabled` 总开关和硬规则模式对流水线正文层与主页编辑器均生效。
4. **metadata 不受影响**：后处理只作用于 `body`，`generationMetadata` 原样写入项目。
5. **无法绕过**：后处理在应用本地执行，不依赖 API 供应商，SKILL 无法关闭或绕过。

## 6. SKILL 层写作须知

1. **不要重复写降AI规则**。前置 17 条方法论已注入，重复会浪费上下文并造成约束冲突。
2. **不要假设应用会自动删词**。默认模式只报告不修改；要减少命中，应从生成源头写正向创作约束。
3. **不要在模板里承诺“最终输出会被清洗”**。V2 默认保留原文，用户可能只看报告。
4. **保护人名、设定、伏笔、对白**。深度修复会强制回对这些内容，SKILL 输出中丢失关键事实会被门禁拦下。

## 7. 快速自查

SKILL 输出正文后，可以按下面顺序自查：

1. 高频AI词是否集中在少数句子里？
2. 是否存在“值得注意的是 / 不可否认 / 综上所述”等套话？
3. 句长是否连续等长，缺少长短变化？
4. 人名、设定、伏笔是否完整保留？
5. 对白是否保留人物口吻，而不是解释剧情？

这些就是应用检测器的主要观察点。
