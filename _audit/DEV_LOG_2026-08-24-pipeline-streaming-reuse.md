# 2026-08-24 生成流水线复用大纲流式经验

## 检查结论

生成流水线存在与大纲工作台相同的根因：

- `PipelinePanel.vue` 的通用 `callApiWithAgent()` 固定使用 `stream: false`。
- `provider.ts` 的章节旧入口 `callApi()` 固定使用 `stream: false`。
- 设定、卷纲、章节原有 UI 只有请求前后阶段日志和进度条，没有把模型累计输出实时呈现。

## 修改

- 通用流水线调用改为 `stream: true`，将 `aiService.onChunk` 的累计文本更新到当前层 API 日志。
- 章节旧入口改为流式，并接入章节 API 日志。
- split-merge / multi-step 的执行参数改为开启流式。
- 保留原有取消生成、断点保存、重试和 JSON 解析逻辑，没有改供应商路由或业务数据结构。

## 验证

- `npm run build:vue`：exit 0，Vite `175 modules transformed`。
- 源文件 Electron + CDP：打开流水线后点击第 3 层，真实读取到 `pl-step-3-content`；点击“AI生成全卷”后读取到取消按钮、状态“链式生成中：1/2”、进度 `width: 40%`。
- 初次脚本错误命中隐藏的卷纲按钮，已重新按“点击第 3 层 → 确认可见 → 点击生成”复验；隐藏 DOM 不作为证据。
- 取消后取消按钮消失；本次供应商响应/断点行为仍需客户在其真实供应商配置下观察首字节日志，不把供应商网络速度写成应用通过。

## 经验

生成流水线已有进度条不等于已有流式 API 反馈。复用大纲工作台经验时要同时检查：请求是否 `stream:true`、当前层是否有临时输出承载、取消后是否恢复、半截结果是否落盘。每层日志有两种 DOM：无卷框时的占位日志和卷框内日志，验证必须选当前可见节点。
