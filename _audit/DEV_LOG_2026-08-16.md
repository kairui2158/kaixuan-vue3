## 经验教训
1. **CSS 高亮必须与 hover 区分**。章节选中状态和 hover 状态用相同背景色导致用户无法区分，这是常见 UX 缺陷。
2. **树形组件默认展开**。章节树首次加载时所有卷折叠，选中的章节可能不可见，需要自动展开选中项所在卷或默认展开第一卷。
3. **selectChapter 联动展开**。从其他路径（流水线、右键菜单）选中章节时，必须确保该章节所在卷已展开，否则用户看不到选中效果。
4. **PowerShell 替换的坑**：`-replace` 在多行匹配时需注意换行符，单行替换用 `$path` 变量比 `apply_patch` 更可靠。PowerShell 的 `-replace` 默认不跨行匹配 `.`（需 `(?s)` 标志）。
5. **先杀进程再启动**。修改代码后必须完整重启 Electron 进程才能加载新代码，热更新在此环境中不生效。
6. **Vue ref Proxy 不能直接传 Electron IPC**。`ipcRenderer.sendSync` 用 structured clone 序列化，Vue 3 的 `ref`/`reactive` Proxy 会触发 "An object could not be cloned" 错误，必须 `JSON.parse(JSON.stringify())` 深拷贝后再传。
7. **函数结构损坏是"按钮失效"的根源之一**。`addStepSkill` 的语法损坏导致模板中 `@change="addStepSkill(1)"` 直接抛错，所有 Skill 添加按钮全部失效。修复时要检查整个函数体的括号闭合，不能只看表面。
8. **行为等价验证必须走真实 UI**。用 CDP 模拟点击 → 检查 store 状态 → 检查 UI 渲染，三步都通过才算闭环完成。"代码编译通过"不算行为验证。
