## 引入点追账

1. **运行记录导出静默失效**
   - 引入提交：`e3abea2c`（3.106.0）。
   - 引入原因：`runTraceExportWorkerService.ts` 从同步导出改为 Worker 导出时，把 Pinia store 中的 reactive run 直接传给 `postMessage`，未做 cloneable 转换。
   - 放大因素：`RunTracePanel.vue` 同批保留 `console.warn` 静默失败路径，用户只能看到按钮无反应。
   - 当时缺口：3.106.0 发布验收没有把运行记录导出按钮列为真实 UI 回归路径。
2. **大纲消息滚动区鼠标无反应**
   - 引入形态：历史虚拟列表设计遗留。`.ow-messages` 长期为 `overflow: hidden`，虚拟列表依赖子滚动器，普通列表没有子滚动器时整体不可滚。
   - 放大因素：流式 `scrollToBottom()` 无节流且不识别用户滚动意图，用户向上滚动会被自动跟随抢回。
   - 引入提交：未定位。滚动容器语义早于近期 V6.3 提交；`64760cf3`、`b9d36d4c` 均已存在同类结构，说明不是 3.108.0 单点引入。
   - 当时缺口：V6.3 响应式收口只覆盖冻结、恢复、输入与专项路径，未把普通列表消息滚动列入发布回归面。
