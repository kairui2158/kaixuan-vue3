## 1. StorageManager 架构

**源文件**: js/storage.js (3.5KB)

StorageManager 是所有持久化数据的唯一入口，采用 IIFE 模块模式封装。

### 1.1 前缀与存储后端

- PREFIX = wa_
- _hasElectron = window.electronAPI && typeof window.electronAPI.storageRead === function
- Electron环境: 通过IPC storage:read/write/remove/list 读写文件系统(用户Documents/写作助手数据/目录)
- 浏览器环境: 降级到localStorage
- 所有key自动加wa_前缀

### 1.2 迁移机制

migrate()在init()时执行一次性迁移: 扫描localStorage中所有wa_前缀的键,复制到Electron文件存储。迁移后标记_migrated=true防止重复。

### 1.3 API 方法

| 方法 | 行为 | 返回值 |
|------|------|--------|
| get(name) | 读取wa_{name},JSON.parse失败则返回原始字符串 | 对象/字符串/null |
| set(name, data) | JSON.stringify后写入wa_{name} | boolean |
| remove(name) | 删除wa_{name} | boolean |
| list() | 列出所有wa_前缀的键,去掉前缀返回 | string[] |
| clearAll() | 删除所有wa_前缀的数据 | void |
| exportAll() | 导出所有数据为{key:value}对象 | object |
| importAll(data) | 批量导入 | void |

### 1.4 关键行为契约

1. get()内部做JSON.parse,如果解析失败返回原始字符串(容错设计)
2. set()内部做JSON.stringify,调用方传入对象即可
3. Electron模式下所有操作是同步的(ipcRenderer.sendSync)
4. 浏览器降级模式下使用localStorage(也是同步的)

## 3. 数据模型定义

### 3.1 Provider (供应商)

源文件: js/provider-manager.js

字段: id(prv_前缀), name, baseUrl, apiKey(存储时加密为enc:前缀), models(string[]|object[]), purpose(generate|verify|detect), streamMode(默认true), temperature(默认0.7), maxTokens(默认128000), systemPrompt, createdAt, updatedAt

API Key加密: 存储时用window.electronAPI.encrypt()加密为enc:+base64,读取时用decrypt()解密。加密通过Electron safeStorage.encryptString。

多供应商并行支持:
- getVerifyProviders(): 过滤purpose===verify的供应商
- getVerifyProvider(): 返回第一个验证供应商(含baseUrl/apiKey/model)
- getDetectProvider(): 返回检测供应商(如朱雀)
- setProviderPurpose(id, purpose): 设置供应商用途

### 3.2 Agent (智能体)

源文件: js/agent-manager.js

字段: id(ag_前缀), name, description, systemPrompt, provider(绑定供应商ID), model(绑定模型), temperature(默认0.7), maxTokens(默认128000), createdAt, updatedAt(ISO时间戳)

重要: Agent只是配置容器,无调度逻辑。在deAiProcess中仅读取model和temperature两个参数。

### 3.3 Skill (技能)

源文件: js/skill-manager.js

字段: id(sk_前缀), name, description, template(纯文本提示词,伪SKILL), category(默认通用), injectMode(默认system_prefix), bindTarget({type,id}), bindTargets(多目标数组,P2-31新增), linkedSkillIds(链式SKILL关联ID), createdAt, updatedAt

双绑定字段: bindTarget(单目标)和bindTargets(多目标数组)同时存在。getActiveForChapter()同时检查两个字段。

绑定类型: project(项目), volume(卷), chapter(章节), body(正文,全局生效)

### 3.4 Project (项目)

源文件: js/project-manager.js

字段: id(prj_前缀), name, outline(大纲文本), createdAt, updatedAt(ISO时间戳)

孤儿恢复机制: getAll()如果索引为空,调用_recoverOrphanedProjects()扫描磁盘上所有project-前缀的键,重建索引。

级联删除: delete(id)同时删除chapters_{id}和project-{id},防止恢复机制把已删除项目找回来。

### 3.5 Volume + Chapter (卷+章节)

源文件: js/chapter-manager.js

存储结构: chapters_{projectId} -> {volumes: Volume[]}

Volume字段: id(ch_前缀), projectId, name, outline(卷纲), skillIds[], chapterCount, order, chapters[](内嵌), createdAt, updatedAt

Chapter字段: id(ch_前缀), projectId, volumeId, title, outline(章节大纲), content(正文), order, summary, skillIds[], conversations[], createdAt, updatedAt

重要: Chapter内嵌在Volume.chapters数组中,不是独立存储。一个chapters_{projectId}键包含整个项目的所有卷和章节。

storeKey函数: chapters_ + projectId, projectId可能是对象(取.id属性)。

## 5. Electron主进程存储 (main.js)

源文件: main.js (15.4KB)

存储目录: Documents/写作助手数据/ (卸载重装不丢失)

文件命名规则: safeKey(key) = key.replace(/[^a-zA-Z0-9_-]/g, _), 文件名 = safeKey(key) + .json
重要: 中文字符会被替换为_

数据迁移: migrateOldDataIfNeeded()从旧路径%APPDATA%/写作助手/data/迁移到Documents/写作助手数据/。通过.migrated标记文件防重复。

窗口状态持久化: userData/window-state.json, 格式{x,y,width,height,maximized}

错误日志: userData/logs/error-YYYY-MM-DD.log, 格式[ISO时间戳]消息。通过process.on(uncaughtException)和process.on(unhandledRejection)捕获。

诊断日志: userData/diag-logs/diag-YYYY-MM-DD.jsonl, 每行一个JSON对象。

单实例锁: app.requestSingleInstanceLock()防止多实例。second-instance事件恢复已有窗口。

GPU: 保持硬件加速启用。之前的disable-gpu-compositing导致严重卡顿。

## 9. 关键行为契约 (12条)

1. StorageManager.get()容错: JSON.parse失败时返回原始字符串,不抛异常
2. StorageManager.set()序列化: 内部JSON.stringify,调用方传对象
3. Provider API Key加解密: 存储时加密(enc:前缀),加载时解密。加密失败保留明文
4. Provider旧数据迁移: loadAll()检查localStorage旧键并迁移到StorageManager
5. Project级联删除: delete(id)同时删除chapters_{id}和project-{id}
6. Project孤儿恢复: getAll()索引为空时扫描磁盘重建
7. Chapter内嵌存储: Chapter不独立存储,嵌在Volume.chapters数组中
8. Skill双绑定兼容: 同时检查bindTarget(单)和bindTargets(多)
9. IPC同步优先: 除fetchModels(invoke)外全部sendSync
10. 文件名安全化: safeKey()替换所有非[a-zA-Z0-9_-]字符为_
11. 数据目录持久化: 存储在Documents/写作助手数据/,卸载不丢失
12. UID全局唯一: prefix+Date.now().toString(36)+random确保跨实体不冲突

## 10. Vue3迁移注意事项 (8条)

1. StorageManager->Pinia store+electron-store: Vue3中应用Pinia store包装StorageManager,底层IPC调用不变。polyfill必须正确实现storageRead的JSON.parse(已知致命缺陷: Vue3 polyfill返回原始字符串未parse)
2. Provider加密: Vue3中API Key加解密必须走IPC,不能在前端做。preload.ts需暴露encrypt/decrypt
3. Agent无调度: Vue3中Agent仍为配置容器,调度逻辑在SkillExecutionEngine和deAiProcess中
4. Skill双绑定: Vue3中bindTarget和bindTargets需同时支持,getActiveForChapter逻辑需完整移植
5. Chapter树形存储: Vue3中考虑是否拆分为独立Chapter存储(当前全量加载到内存,200+章时性能可接受)
6. IPC同步阻塞: sendSync会阻塞渲染进程,Vue3中可考虑改为invoke(异步),但需评估对现有同步逻辑的影响
7. Project级联删除: Vue3中删除项目时必须同时清理chapters_{id}和project-{id},否则孤儿恢复会把已删项目找回来
8. safeKey文件名: Vue3中main进程的safeKey逻辑必须保留,否则中文键名会导致文件系统问题

## 11. SkillExecutionEngine数据流 (skill-engine.js)

源文件: js/skill-engine.js (19KB)

SkillExecutionEngine是技能执行的核心引擎,提供三种执行模式:

### 11.1 chain模式(串行链式)
输入文本 -> [Skill1] -> [Skill2] -> ... -> [SkillN] -> 输出
每步: 上一步输出作为下一步输入。每步有验证器,验证失败自动重试一次。

### 11.2 splitMerge模式(切分并行)
输入文本 -> _splitText(targetSize) -> N段 -> Promise.all(每段并行调Skill1) -> 拼接 -> [可选Skill2合并] -> 输出
_splitText算法: 按段落分割,累积到minSize~maxSize范围,超长段落按句号/问号/感叹号断句,最后一段太短则合并到前一段,段间添加overlapContext(最多150字),并发度默认3

### 11.3 multiStep模式(多步代码控制)
输入文本 -> _splitText(splitSize=1500) -> N段 -> Step1并行提取事件核(skills[0]) -> Step2并行选偏转视角(skills[1]) -> Step3并行重组输出(skills[2]) -> [可选Step4:S2验证(skills[3])] -> 拼接 -> 最终验证 -> 输出
每步有验证器: Step1后event_core_count检查, Step2后perspective_rotation检查, Step3后first_subject_different检查(首句主语与原文不同),相同则重试

### 11.4 getAutoValidators
根据type返回验证器配置:
- settings: validators=[json_array, field_exists(name)], finalValidators=[field_exists(name,category,attrs)]
- volumes: validators=[json_array, min_length(50)], finalValidators=[field_exists(name,outline,summary,suggestedWords), field_min_length(outline,500), json_escape_valid]
- chapters: validators=[json_array, field_exists(title,plot)], finalValidators=[field_exists(title,plot), field_min_length(title,1), field_min_length(plot,200), json_escape_valid, exact_count]
- body: validators=[min_length(500)], finalValidators=[prose_metadata_exists, prose_scene_count_match, prose_min_length, analysis_word_detection]

## 13. SkillTemplateEngine (skill-template-engine.js)

源文件: js/skill-template-engine.js (5.6KB)

支持script标签内嵌沙箱执行:
- extractScripts(template): 提取script块和文本块
- runSandboxed(scriptCode, context): 在受限scope中执行脚本
- replaceVars(text, context): 替换{{varName}}变量
- render(template, context): 主渲染函数

沙箱限制: 阻止访问require/process/fs/window/document/eval/fetch/localStorage等。

场景变量定义:
- volume: outlineContent, volumeCount, wordsPerVolume, novelTitle, styleTags, pacingParams
- chapter: volumeOutline, chapterCount, wordsPerChapter, styleTags, pacingParams, novelTitle
- body: chapterTitle, chapterSummary, prevChapterSummary, characters, novelTitle, chapterPlot
- deai: selectedText
- dialogue: selectedText, novelTitle, outlineContent, chapterSummary, characters, chapterTitle
