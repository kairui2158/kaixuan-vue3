# T15 - 编码与文本处理层 (Encoding & Text Processing Layer)

> 旧架构行为手册 第十五层 | 源码权威参考 | Vue3迁移差异检测驱动依据

## 1. 层级定位与职责边界

编码与文本处理层负责字符编码、JSON序列化反序列化、文本截断、字符串处理等底层文本操作。

## 2. 字符编码

### 2.1 UTF-8无BOM

规则13强制要求：所有源文件必须以无BOM的UTF-8编码保存。main.js的文件读写都指定utf8编码：fs.readFileSync(file, "utf8")、fs.writeFileSync(file, data, "utf8")。

### 2.2 编码安全规则

规则13禁止：使用PowerShell的Set-Content -Encoding UTF8修改含中文源文件（会添加BOM）；使用Out-File、Set-Content、Add-Content等PowerShell cmdlet写入含中文源文件。必须使用Node.js fs或apply_patch。

### 2.3 TextDecoder

流式响应用TextDecoder解码二进制：new TextDecoder()。decoder.decode(chunk.value, { stream: true })支持流式解码（多字节字符跨chunk时正确处理）。

## 3. JSON处理

### 3.1 序列化

StorageManager.set: JSON.stringify(data)。存储前序列化为字符串。

### 3.2 反序列化

StorageManager.get: try { return JSON.parse(raw); } catch(e) { return raw; }。反序列化失败返回原始字符串。

### 3.3 JSON转义

SKILL输出要求JSON字符串值内换行符转义为\n，双引号转义为\"。模型可能输出字面换行或裸ASCII双引号导致JSON.parse失败。旧架构在skill-validators.js中校验JSON转义但不在存储层校验。

### 3.4 JSONL格式

诊断日志使用JSONL格式（每行一个JSON对象）。写入：batch.map(e => JSON.stringify(e)).join("\n") + "\n"。读取：split("\n")逐行JSON.parse，失败跳过。

## 4. 文本处理

### 4.1 字数统计

编辑器字数统计：计算中文字符数+英文单词数。典型实现：text.replace(/\s/g, "").length（简单字符计数）或中文按字英文按词的混合计数。

### 4.2 文本截断

项目名称回退链中使用outline.substring(0, 20)截取前20字作为项目名。

### 4.3 safeKey

main.js safeKey函数：key.replace(/[^a-zA-Z0-9_-]/g, "_")。将键名中非安全字符替换为下划线，确保文件名安全。

### 4.4 URL处理

模型列表获取时URL拼接：baseUrl.replace(/\/+$/, "") + "/models"。先去除末尾斜杠再拼接。

API请求URL：baseUrl + "/chat/completions"。直接拼接不做斜杠处理（潜在bug：如果baseUrl以/结尾会变成//chat/completions）。

## 5. markdown处理

聊天消息使用marked库解析markdown为HTML，通过v-html注入。旧架构没有对marked输出做XSS sanitize（已知安全隐患）。

## 6. Vue3迁移差异检测要点

必须保留：UTF-8无BOM编码；JSON.parse失败返回原始字符串；JSONL日志格式；safeKey字符替换；TextDecoder流式解码。

可改进：API请求URL拼接做斜杠处理；marked输出做XSS sanitize；JSON转义在存储层校验而非仅SKILL层。

差异检测规则：文件编码UTF-8无BOM必须保持；JSON.parse失败返回原始字符串必须保持；JSONL格式必须保持；safeKey正则必须保持。

## 7. 已知问题

1.API请求URL不做末尾斜杠处理 2.marked输出无XSS防护 3.JSON转义只在SKILL层校验 4.字数统计可能不准确
