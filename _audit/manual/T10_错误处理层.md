# T10 - 错误处理层 (Error Handling Layer)

> 旧架构行为手册 第十层 | 源码权威参考 | Vue3迁移差异检测驱动依据

## 1. 层级定位与职责边界

错误处理层负责应用全生命周期的错误捕获、分类、恢复和记录。它是应用稳定性的最后一道防线。

职责范围：try-catch错误捕获模式；错误分类（网络错误/存储错误/解析错误/UI错误）；错误恢复策略（重试/降级/静默忽略）；错误日志记录（ErrorLog/DiagLogger/console）；全局未捕获异常处理；IPC错误处理。

## 2. 错误处理模式分类

### 2.1 静默忽略模式

特征：try-catch块内catch为空或仅console.error，不抛出不恢复。

使用场景：窗口状态加载失败（main.js loadWindowState L10-12）、ErrorLog写入失败（main.js L35）、storage迁移失败（main.js L201）、日志解析失败（JSON.parse单行跳过）。

行为契约：失败不阻塞功能；返回null或默认值；错误信息可能写入console但不写入ErrorLog。

Vue3迁移注意：静默忽略可能导致数据丢失但不被察觉。建议至少加入DiagLogger记录。

### 2.2 返回默认值模式

特征：catch块返回false/null/空数组，调用方通过返回值判断成功失败。

使用场景：StorageManager.get返回null（storage.js L39）、StorageManager.set返回false（storage.js L53）、storage:read返回null（main.js L216）、storage:write返回false（main.js L226）、storage:list返回空数组（main.js L248）。

行为契约：异常被完全捕获不传播；返回值明确表示成功或失败；调用方负责处理失败情况。

### 2.3 重试模式

特征：catch块内根据错误类型决定重试或抛出，配合retryDelays数组递增等待。

使用场景：_aiRequest的8次递增重试（renderer_v2.js）、心跳重连无限重试。

行为契约：可重试错误（429/502/503/超时/网络错误）触发重试；不可重试错误（401/403/404）直接抛出；重试次数有上限（8次）；重试耗尽后进入心跳模式或抛出。

### 2.4 降级模式

特征：功能不可用时降级到替代方案。

使用场景：Electron不可用时降级为localStorage（storage.js L2-3）、safeStorage不可用时降级为明文存储（main.js L157）、JSON.parse失败时返回原始字符串（storage.js L40）、fullText为空时用reasoningText回退（_aiRequest）。

行为契约：降级不阻塞核心功能；降级后行为与正常模式一致（调用方无感知）；降级状态可能通过console.log记录。

### 2.5 抛出传播模式

特征：catch块重新抛出异常或抛出新错误，由上层处理。

使用场景：_aiRequest重试耗尽后throw lastErr、cfg.signal.aborted时throw e（不重试外部取消）。

行为契约：异常传播到调用方；调用方必须有自己的try-catch；异常信息保留原始message。

## 3. 全局错误处理

### 3.1 主进程全局错误

源码位置: main.js L143-149

process.on("uncaughtException", function(e) { ErrorLog.write("UNCAUGHT: " + (e && e.stack ? e.stack : String(e))); });
process.on("unhandledRejection", function(reason) { ErrorLog.write("UNHANDLED_REJECTION: " + String(reason)); });

行为：捕获所有未处理异常和Promise rejection，写入ErrorLog文件。不崩溃应用不退出。

### 3.2 IPC错误处理

每个IPC处理器都有独立的try-catch，失败时设置event.returnValue为安全默认值并写入ErrorLog。

模式：try { ... event.returnValue = result; } catch(e) { ErrorLog.write("xxx failed: " + e.message); event.returnValue = null/false/[]; }

关键不变量：event.returnValue必须被设置（sendSync协议要求），否则渲染进程会永久阻塞。

### 3.3 渲染进程错误处理

渲染进程的错误通过console.error/console.warn输出，严重错误通过DiagLogger记录。没有全局window.onerror处理器（已知缺陷）。

## 4. 错误分类体系

### 4.1 网络错误

- HTTP 429: 请求太频繁，触发重试
- HTTP 502/503: 服务不可用，触发重试
- HTTP 400: 请求参数错误，尝试max_tokens减半重试
- HTTP 401: API Key无效，不重试
- HTTP 403: 访问被禁止，不重试
- HTTP 404: 接口不存在，不重试
- HTTP 500: 服务器内部错误，不重试（但根据代码实际会重试因为不在_noRetry列表中）
- TimeoutError: 超时，触发重试
- AbortError: 外部取消，不重试
- stream_idle_timeout: 流式空闲超时，触发重试
- 网络断开: fetch抛出TypeError，触发重试

### 4.2 存储错误

- 文件不存在: 返回null（正常行为非错误）
- 文件写入失败: 返回false，记录ErrorLog
- JSON.parse失败: 返回原始字符串（降级）
- 目录创建失败: 记录ErrorLog，可能导致后续操作全部失败

### 4.3 解析错误

- SSE JSON.parse失败: console.warn跳过该行
- 诊断日志JSON.parse失败: 跳过该行
- API响应JSON.parse失败: 返回{ ok: false, error: "JSON parse failed" }

### 4.4 UI错误

- DOM元素不存在: 静默返回（if (!ed) return模式）
- 事件监听器错误: 通过console.error输出

## 5. 错误恢复策略

### 5.1 自动重试

触发条件：网络错误（429/502/503/超时/空闲超时/非客户端错误）。最多8次递增等待。重试期间应用继续运行不阻塞。

### 5.2 心跳重连

触发条件：8次重试全部失败。每60秒探测一次API可用性。成功后恢复原始请求。无限循环直到恢复。

### 5.3 降级运行

触发条件：Electron不可用、safeStorage不可用、JSON.parse失败、fullText为空。降级到替代方案继续运行。

### 5.4 数据恢复

触发条件：项目索引为空但磁盘有项目文件。扫描磁盘重建索引。写回StorageManager防止再次扫描。

## 6. 错误日志体系

### 6.1 ErrorLog（主进程）

源码位置: main.js L27-36

追加写入%APPDATA%/写作助手/logs/error-YYYY-MM-DD.log。格式：[ISO时间戳] 消息。写入失败静默忽略。按日期分文件。

### 6.2 DiagLogger（渲染进程）

源码位置: js/diag.js

DiagLogger提供更细粒度的诊断日志：perfStart/perfEnd（性能追踪）、trackApiCall（API调用记录）、warn/error（警告错误记录）。日志通过diag:write IPC批量写入JSONL文件。

### 6.3 console输出

console.log: [OK]标记正常操作。console.warn: [WARN]标记警告和重试。console.error: [ERR]标记严重错误。

## 7. Vue3迁移差异检测要点

### 7.1 必须保留的行为

1.五层错误处理模式（静默/默认值/重试/降级/抛出）2.全局uncaughtException和unhandledRejection捕获 3.IPC每个处理器独立try-catch 4.event.returnValue必须设置 5.ErrorLog按日期分文件 6.DiagLogger性能追踪和API调用记录 7.错误分类体系（网络/存储/解析/UI） 8.心跳重连恢复策略 9.数据恢复机制

### 7.2 可改进的行为

1.添加渲染进程window.onerror全局处理器 2.ErrorLog增加日志轮转（防止文件过大）3.DiagLogger增加错误聚合（相同错误不重复记录）4.错误分类更细粒度 5.用户可见错误提示（目前大部分错误用户看不到）

### 7.3 差异检测规则

ErrorLog路径userData/logs/必须保持；DiagLogger路径userData/diag-logs/必须保持；日志格式[ISO时间戳]消息必须保持；JSONL格式每行一个JSON必须保持；IPC event.returnValue必须设置必须保持；全局uncaughtException捕获必须保持。

## 8. 已知问题

1.渲染进程无全局window.onerror处理器 2.ErrorLog无日志轮转可能文件过大 3.部分错误静默忽略可能导致数据丢失不被察觉 4.DiagLogger的warn和error没有聚合机制 5.HTTP 500实际会被重试因为不在_noRetry列表中但errMap有映射
