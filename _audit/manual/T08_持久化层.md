# T08 - 持久化层 (Persistence Layer)

> 旧架构行为手册 第八层 | 源码权威参考 | Vue3迁移差异检测驱动依据

## 1. 层级定位与职责边界

持久化层是旧架构数据生命周期的核心基础设施。负责所有用户数据的写入读取删除迁移和备份，是应用状态在会话间延续的唯一保障。

职责范围：用户数据（供应商配置智能体配置技能配置项目数据章节数据）的序列化存储；API Key 加密存储与解密读取；窗口状态持久化；诊断日志文件持久化；数据导入导出；数据迁移（localStorage到文件存储、APPDATA到Documents目录）。

不负责：数据业务逻辑校验（由各Manager负责）；UI状态管理（由事件层状态机负责）；网络请求（由网络层负责）。

## 2. 存储架构总览

旧架构采用双模式存储设计，Electron环境用文件系统持久化，浏览器开发环境降级为localStorage。

### 2.1 存储模式检测

源码位置: js/storage.js L2-3

存储模式在模块加载时一次性检测，结果缓存在闭包变量_hasElectron中：

var _hasElectron = (typeof window !== "undefined" && window.electronAPI && typeof window.electronAPI.storageRead === "function");

检测逻辑链：1.检查window对象存在 2.检查window.electronAPI被preload注入 3.检查storageRead函数可调用。降级策略：检测失败自动降级为localStorage不抛异常。

Vue3迁移注意：Vue3响应式系统在模块加载时触发，需确保StorageManager在Pinia store初始化前完成模式检测。建议在main.ts的app.mount()之前调用StorageManager.init()。

### 2.2 存储键命名规范

源码位置: js/storage.js L5-7

所有存储键统一添加前缀wa_防止冲突：var PREFIX = "wa_"; function key(name) { return PREFIX + name; }

实际存储键示例：wa_providers（供应商列表）、wa_active-profile（激活供应商ID）、wa_agents（智能体列表）、wa_skills（技能列表）、wa_projects（项目索引）、wa_chapters_{projectId}（项目章节数据）、wa_project-{projectId}（项目独立数据文件）。

键安全处理：main.js文件存储层用safeKey()将非安全字符替换为下划线：function safeKey(key) { return key.replace(/[^a-zA-Z0-9_-]/g, "_"); }

### 2.3 数据序列化策略

源码位置: js/storage.js L35-42

所有数据以JSON字符串存储。get()读取时尝试JSON.parse，失败则返回原始字符串：

try { return JSON.parse(raw); } catch(e) { return raw; }

行为契约：输入存储键名（不带前缀）；输出反序列化后的JS对象数组或原始字符串或null；JSON.parse失败返回原始字符串而非抛异常；storageRead失败返回null而非抛异常。

Vue3迁移注意：Pinia持久化插件默认用JSON序列化，需兼容parse失败返回原始字符串的行为，否则旧数据迁移时可能丢失。

### 2.4 数据写入策略

源码位置: js/storage.js L43-54

set()方法先JSON.stringify再写入。写入是同步IPC调用（sendSync），返回布尔值。JSON.stringify可能因循环引用抛异常被外层try-catch捕获。storageWrite阻塞渲染进程直到主进程完成文件写入。

## 3. Electron文件存储层

### 3.1 存储目录结构

源码位置: main.js L177-181

function getStorageDir() { var dir = path.join(app.getPath("documents"), "写作助手数据"); if (!fs.existsSync(dir)) fs.mkdirSync(dir, { recursive: true }); return dir; }

存储目录：C:\Users\{用户名}\Documents\写作助手数据\。设计决策：数据存储在用户文档目录而非APPDATA，目的是让数据在卸载重装后仍保留。每个存储键对应一个.json文件。

### 3.2 IPC存储通道

源码位置: preload.js L6-13, main.js L206-289

preload.js通过contextBridge暴露7个存储IPC方法：storageRead(storage:read,同步,返回string/null)、storageWrite(storage:write,同步,返回boolean)、storageRemove(storage:remove,同步,返回boolean)、storageList(storage:list,同步,返回string[])、storageExport(storage:export,同步,返回{success,count})、storageImport(storage:import,同步,返回{success,count})、storageGetDataDir(storage:getDataDir,同步,返回string)。

所有存储IPC都是同步的（sendSync），渲染进程在等待文件IO完成期间完全阻塞。对于小文件通常无影响，但大量章节数据可能数百KB会有短暂卡顿。

Vue3迁移注意：Vue3响应式更新是异步的，存储IPC是同步的。在Pinia store action中调用存储时需注意时序：先更新响应式状态再调用同步存储避免UI卡顿。

### 3.3 存储读取流程

源码位置: main.js L206-218

每次读取前先执行migrateOldDataIfNeeded()（幂等有标记文件防重复）。将key经safeKey()清洗后拼接文件路径。同步读取文件内容fs.readFileSync。文件不存在返回null。任何异常返回null并写错误日志。event.returnValue必须设置（sendSync协议要求）。返回字符串是文件原始UTF-8内容，JSON.parse在StorageManager层完成。

### 3.4 存储写入流程

源码位置: main.js L220-228

写入前执行migrateOldDataIfNeeded()。同步写入fs.writeFileSync覆盖已存在文件。成功返回true失败返回false并记录日志。data参数是已JSON.stringify的字符串。

原子性：fs.writeFileSync不是原子操作，进程崩溃时文件可能截断或损坏。旧架构未实现写入原子性（如先写临时文件再重命名），是已知技术债务。Vue3迁移应考虑原子写入。

### 3.5 存储删除流程

源码位置: main.js L231-239。先检查文件存在再删除，文件不存在不报错返回true。

### 3.6 存储列表流程

源码位置: main.js L241-249。读取目录下所有.json文件，返回文件名数组（去掉.json后缀）。StorageManager.list()进一步过滤wa_前缀键并去前缀。注意：main.js中storage:list的IPC处理器注册了两次（L241和L430），第二个覆盖第一个，是已知bug。

## 4. 数据迁移机制

### 4.1 localStorage到文件存储迁移

源码位置: js/storage.js L9-28

StorageManager在init()时执行一次性迁移：遍历localStorage中wa_前缀键，通过storageWrite写入文件存储，设置_migrated标记防重复。ProviderManager有额外迁移：loadAll()时检查StorageManager是否已有providers数据，没有则从localStorage读取旧数据写入。

### 4.2 APPDATA到Documents目录迁移

源码位置: main.js L183-202

migrateOldDataIfNeeded()函数：检查.migrated标记文件存在则跳过；检查旧目录APPDATA/写作助手/data/存在；逐文件复制到新目录Documents/写作助手数据/；只复制目标不存在的文件不覆盖新数据；写入.migrated标记文件含迁移数和时间戳。在每次storage:read/write/list调用前执行（标记文件保证只执行一次）。迁移是复制不是移动，旧数据不删除。

### 4.3 项目数据恢复机制

源码位置: js/project-manager.js L17-40

ProjectManager有孤儿项目恢复：getAll()返回空列表时扫描磁盘所有project-前缀存储键重建索引。从项目数据文件提取id/name/outline/时间戳。恢复后写回StorageManager。项目名称回退链：projData.name > outline前20字 > 恢复项目_ID后6位。

Vue3迁移注意：此恢复机制是安全网，应保留或用等效逻辑替代。

### 4.4 项目删除级联清理

源码位置: js/project-manager.js L97-106

删除项目清理3处：项目索引（projects数组条目）、章节数据（wa_chapters_{id}.json）、项目数据文件（wa_project-{id}.json）。级联删除确保恢复机制不会把已删除项目找回来。

## 5. API Key加密存储

### 5.1 加密解密机制

源码位置: main.js L151-174, preload.js L8-9

使用Electron safeStorage API。加密后值以enc:前缀标识Base64编码。解密时检查enc:前缀，非enc:开头视为明文直接返回。safeStorage使用OS级密钥链（Windows DPAPI macOS Keychain Linux libsecret），绑定当前用户账户。加密不可用时降级为明文存储不阻塞功能。

### 5.2 Provider加密集成

源码位置: js/provider-manager.js L19-48

加载时解密：从StorageManager读取供应商列表，遍历检查apiKey是否enc:开头，是则调用electronAPI.decrypt解密，解密失败保留加密形式。保存时加密：深拷贝供应商列表JSON.parse(JSON.stringify)，遍历副本检查apiKey不以enc:开头（防重复加密），是则调用electronAPI.encrypt加密，将加密副本写入StorageManager。

关键不变量：内存中apiKey始终明文，磁盘上apiKey始终密文，已加密值不重复加密，深拷贝确保加密不影响内存对象。

## 6. 各Manager持久化模式

### 6.1 通用模式

所有Manager遵循相同模式：读取StorageManager.get(KEY)||defaultValue；写入StorageManager.set(KEY,fullList)；单次全量写入每次修改写整个列表；无缓存每次读取从StorageManager获取最新数据。优点简单可靠，缺点性能开销每次操作读写整个列表。

### 6.2 ProviderManager

存储键wa_providers（数组）+wa_active-profile（字符串）。数据结构含id/name/baseUrl/apiKey(加密)/models/purpose(generate|verify|detect)/streamMode/temperature/maxTokens/systemPrompt/createdAt。特殊行为：加载解密apiKey、保存加密apiKey、旧localStorage迁移、purpose字段区分用途。

### 6.3 AgentManager

存储键wa_agents（数组）。数据结构含id/name/model/temperature/maxTokens/systemPrompt/createdAt。标准CRUD全量写入。

### 6.4 SkillManager

存储键wa_skills（数组）。数据结构含id/name/template/category/chainOrder/createdAt。标准CRUD全量写入。

### 6.5 ProjectManager

存储键wa_projects（索引数组）+wa_project-{id}（项目数据）+wa_chapters_{id}（章节数据）。索引数组只存轻量信息。特殊行为：孤儿恢复、级联删除、创建时同时写索引和项目数据文件。

### 6.6 ChapterManager

存储键wa_chapters_{projectId}（数组）。章节数据按项目隔离存储，避免单个存储键过大。getAll(projectId)和save(projectId,chapters)两个方法。

## 7. 数据导入导出

### 7.1 导出

StorageManager.exportAll()：list()获取所有键，遍历get()组装为对象返回。main.js storage:export：读取存储目录所有.json文件，组装为{filename:content}对象，JSON.stringify写入用户指定路径。注意差异：exportAll()返回已解析JS对象，main.js返回原始字符串。

### 7.2 导入

main.js storage:import：读取备份文件JSON.parse，遍历键值对safeKey()清洗后写入文件。覆盖导入非合并导入。

### 7.3 文件对话框

dialog:saveFile用showSaveDialogSync默认文件名writing-assistant-backup.json。dialog:openFile用showOpenDialogSync属性openFile单选。

## 8. 窗口状态持久化

源码位置: main.js L6-25

窗口状态存储在APPDATA/写作助手/window-state.json（不在Documents数据目录中）。保存{x,y,width,height,maximized}。保存时机：close/resize/move/before-quit事件。恢复时机：createWindow()时读取。最大化时不恢复x/y避免窗口在屏幕外。状态文件损坏时静默忽略。

## 9. 诊断日志持久化

源码位置: main.js L290-363

诊断日志存储在APPDATA/写作助手/diag-logs/按日期分文件diag-YYYY-MM-DD.jsonl。写入：接收批量条目JSON.stringify后换行连接appendFileSync追加。读取：按日期定位文件按换行分割逐行JSON.parse失败的行跳过。导出：读最近7天合并JSON.stringify带缩进写入。清空：删除目录下所有文件不删目录。

## 10. 错误日志持久化

源码位置: main.js L27-36

ErrorLog将错误信息追加写入APPDATA/写作助手/logs/error-YYYY-MM-DD.log。写入失败静默忽略。日志目录自动创建。按日期分文件。全局错误处理：process.on(uncaughtException)和process.on(unhandledRejection)写入ErrorLog。

## 11. Vue3迁移差异检测要点

### 11.1 必须保留的行为

1.双模式存储降级Electron文件+localStorage 2.wa_前缀 3.JSON序列化parse失败返回原始字符串 4.API Key加密enc:+safeStorage 5.数据目录在Documents跨卸载保留 6.项目孤儿恢复索引空时扫描重建 7.项目删除级联清理 8.窗口状态持久化 9.诊断日志JSONL格式 10.同步IPC存储sendSync

### 11.2 可改进的行为

1.原子写入write-to-temp-then-rename 2.异步存储ipcRenderer.invoke减少阻塞 3.增量更新减少IO 4.数据压缩 5.storage:list重复注册清理 6.导入合并模式

### 11.3 差异检测规则

存储键前缀wa_保持不变；存储目录Documents/写作助手数据/保持不变；文件扩展名.json保持不变；API Key加密enc:+safeStorage保持不变；迁移标记.migrated文件保持不变；窗口状态路径userData/window-state.json保持不变；诊断日志路径userData/diag-logs/保持不变；错误日志路径userData/logs/保持不变；JSON.parse失败返回原始字符串必须保持；storage:read文件不存在返回null必须保持；storage:write成功返回true必须保持；storage:remove文件不存在返回true必须保持。

## 12. 已知问题与技术债务

1.非原子写入fs.writeFileSync崩溃导致数据损坏 2.同步IPC阻塞sendSync大文件读写阻塞渲染进程 3.全量写入每次修改写整个列表大数据集性能差 4.storage:list重复注册main.js L241和L430 5.无数据版本号存储数据没有版本字段 6.无数据校验读取不校验结构完整性 7.导出格式不一致exportAll和storage:export返回不同格式
