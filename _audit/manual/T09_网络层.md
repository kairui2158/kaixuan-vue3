# T09 - 网络层 (Network Layer)

> 旧架构行为手册 第九层 | 源码权威参考 | Vue3迁移差异检测驱动依据

## 1. 层级定位与职责边界

网络层负责所有与AI API供应商的HTTP通信，包括请求构建、流式解析、错误重试、超时处理、心跳重连。这是应用与外部服务交互的唯一通道。

职责范围：AI API请求构建与发送；流式SSE响应解析；非流式JSON响应解析；reasoning_content（深度思考）提取；HTTP错误分类与重试策略；429/502/503限流退避重试；400错误自适应max_tokens减半；超时检测与AbortSignal；心跳重连机制；流式空闲检测；API调用诊断日志。

不负责：API Key存储（持久化层）；供应商配置管理（ProviderManager）；UI更新（渲染层）；业务逻辑（功能系统层）。

## 2. 统一AI请求方法 _aiRequest

源码位置: renderer_v2.js _aiRequest方法（约L1200-1400）

_aiRequest是旧架构所有AI调用的统一入口。合并了三处重复的fetch+流解析+reasoning_content+重试逻辑。

### 2.1 请求构建

var reqBody = { model: cfg.model || this.settings.model || this._getSelectedModel(), messages: cfg.messages, stream: cfg.stream !== false };

max_tokens自适应：默认8192，400错误时自动减半。这处理了DeepSeek（8192限制）和OpenAI（128000限制）的不同限制，无需硬编码。

var _mt = cfg.maxTokens && cfg.maxTokens > 0 ? cfg.maxTokens : 8192;
reqBody.max_tokens = _mt;
if (cfg.temperature != null) reqBody.temperature = cfg.temperature;

### 2.2 请求参数

cfg对象支持以下参数：
- model: 模型名（可选，回退到settings.model再到_getSelectedModel()）
- messages: 消息数组（必需）
- stream: 是否流式（默认true）
- maxTokens: 最大token数（默认8192）
- temperature: 温度（可选）
- timeoutMs: 超时毫秒（默认600000=10分钟）
- retry: 是否重试（默认true）
- baseUrl: API基础URL（可选，回退到settings.baseUrl）
- apiKey: API密钥（可选，回退到settings.apiKey）
- signal: AbortSignal用于取消（可选）
- onChunk: 流式回调（可选）
- onReasoning: reasoning回调（可选）
- onUsage: usage回调（可选）
- onPause: 暂停钩子（可选）

### 2.3 请求发送

var resp = await fetch(_reqBaseUrl + "/chat/completions", { method: "POST", headers: { Authorization: "Bearer " + _reqApiKey, "Content-Type": "application/json" }, body: JSON.stringify(reqBody), signal: signal });

URL拼接：baseUrl + "/chat/completions"。认证：Bearer Token。Content-Type: application/json。

signal构建：如果cfg.signal存在，用AbortSignal.any合并外部signal和超时signal；否则只用AbortSignal.timeout(timeoutMs)。

## 3. 重试策略

### 3.1 重试参数

var maxRetries = doRetry ? 8 : 0;
var retryDelays = [2000, 4000, 6000, 8000, 10000, 12000, 15000, 20000, 25000, 30000, 35000, 40000, 45000, 50000, 55000, 60000, 65000, 70000, 75000, 80000];

最多8次重试，间隔递增从2秒到80秒。retryDelays数组长度远超maxRetries，确保不会越界。

### 3.2 可重试状态码

HTTP 429（请求太频繁）、502（网关错误）、503（服务不可用）：触发重试。

if (doRetry && (resp.status === 429 || resp.status === 502 || resp.status === 503) && attempt < maxRetries) { await new Promise(r => setTimeout(r, retryDelays[attempt])); continue; }

### 3.3 不重试错误

客户端错误不重试（永远不会成功）：401 API Key无效、403访问被禁止、404接口不存在、400请求参数错误（非max_tokens相关）。

var _noRetry = e.message.indexOf("API Key") !== -1 || e.message.indexOf("访问被禁止") !== -1 || e.message.indexOf("接口不存在") !== -1 || e.message.indexOf("请求参数错误") !== -1;

### 3.4 400错误自适应max_tokens减半

当收到400错误且max_tokens大于1024时：尝试读取响应体，如果包含max_tokens/max output/maximum/too large/token等关键词，则将max_tokens减半重试。即使无法读取响应体也会尝试减半。这处理了不同模型token限制不同的问题。

### 3.5 错误映射

var errMap = { 400: "请求参数错误", 401: "API Key 无效", 403: "访问被禁止", 404: "接口不存在", 429: "请求太频繁", 500: "服务器内部错误" };

## 4. 流式响应解析

### 4.1 SSE解析流程

1. 获取ReadableStream reader：resp.body.getReader()
2. 创建TextDecoder解码二进制
3. 循环读取chunk，decoder.decode(chunk.value, { stream: true })
4. 按换行符分割，每行trim后检查是否以"data: "开头
5. 去掉"data: "前缀，如果是"[DONE]"则跳过
6. JSON.parse解析SSE数据
7. 提取choices[0].delta.content和choices[0].delta.reasoning_content
8. content追加到fullText，reasoning追加到reasoningText
9. 通过onChunk和onReasoning回调实时输出

### 4.2 reasoning_content（深度思考）处理

部分模型（如DeepSeek）返回reasoning_content字段表示思考过程。处理逻辑：
- reasoningDelta追加到reasoningText
- 如果有onReasoning回调则调用
- 如果fullText为空但reasoningText有内容，则用reasoningText作为fullText的回退

### 4.3 buffer处理

流式数据可能在一个chunk中间断开，buffer保留最后一个不完整行，与下一个chunk拼接后继续解析：

buffer += decoder.decode(chunk.value, { stream: true });
var lines = buffer.split("\n");
buffer = lines.pop() || "";

## 5. 非流式响应解析

当cfg.stream === false时：

var data = await resp.json();
var msg = data.choices && data.choices[0] && data.choices[0].message ? data.choices[0].message : {};
var text = msg.content || "";
var reasoning = msg.reasoning_content || "";
if (!text && reasoning) text = reasoning;
if (data.usage && cfg.onUsage) cfg.onUsage(data.usage);
return { text: text, reasoning: reasoning };

## 6. 流式空闲检测

源码位置: _aiRequest流式循环内

feature 3: streaming idle detection。使用Promise.race竞争chunk读取和空闲超时：

var _idlePromise = new Promise(resolve => _idleTimer = setTimeout(() => resolve('idle'), _idleThreshold));
var _chunkPromise = reader.read().then(c => ({ type: 'chunk', data: c }));
var _raceResult = await Promise.race([_chunkPromise, _idlePromise]);

参数：_idleThreshold初始15000ms（15秒），空闲3次后降为10000ms（10秒）。空闲超过3次抛出stream_idle_timeout错误。

行为：空闲超时时调用reader.cancel()取消流，然后抛出错误进入重试流程。

## 7. 心跳重连机制

源码位置: _aiRequest重试耗尽后

当所有8次重试全部失败后，进入heartbeat mode：

1. 每60秒发送一次探测请求
2. 探测成功则恢复原始请求（重新创建reader解析流式响应）
3. 探测失败则继续等待下一个60秒
4. 无限循环直到API恢复

这个机制确保长时间API中断后应用能自动恢复，不需要用户手动重试。

心跳重连的流式解析与正常流式解析逻辑完全相同，但使用新的reader和decoder。

## 8. 超时处理

### 8.1 请求超时

default timeoutMs = 600000（10分钟）。使用AbortSignal.timeout(timeoutMs)创建超时signal。

如果cfg.signal存在，用AbortSignal.any合并外部signal和超时signal，支持外部取消+超时取消双重保护。

### 8.2 超时错误处理

TimeoutError和AbortError触发重试（如果doRetry且attempt < maxRetries）。cfg.signal.aborted表示外部主动取消，不重试直接抛出。

## 9. API调用诊断

### 9.1 性能追踪

var _diagKey = "api-" + Date.now() + "-" + Math.random().toString(36).substr(2,5);
if (window.DiagLogger) DiagLogger.perfStart(_diagKey);

成功完成后：DiagLogger.perfEnd(_diagKey, "api", "API")和DiagLogger.trackApiCall(model, 0, elapsed, "ok")。

失败时：DiagLogger.trackApiCall(model, 0, 0, "error", e.message)。

### 9.2 暂停钩子

if (cfg.onPause) await cfg.onPause();

每个chunk处理前检查onPause回调，支持流式输出暂停（如用户暂停生成）。

## 12. 网络层与其他层的交互

### 12.1 与调用链层的交互

生成流水线（大纲/设定/卷纲/章节/正文）和去AI味流程都通过_aiRequest发送API请求。_callAiApi方法是流水线层的封装，内部调用_aiRequest。

### 12.2 与持久化层的交互

baseUrl和apiKey从ProviderManager获取（经持久化层存储和加密解密）。model从供应商配置或用户选择获取。

### 12.3 与错误处理层的交互

所有网络错误通过try-catch捕获，分类后决定重试或抛出。错误信息通过console.warn输出，严重错误通过DiagLogger记录。

## 13. Vue3迁移差异检测要点

### 13.1 必须保留的行为

1. 统一_aiRequest入口：所有AI调用经过同一方法
2. 流式SSE解析：data: 前缀+JSON.parse+delta提取
3. reasoning_content处理：深度思考提取和回退
4. 重试策略：8次递增重试+不重试客户端错误
5. 400自适应max_tokens减半
6. 流式空闲检测：15秒超时+3次降为10秒
7. 心跳重连：60秒间隔无限重试
8. 超时：10分钟默认+AbortSignal.any合并
9. 模型列表获取：主进程代理绕过CORS
10. 诊断日志：每次API调用记录

### 13.2 可改进的行为

1. 重试参数可配置化（不硬编码8次和delay数组）
2. 心跳重连可配置间隔和最大尝试次数
3. 流式空闲检测参数可配置
4. 错误映射可扩展为完整HTTP状态码表
5. 模型列表获取可缓存结果避免频繁请求

### 13.3 差异检测规则

请求URL格式baseUrl+/chat/completions必须保持；认证方式Bearer Token必须保持；SSE解析data:前缀+[DONE]结束必须保持；reasoning_content提取必须保持；429/502/503重试必须保持；401/403/404不重试必须保持；400减半max_tokens重试必须保持；心跳重连60秒间隔必须保持；流式空闲15秒检测必须保持；超时10分钟默认必须保持。

## 14. 已知问题与技术债务

1. retryDelays数组长度远超maxRetries（20个元素但只用8个），是冗余但无害
2. 心跳重连无限循环可能导致内存泄漏（长时间运行的Promise链）
3. 流式解析中JSON.parse失败只warn不记录详细日志
4. 400错误减半max_tokens时没有上限检查（可能减到极小值）
5. 非流式模式不支持reasoning_content的onReasoning回调
6. 模型列表获取没有缓存，每次都发请求
