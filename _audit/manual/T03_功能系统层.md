## 1. 生成流水线 (pipeline-manager.js)

### 入口与导航
- 入口按钮: btn-pipeline -> showPipeline()
- 关闭: btn-close-pl -> closePipeline()
- 面板ID: pipeline-panel，CSS类: pl-hidden/visible
- 5步流水线: 大纲(Step1) -> 设定(Step2) -> 卷纲(Step3) -> 章节(Step4) -> 正文(Step5)
- 每步有独立的确认按钮和SKILL绑定: pl-s1-skill ~ pl-s5-skill

### Step1 大纲层
- 编辑器: textarea#pl-outline-editor
- 字数输入: pl-outline-wordcount (全书总字数)
- SKILL选择: pl-s1-skill
- 确认按钮: pl-confirm-outline -> 进入Step2
- AI生成: _plGenOutline() 调用 apiGenerate("outline", params, null, opts)
- 数据持久化: pl.outlineText, pl.bookWordCount
- 行为契约: 用户填写或AI生成大纲文本+全书字数，确认后进入设定层

### Step2 设定层
- AI生成: _plGenSettings() 调用 apiGenerate("settings", params)
- 编辑区: pl-settings-editor
- SKILL选择: pl-s2-skill
- 确认按钮: pl-confirm-settings
- 绑定设定: _getBoundSettingsText() 从 SkillManager 获取绑定到当前项目的设定
- 动态分类: 根据大纲内容动态推断设定分类
- 数据持久化: pl.settingsText
- 行为契约: AI生成或手动编辑设定JSON，确认后进入卷纲层

### Step3 卷纲层（3种生成模式）
#### 模式1: AI生成
- 入口: btn-pl-gen-volumes -> _plGenVolumes()
- 行为: 一次性调用API生成所有卷纲
- 参数: outline + settings + bookWordCount + volumeCount
- 输出: JSON数组 [{name, outline, summary, suggestedWords}]
- SKILL: pl-s3-skill

#### 模式2: 自动生成
- 入口: btn-pl-auto-volumes -> _plAutoGenVolumes()
- 行为: AI推断卷数和字数分配，自动生成
- 卷数推断: 根据全书字数和情节复杂度

#### 模式3: 逐卷生成
- 入口: btn-pl-gen-volume-single
- 行为: 逐卷调用API，每卷独立生成
- 优势: 用户可在每卷后检查修改再继续
- 断网恢复: 已生成卷保留，从断点继续

#### 卷纲编辑
- 卡片式UI: 每卷一张卡片，含name/outline/summary/suggestedWords
- 卡片操作: 编辑/确认/删除
- 确认卷纲: pl-confirm-volumes -> volumesConfirmed=true
- 数据持久化: pl.volumes[] 数组

### Step4 章节层（核心功能）
#### 分批增量生成 _plGenChaptersBatched(volIdx, opts)
- 核心方法，所有章节生成的统一入口
- 参数: volIdx(卷索引), opts.expectedCount(预期章节数)
- 字数计算: vol.suggestedWords / chapterWordCount = expectedCount
- 批次大小: pl-chapter-batchsize 输入，默认5，范围1-20

#### 生成流程
1. 计算本卷预期章节数: Math.round(volWords / chWordCount)
2. while循环: vol.chapters.length < expectedCount
3. 每批生成 batchSize 章
4. 上下文构建: 全书大纲 + 设定摘要 + 风格分析 + 卷概要 + 前文已生成章节摘要(最近10章)
5. API调用: apiGenerate("chapters", batchParams, null, batchOpts)
6. JSON解析: _plExtractJsonArray() 7层回退修复
7. 立即持久化: _plPersist(pl) 每批完成后保存
8. 立即渲染: _plRenderChapterCards() + renderChapterTree()
9. 进度条更新: _plShowChapterProgressBar()

#### 断网续接机制
- 进度记录: pl.genProgress = {layer, volIdx, completedCount, expectedCount, status, timestamp}
- 状态值: in_progress / interrupted / completed
- 恢复入口: _plResumeChapterGen(volIdx)
- 恢复逻辑: 读取genProgress，从vol.chapters.length继续
- UI: 进度条显示 interrupted 状态 + 恢复生成按钮

#### JSON深度修复 _plExtractJsonArray(text)
7层回退策略:
1. 直接JSON.parse
2. 提取[...]后parse
3. 截断到最后一个}后补]再parse
4. 从首个{提取到最后一个}
5. 部分对象修复
6. 截断字符串补全
7. 正则提取name/outline/summary/title/plot字段

#### 章节卡片UI
- 容器: pl-chapter-cards
- 每章卡片: title + plot摘要 + 确认/编辑按钮
- 进度条: pl-ch-progress-bar (sticky定位)
- 空状态: pl-ch-empty-hint

### Step5 正文层
- 入口: _plGenBodyForChapter(vi, ci)
- 参数构建: 全书大纲 + 设定摘要 + 风格分析 + 卷概要 + 章节剧情点
- API调用: apiGenerate("body", params)
- 结果区: pl-body-result
- 插入编辑器: 将生成正文写入editor-content

### 流水线数据结构
```javascript
pl = {
  outlineText: "", bookWordCount: 0,
  settingsText: "", settingsConfirmed: false,
  volumes: [{id, name, outline, summary, suggestedWords, confirmed, chapters: []}],
  volumesConfirmed: false,
  currentVolumeIndex: -1,
  chapterWordCount: 3000, chapterBatchSize: 5,
  agentId: null, s1Skills: [], s2Skills: [], s3Skills: [], s4Skills: [], s5Skills: [],
  genProgress: {layer, volIdx, completedCount, expectedCount, status, timestamp}
}
```

### 风格上下文 _plStyleContext(pl)
- 从大纲和设定中提取风格标签和节奏参数
- 返回风格分析文本，注入到章节和正文生成的参数中

1. pipeline-manager.js 125KB需拆分为多个Vue composables
2. 5步流水线改Stepper组件
3. 卷纲3模式改策略模式

## 2. 去AI味系统 (de-ai.js + renderer_v2.js L572-810)

### 入口
- 按钮: btn-de-ai -> deAiProcess()
- 配置面板: renderDeAiSettings() 在设置tab中
- 进度模态框: deai-progress-modal

### 3种模式

#### 模式1: chain（串行链式）
- 方法: deAiProcess() 内部for循环
- 流程: 硬规则pre -> S1改写 -> 硬规则mid -> S2验证 -> 硬规则post
- Fix D修正: S1先跑(原文上改写) -> 硬规则清洗 -> S2验证 -> 硬规则安全网
- 温度: S1(rewrite)=0.7, S2(verify)=0.3 (Fix B)
- SKILL作为system message (Fix C)
- 风格样本注入S1 (Fix E)
- 验证供应商: ProviderManager.getVerifyProvider() 提供跨模型审核

#### 模式2: splitMerge（Agent调度/切分并行）
- 方法: _deAiSplitMerge(text, cfg, cancelController)
- 流程:
  1. 本地切分: _splitText(text, splitSize) 按段落+句子边界切分
  2. 并行处理: Promise.all + 并发限制3
  3. 拼接: _mergeSegments(results, segments)
- 切分算法: 段落级切分，溢出机制(0.7x~1.3x)，句子边界回退
- 重叠上下文: 每段携带前段尾部150字作为参考
- 进度: 每段一个进度步骤

#### 模式3: multiStep（代码控制多步流程）
- 方法: _deAiMultiStep(text, cfg, cancelController)
- 4阶段流程:
  Phase 1: S1A事件核提取 (并行, 3并发)
  Phase 2: S1B视角偏转 (并行, 3并发)
  Phase 3: S1C重组输出 (并行, 3并发)
  Phase 4: S2验证 (全文单次, 可选)
- 验证器:
  - validateEventCores: 检查[段N]标记数量 >= 段落数*0.7
  - validatePerspective: 检查偏转方法不连续3个相同
  - extractFirstSubject: 首句主语对比，相同则重试
- 风格样本: 注入S1A第一段 (Fix E)
- 温度: S1A/B/C=0.7, S2=0.3 (Fix B)

### 切分算法 _splitText(text, targetSize)
- minSize = targetSize * 0.7
- maxSize = targetSize * 1.3
- 按换行分段，累积到minSize~maxSize区间
- 长段落内部按句子边界(。！？….!?)切分
- 尾部小段合并到前段
- 重叠上下文: 前段尾部150字(或splitSize*15%)

### 硬规则系统
- 模块: DeAiProcessor.getHardRules()
- 20条硬规则，每条有id和name
- 用户可逐条开关: _deAiConfig.hardRules[ruleId] = true/false
- 总开关: _deAiConfig.hardRulesEnabled
- 执行时机: chain模式中S1前后, 其他模式在最终输出后

### 温度控制 _getDeAiTemperature(level, version, stage)
- level: low/medium/high
- version: v2/v3
- stage: rewrite(0.7) / verify(0.3)
- 返回对应温度值

### 风格样本 DeAiSamples
- 38个人类风格样本
- getSampleText() 返回样本文本
- 注入策略: chain模式注入最后skill, splitMerge注入第一段, multiStep注入S1A第一段
- Fix E修正: 样本应注入S1(改写阶段)而非S2(验证阶段)

### 验证供应商
- ProviderManager.getVerifyProvider(): 获取purpose='verify'的供应商
- cross_model_check: 用验证供应商的模型对S1输出做跨模型审核
- _updateVerifyProviderStatus(): UI显示验证供应商状态

### 进度UI
- 模态框: deai-progress-modal
- 进度条: deai-progress-fill (宽度百分比)
- 百分比: deai-progress-percent
- 当前步骤: deai-progress-step
- 步骤列表: deai-step-list (每项有dot/label/status)
- 状态: pending/active/done/failed
- 取消按钮: btn-deai-cancel (AbortController)

### 流程预览 _updateFlowPreview()
- 根据当前模式生成流程步骤HTML
- 显示: deai-flow-preview
- 包含: 步骤名+箭头+预计耗时+强度+版本+温度+模型
- 耗时计算: 根据模式和段数估算

### 配置持久化 _saveDeAiConfig()
- 读取所有DOM值写入_deAiConfig
- StorageManager保存到key: deai-config
- 配置字段: agentMode, skills[], agentId, hardRulesEnabled, hardRules{}, level, version, textType, splitSize

### 迁移注意
1. 3模式改策略模式(Pinia store + strategy pattern)
2. 切分算法保留为工具函数
3. 验证器保留为工具函数
4. 进度UI改Vue组件
5. 硬规则系统保留为独立模块
6. 风格样本管理改独立composable

## 3. 聊天对话系统

- 清除: btn-clear -> clearChat()

### 消息构建 buildMessages()

1. Agent systemPrompt (如果有Agent)
2. Skill template (如果有绑定的Skill)
3. 全局systemPrompt (settings.systemPrompt)
4. 上下文深度控制 (最近N条消息)

### 流式输出 streamChat()
- API: fetch POST /chat/completions, stream=true
- SSE解析: 逐行读取data:前缀，JSON.parse提取delta.content
- 实时渲染: 消息DOM实时更新
- 完成: [DONE]标记结束

### 消息操作（3个按钮）

#### 重新生成 _regenerateMessage(idx)
- 删除该消息及之后所有消息
- 重新调用API生成

#### 应用到编辑区 _applyToEditor(idx)
- 将AI消息内容插入editor-content当前光标位置
- 如果有选中文本则替换

### Agent/Skill上下文
- Agent选择: agent-select / agent-select-chat (双向同步)
- Model选择: model-select / model-select-chat (双向同步)
- Agent切换: 更新currentAgentId + populateModelSelect + _autoSelectAgentModel

## 行为契约汇总（15条）

1. 生成流水线5步必须按顺序执行，每步确认后才能进入下一步

6. 风格样本注入S1(改写阶段)，不注入S2
7. S2验证使用低温(0.3)，S1改写使用高温(0.7)
8. SKILL模板作为system message，不作为user message
9. 聊天消息8层组装，Agent和Skill优先级最高
10. 编辑器撤销/重做使用execCommand(需迁移)
11. 章节树支持右键/拖拽/双击重命名
12. 设置6个tab互斥显示
13. 多供应商可同时启用(generate+verify)
14. 所有AI调用通过apiGenerate或_aiRequest统一入口
