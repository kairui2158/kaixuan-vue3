# T07-生命周期层行为手册

> 本文档描述旧架构从启动到退出的完整生命周期，包括初始化序列、状态转换、自动保存、会话恢复、退出流程等行为规格。

## 1. 生命周期总览

旧架构基于Electron + 纯JS class，生命周期围绕RendererApp类的constructor -> init -> 运行态 -> 退出 这条主线展开。

### 1.1 生命周期阶段图

```
[Electron启动]
    |
    v
[main.js: app.whenReady()]
    |
    v
[BrowserWindow创建 + preload.js注入]
    |
    v
[renderer.html加载]
    |
    v
[DOM ContentLoaded -> new RendererApp()]
    |
    v
[constructor: 读取settings + 初始化管理器]
    |
    v
[init(): 事件绑定 + 数据迁移 + UI初始化 + 会话恢复]
    |
    v
[运行态: 用户交互 + 自动保存 + IPC通信]
    |
    v
[退出信号: onCloseRequest IPC]
    |
    v
[退出确认模态框 -> 用户选择]
    |
    v
[onFinalSave IPC -> 保存数据 -> 退出]
```

## 2. 构造函数阶段（constructor）

### 2.1 constructor执行内容

源码位置：renderer_v2.js constructor()

constructor按顺序执行：

1. 合并默认设置：`this.settings = Object.assign({}, DEFAULT_SETTINGS, savedSettings)`
2. 初始化状态变量：currentProjectId/currentVolumeId/currentChapterId/currentProviderId/currentAgentId
3. 初始化undo/redo栈：`this._undoStack = []; this._redoStack = []`
4. 初始化定时器引用：`this._autoSaveTimer = null; this._lastSaveTime = 0`
5. 初始化面板状态：`this._panelsOpen = {}`
6. 初始化表单状态：`this._formDirty = false`
7. 初始化Diff状态：`this._diffAccepted = []; this._diffCurrentIdx = 0; this._diffChangeCount = 0`
8. 初始化上下文菜单状态：`this._ctxNodeId = null; this._ctxVolumeId = null`
9. 初始化拖拽状态：`this._dragNode = null`
10. 初始化Notyf通知系统：`this._notyf = null`（在init中创建）

### 2.2 设置加载策略

```javascript
var DEFAULT_SETTINGS = {
  baseUrl: '', apiKey: '', model: '', providerId: '',
  temperature: 0.7, maxTokens: 4096, systemPrompt: '',
  theme: 'dark', fontSize: 16, editorFontSize: 16,
  autoSaveInterval: 30, streamMode: true
};
var savedSettings = StorageManager.get('settings') || {};
this.settings = Object.assign({}, DEFAULT_SETTINGS, savedSettings);
```

特点：
- 使用Object.assign浅合并，savedSettings覆盖DEFAULT_SETTINGS
- 不做深拷贝，嵌套对象引用共享
- StorageManager.get返回null时使用空对象
- 新增的设置字段自动获得默认值（因为DEFAULT_SETTINGS有）

### 2.3 管理器初始化

constructor不直接初始化管理器，管理器在文件加载时已自初始化：
- StorageManager：IIFE单例，加载时读取localStorage/IPC
- ProviderManager：IIFE单例，从StorageManager加载供应商数据
- AgentManager：IIFE单例
- SkillManager：IIFE单例
- ProjectManager：IIFE单例
- ChapterManager：IIFE单例

constructor只读取管理器数据，不修改。

## 3. 初始化阶段（init）

### 3.1 init执行序列

init()是应用启动的核心方法，按严格顺序执行：

```
init()
  |
  +-- 1. window._app = this（全局引用，供panels.js内联onclick使用）
  +-- 2. 全局keydown监听器注册
  +-- 3. Notyf通知系统初始化
  +-- 4. bindEvents()（200+个事件绑定）
  +-- 5. 数据迁移（默认卷->第一卷）
  +-- 6. 供应商初始化（currentProviderId设置）
  +-- 7. fillSettingsForm()（填充设置表单）
  +-- 8. populateModelSelect()（填充模型下拉）
  +-- 9. populateAgentSelect()（填充智能体下拉）
  +-- 10. _applyAppearance()（应用主题/字体大小）
  +-- 11. updateUIState()（更新UI状态显示）
  +-- 12. _initPanelResizers()（面板缩放初始化）
  +-- 13. 自动选择最后编辑的项目（会话恢复）
  +-- 14. _syncTreeToPipeline()（同步树到流水线）
  +-- 15. renderChapterTree()（渲染章节树）
  +-- 16. renderSkillArea()（渲染技能区域）
  +-- 17. 自动打开最后编辑的章节
  +-- 18. _lastSaveTime = Date.now()
  +-- 19. _startAutoSaveTimer()（启动自动保存定时器）
  +-- 20. closeAllPanels()（防御性关闭所有面板）
  +-- 21. onFinalSave IPC监听器注册
  +-- 22. onCloseRequest IPC监听器注册
  +-- 23. 退出确认模态框按钮事件绑定
```

### 3.2 数据迁移（步骤5）

init中执行一次性数据迁移，将所有项目中名为"默认卷"的卷重命名为"第一卷"：

```javascript
var _allProjs = ProjectManager.getAll();
var _migrated = 0;
_allProjs.forEach(function(proj) {
  var _vols = ChapterManager.getVolumes(proj.id) || [];
  _vols.forEach(function(v) {
    if (v.name === '默认卷') {
      ChapterManager.updateVolume(proj.id, v.id, { name: '第一卷' });
      _migrated++;
    }
  });
  // 同时迁移流水线中的卷数据
  var _pd = StorageManager.get('project-' + proj.id) || {};
  if (_pd._pipeline && _pd._pipeline.volumes) {
    _pd._pipeline.volumes.forEach(function(pv) {
      if (pv.name === '默认卷') pv.name = '第一卷';
    });
    StorageManager.set('project-' + proj.id, _pd);
  }
});
```

迁移特点：
- 遍历所有项目，不跳过任何项目
- 同时迁移ChapterManager和pipeline两处数据
- 迁移数量通过console.log输出
- 整个迁移包裹在try-catch中，失败只warn不阻断启动

### 3.3 供应商初始化（步骤6）

```javascript
if (this.settings.providerId && ProviderManager.get(this.settings.providerId)) {
  this.currentProviderId = this.settings.providerId;
} else {
  var allP = ProviderManager.getAll();
  if (allP.length > 0) this.currentProviderId = allP[0].id;
}
```

逻辑：
- 优先使用settings中记录的providerId
- 如果该providerId不存在（被删除），回退到第一个供应商
- 如果没有任何供应商，currentProviderId为null

### 3.4 会话恢复（步骤13）

会话恢复是多级回退逻辑，确保用户回到上次工作的位置：

```
1. 获取所有项目，按updatedAt降序排序
2. 读取lastSession（StorageManager.get('lastSession')）
3. 如果lastSession有pid:
   3a. 在项目列表中找到对应项目
   3b. 如果项目存在:
       - 设置currentProjectId
       - 更新项目名显示
       - 获取pipeline数据
       - 如果lastSession有vid:
         - 在pipeline.volumes中找到对应卷
         - 如果卷存在且lastSession有cid:
           - 在卷的chapters中找到对应章节
           - 如果章节存在: 设置currentVolumeId/currentChapterId
       - 如果currentVolumeId仍为null但有卷数据:
         - 回退到第一卷
         - 如果第一卷有章节，回退到第一章
       - FIX v2.7.24: 如果currentChapterId仍为null:
         - 遍历所有卷找到第一个有章节的卷
         - 设置该卷和该卷第一章为当前
4. 如果lastSession不存在或项目不存在:
   4a. 使用排序后的第一个项目
   4b. 同样的多级回退逻辑找卷和章节
5. 如果没有任何项目:
   - 不设置currentProjectId
   - 显示空状态
```

### 3.5 自动打开章节（步骤17）

```javascript
if (this.currentProjectId && this.currentVolumeId && this.currentChapterId) {
  try { this.openChapter(this.currentVolumeId, this.currentChapterId); }
  catch(e) { console.warn('[WARN] auto-open chapter failed:', e.message); }
}
```

只有在三个ID都存在时才自动打开章节。失败不阻断启动。

### 3.6 防御性面板关闭（步骤20）

```javascript
this.closeAllPanels();
```

在启动末尾关闭所有面板，防止CSS残留的visible类阻塞UI。这是修复stale visible class的防御措施。

## 4. 运行态

### 4.1 自动保存机制

**定时器启动（步骤19）**：
```javascript
this._startAutoSaveTimer();
```

_startAutoSaveTimer()的行为：
- 清除已有定时器：`clearInterval(this._autoSaveTimer)`
- 读取间隔：`var interval = (this.settings.autoSaveInterval || 30) * 1000`
- 设置定时器：`this._autoSaveTimer = setInterval(function() { self.autoSave(); }, interval)`
- 默认30秒，可配置

**autoSave()的行为**：
- 检查currentProjectId是否存在
- 检查编辑器内容是否非空
- 调用_saveChapterContent()保存当前章节
- 更新_lastSaveTime
- 不显示toast通知（静默保存）

**手动保存（Ctrl+S）**：
- 调用saveEditorContent()
- saveEditorContent()调用autoSave() + 显示toast通知

### 4.2 编辑器内容变更链

用户在编辑器输入时触发的链式反应：

```
用户输入
  |
  +-- editor-content input事件
  +-- _pushUndoState()（undo栈push，限制50条）
  +-- updateWordCount()（更新字数统计UI）
  +-- autoSave()（静默自动保存）
```

### 4.3 undo/redo状态管理

**_pushUndoState()**：
- 将当前编辑器内容push到_undoStack
- _undoStack长度限制50（超过时移除最早的）
- 清空_redoStack（新操作后redo栈清空）

**_undo()**：
- 检查_undoStack长度 > 0
- 将当前内容push到_redoStack
- 从_undoStack pop一条内容
- 设置编辑器内容
- 更新字数统计

**_redo()**：
- 检查_redoStack长度 > 0
- 将当前内容push到_undoStack
- 从_redoStack pop一条内容
- 设置编辑器内容
- 更新字数统计

### 4.4 面板状态管理

**openXxx方法（如openOutlineWorkspace/showPipeline等）**：
- 先调用closeAllPanels()关闭其他面板
- 设置目标面板元素classList.add('visible')
- 更新_panelsOpen状态

**closeAllPanels()**：
- 遍历所有面板元素
- 移除visible类
- 重置_panelsOpen

**toggleSettings()**：
- 如果开启：先closeAllPanels()，再显示设置面板
- 如果关闭：隐藏设置面板

### 4.5 项目切换生命周期

用户切换项目时触发的事件链：

```
openProject(projectId)
  |
  +-- autoSave()（保存当前项目数据）
  +-- currentProjectId = projectId
  +-- 更新项目名显示
  +-- 获取pipeline数据
  +-- 重置currentVolumeId/currentChapterId
  +-- 多级回退找卷和章节
  +-- _syncTreeToPipeline()
  +-- renderChapterTree()
  +-- renderSkillArea()
  +-- openChapter()（加载第一章内容到编辑器）
  +-- closeProjectModal()
  +-- StorageManager.set('lastSession', {...})
```

### 4.6 章节切换生命周期

用户点击章节树中的章节时：

```
openChapter(vid, cid)
  |
  +-- autoSave()（保存当前章节）
  +-- currentVolumeId = vid
  +-- currentChapterId = cid
  +-- 从ChapterManager获取章节内容
  +-- 设置编辑器内容
  +-- updateWordCount()
  +-- 更新面包屑导航
  +-- StorageManager.set('lastSession', {pid, vid, cid, ts})
```

## 5. 退出流程

### 5.1 退出信号触发

退出由Electron主进程触发：
- 用户点击窗口关闭按钮
- 主进程发送IPC消息到渲染进程
- renderer通过onCloseRequest监听

### 5.2 退出确认流程

```
[onCloseRequest IPC]
  |
  v
[显示exit-confirm-modal]
  |
  v
[用户选择]
  |
  +-- 保存后退出(0): respondCloseChoice(0)
  |     |
  |     v
  |   [主进程触发onFinalSave]
  |     |
  |     v
  |   [autoSave + _syncTreeToPipeline + _plPersist + lastSession]
  |     |
  |     v
  |   [主进程关闭窗口]
  |
  +-- 直接退出(1): respondCloseChoice(1)
  |     |
  |     v
  |   [主进程直接关闭窗口，不保存]
  |
  +-- 取消(2): respondCloseChoice(2)
        |
        v
      [隐藏模态框，继续运行]
```

### 5.3 onFinalSave的容错设计

onFinalSave回调中每个操作独立try-catch：

```javascript
window.electronAPI.onFinalSave(function() {
  try { selfRef.autoSave(); } catch(e) { console.warn('[WARN] final save failed:', e); }
  try { selfRef._syncTreeToPipeline(); } catch(e) { console.warn('[WARN] catch #2', e); }
  try { var _pl = selfRef._plData(); if (_pl) selfRef._plPersist(_pl); } catch(e) { console.warn('[WARN] catch #3', e); }
  try { StorageManager.set('lastSession', {...}); } catch(e) { console.warn('[WARN] catch #4', e); }
  selfRef._lastSaveTime = Date.now();
});
```

设计意图：
- 任何一个保存操作失败不影响其他操作
- autoSave失败不影响pipeline同步
- pipeline同步失败不影响lastSession记录
- 每个catch都同时输出console.warn和DiagLogger.warn

### 5.4 退出时的数据一致性保证

退出时需要保证的数据一致性：

| 数据项 | 保存方式 | 失败影响 |
|-------|--------|--------|
| 当前章节正文 | autoSave() -> _saveChapterContent() -> ChapterManager.save() | 正文丢失未保存部分 |
| 章节树与流水线同步 | _syncTreeToPipeline() | 树和流水线可能不一致 |
| 流水线数据持久化 | _plPersist(_pl) -> StorageManager.set() | 流水线数据丢失 |
| 最后会话状态 | StorageManager.set('lastSession') | 下次启动无法恢复会话 |

## 7. 定时器生命周期

### 7.1 自动保存定时器

- 创建：init()步骤19 _startAutoSaveTimer()
- 间隔：settings.autoSaveInterval * 1000（默认30秒）
- 回调：autoSave()
- 销毁：无显式销毁（应用退出时自动清理）
- 重建：settings变更时可通过_startAutoSaveTimer()重建

### 7.2 其他定时器

旧架构中没有其他长期运行的定时器。流式API调用使用Promise + setTimeout组合，不是setInterval。

## 8. 错误恢复机制

### 8.1 启动错误恢复

init()中的每个步骤都可能失败，恢复策略：

| 步骤 | 失败处理 | 恢复方式 |
|------|---------|--------|
| 数据迁移 | try-catch + console.warn | 跳过迁移继续启动 |
| 会话恢复 | 多级回退 | 回退到第一个项目/第一卷/第一章 |
| 自动打开章节 | try-catch + console.warn | 跳过，用户手动打开 |
| _syncTreeToPipeline | try-catch + console.warn | 跳过同步 |
| IPC监听 | 无try-catch | 如果electronAPI不存在则跳过 |

### 8.2 运行态错误恢复

| 场景 | 恢复策略 |
|------|--------|
| API调用失败 | toast通知用户，不自动重试 |
| 存储写入失败 | console.warn，不通知用户 |
| 章节内容加载失败 | console.warn，编辑器显示空 |
| 面板打开失败 | 无显式处理 |

## 9. 行为契约清单

| 编号 | 契约描述 | 验证方法 |
|------|---------|--------|
| LC-01 | 应用启动后window._app指向RendererApp实例 | 控制台输入window._app验证 |
| LC-02 | 启动后自动恢复上次会话的项目/卷/章节 | 关闭重开应用验证恢复 |

## 10. 迁移注意事项

| 编号 | 注意事项 | Vue3对应方案 |
|------|---------|-------------|
| M-01 | constructor + init两阶段合并为Vue setup/onMounted | 使用setup() + onMounted() |
| M-02 | window._app全局引用不需要 | Vue组件实例通过ref访问 |
| M-03 | 管理器IIFE单例改为Vue插件或composable | 使用provide/inject或pinia store |
| M-04 | 自动保存定时器在onMounted启动，onUnmounted清理 | 使用onMounted/onUnmounted |
| M-05 | IPC监听器在onMounted注册，onUnmounted清理 | 同上 |
| M-06 | settings加载改为pinia store + 持久化插件 | 使用pinia-plugin-persistedstate |
| M-07 | 会话恢复改为路由query或store | 使用vue-router + pinia |
| M-08 | undo/redo可用Vue响应式栈 | 使用ref数组 |
| M-09 | 面板状态改为Vue路由或组件状态 | 使用v-if + 路由 |
| M-10 | 数据迁移逻辑可在App.vue的onMounted中执行 | 同上 |
| M-11 | 退出确认改为Vue组件 + Electron IPC | 使用Teleport + IPC |
| M-12 | 多级回退会话恢复逻辑可提取为composable | 使用useSessionRestore() |

## 11. 已知缺陷与风险

| 编号 | 缺陷描述 | 风险等级 | 影响 |
|------|---------|---------|------|
| D-01 | 自动保存定时器无显式销毁 | 中 | 如果init被多次调用会有多个定时器 |
| D-02 | Object.assign浅合并嵌套对象 | 低 | 嵌套设置修改可能影响默认值 |
| D-03 | 退出时没有等待异步保存完成 | 中 | 大量数据时可能保存不完整 |
| D-04 | 会话恢复中没有验证章节内容是否存在 | 低 | 可能恢复到空章节 |
| D-05 | _undoStack限制50但_pushUndoState在input事件中 | 低 | 快速输入可能push大量状态 |
| D-06 | IPC监听器没有清理机制 | 中 | 如果应用被多次初始化会重复监听 |
| D-07 | 数据迁移每次启动都执行 | 低 | 性能轻微浪费 |
| D-08 | closeAllPanels在启动末尾执行可能闪烁 | 低 | 用户可能看到面板闪现 |

## 12. Vue3迁移差异检测规则

| 规则编号 | 检测内容 | 旧架构行为 | Vue3期望行为 |
|---------|--------|-----------|-------------|
| R-01 | 生命周期阶段 | constructor + init | setup + onMounted |
