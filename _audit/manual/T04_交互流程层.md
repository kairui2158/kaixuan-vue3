# T04 - 交互流程层行为手册

> 本文档深度分析旧架构中所有用户交互流程、面板管理、工作流编排、快捷键系统、拖拽交互、右键菜单、内联编辑等行为契约，作为Vue3迁移的行为规格权威参考。

## 1. 应用启动交互流程

### 1.1 构造函数初始化 (constructor)

**源码位置**: renderer_v2.js constructor()

**行为契约**:
- 初始化核心状态变量: currentProjectId=null, currentVolumeId=null, currentChapterId=null, currentAgentId=null
- 设置编辑器模式: editorMode='ch-body'（支持 'vol-outline' | 'ch-plot' | 'ch-body' 三种模式）
- 加载设置: this.settings = this.loadSettings()
- 初始化消息数组: this.messages = []
- 流式状态: isStreaming=false, abortController=null
- 去AI味配置初始化: _deAiConfig = { skills:[], agentId:null, hardRulesEnabled:true, agentMode:"chain", splitSize:1000, level:"medium", version:"v3", textType:"novel" }
- 去AI味配置持久化: 从 StorageManager.get("app-deai-config") 加载已保存配置
- 文本过滤器: _textFilterEnabled=false（去AI是后处理功能，不预生成注入）
- 调用 init()，异常捕获并 console.error

**迁移注意**: Vue3 中这些状态应放入 reactive store，constructor 逻辑移入 setup() 或 onMounted

### 1.2 设置加载 (loadSettings)

**行为契约**:
- 从 StorageManager.get("app-settings") 读取
- API密钥解密: 如果 apiKey 以 "enc:" 开头，调用 window.electronAPI.decrypt() 解密
- maxTokens 下限保护: 如果 < 128000，强制设为 128000
- 默认值: { baseUrl:"", apiKey:"", model:"", systemPrompt:"", streamMode:false, fontSize:14, editorFontSize:15, theme:"dark", maxTokens:128000 }

**迁移注意**: 解密逻辑应移入 Electron preload 层，Vue3 只读取明文配置

### 1.3 初始化流程 (init)

**源码位置**: renderer_v2.js init()，约200行

**执行顺序（严格按序）**:

1. **全局引用**: window._app = this
2. **键盘快捷键注册**: document.addEventListener("keydown", ...) — 见快捷键系统章节
3. **通知组件初始化**: new Notyf({ duration:3000, position:{x:"right",y:"top"}, dismissible:true })
4. **事件绑定**: this.bindEvents() — 绑定所有DOM事件
5. **数据迁移**: 遍历所有项目，将 "默认卷" 重命名为 "第一卷"，同步更新 pipeline 数据
6. **供应商选择**: 优先使用 settings.providerId，否则取第一个供应商
7. **表单填充**: fillSettingsForm(), populateModelSelect(), populateAgentSelect()
8. **外观应用**: _applyAppearance()
9. **UI状态更新**: updateUIState()
10. **面板缩放器初始化**: _initPanelResizers()
11. **上次会话恢复**: 
    - 获取所有项目并按 updatedAt 降序排列
    - 读取 StorageManager.get('lastSession')
    - 如果有 lastSession.pid，找到对应项目
    - 恢复 currentProjectId, currentVolumeId, currentChapterId
    - 多级回退: 如果 lastSession 的卷/章不存在，回退到第一卷第一章
    - FIX v2.7.24: 如果 currentChapterId 仍为 null，遍历所有卷找第一个有章的卷
12. **如果没有 lastSession**: 选择最近更新的项目，回退到第一卷第一章
13. **树同步**: _syncTreeToPipeline() — 章节树与pipeline数据双向同步
14. **渲染章节树**: renderChapterTree()
15. **渲染技能区**: renderSkillArea()
16. **自动打开上次章节**: openChapter(currentVolumeId, currentChapterId)
17. **自动保存定时器**: _lastSaveTime = Date.now(); _startAutoSaveTimer()
18. **防御性关闭面板**: closeAllPanels() — 确保启动时无残留可见面板
19. **IPC监听**: 
    - onFinalSave: 退出前保存（autoSave + _syncTreeToPipeline + _plPersist + lastSession写入）
    - onCloseRequest: 显示自定义退出确认模态框（保存并退出/直接退出/取消）
20. **退出确认按钮绑定**: btn-exit-save(0), btn-exit-direct(1), btn-exit-cancel(2), 以及关闭按钮(×)等同cancel

**迁移注意**: 
- Vue3 中启动流程应拆分为多个 composable: useStartup(), useSessionRestore(), useAutoSave()
- 数据迁移逻辑应独立为 migration 模块
- IPC 监听应封装为 useElectronIPC() composable

### 2.2 面板关闭机制

**closeAllPanels()** — 关闭所有面板:
- 移除 panel-backdrop 的 visible 类
- 大纲工作台: 移除 visible，添加 ow-hidden
- 设置集合: 移除 visible，添加 sc-hidden
- 技能绑定模态框: 移除 visible，display=none
- 流水线: 移除 visible，添加 pl-hidden
- 记忆: 移除 visible，添加 mem-hidden
- 显示 app-main（添加 visible）
- 清除侧栏激活状态: setSidebarActive(null)
- 更新面包屑: _updateBreadcrumb()

**_closeAllPanels()** — 内部关闭（不带backdrop处理）:
- 隐藏 app-main（移除 visible）
- 关闭大纲/设置集合/流水线/记忆面板
- 注意: 此方法不显示 app-main，用于打开新面板前先关闭其他面板

**ESC全局关闭**:
- init() 中注册: e.key === "Escape" → closeAllPanels()
- bindEvents() 中 hotkeys("escape") 注册了更细粒度的关闭:
  - 如果查找替换栏可见 → _closeFindBar()
  - 否则依次尝试关闭: settings, project-modal, settings-collection, memory, pipeline, new-project-modal, volume-modal, skill-bind-modal, sc-bind-modal
  - 每个关闭操作都有 try-catch 保护

### 2.3 面板切换逻辑

**打开面板的通用模式**:
1. 调用 _closeAllPanels() 关闭其他面板（隐藏 app-main）
2. 移除目标面板的 hidden 类，添加 visible 类
3. 调用 setSidebarActive(btnId) 激活侧栏按钮
4. 加载面板数据
5. 绑定面板内按钮事件

**关闭面板的通用模式**:
1. 移除 visible 类，添加 hidden 类
2. 显示 app-main（添加 visible）
3. 保存面板数据（如适用）
4. 更新面包屑
5. 清除侧栏激活状态

**setSidebarActive(btnId)**:
- 遍历所有 .sidebar-btn，移除 active 类
- 如果提供了 btnId，给对应按钮添加 active 类

**迁移注意**: 
- Vue3 中面板应改为路由或条件渲染组件
- backdrop 点击关闭用 @click.self
- ESC 全局处理用 Vue3 的全局 keydown 监听
- 面板切换的 CSS 类管理改为 v-show 或 v-if

## 3. 核心工作流

### 3.1 工作流1: 新建项目

**触发**: btn-open-project → openProjectModal() → 显示项目列表
**新建**: btn-new-project → showNewProjectForm() → 显示新建表单
**创建**: btn-create-project → createProject() 
  - 创建项目记录到 ProjectManager
  - 创建默认卷和章
  - 切换到该项目
  - 渲染章节树
**打开**: project-list click → data-a="pm-open" → openProject(id)
**删除**: project-list click → data-a="pm-delete" → deleteProject(id)

**交互细节**:
- 项目列表通过 data-a 属性区分操作类型（事件委托模式）
- backdrop 点击关闭项目模态框
- 新建项目模态框有独立的 backdrop 关闭

### 3.2 工作流2: 大纲工作台

**触发**: btn-outline-workspace 或 Ctrl+1 → openOutlineWorkspace()

**面板内容**:
- 大纲编辑器 (outline-editor): textarea
- AI共创区域 (ow-chat-area): 可折叠的AI对话区
- 技能建议区 (ow-skill-suggestions): AI生成技能建议
- 绑定技能列表 (ow-bound-list): 已绑定技能

**功能按钮**:
- btn-import-outline: 导入文件（支持 .txt/.md/.text/.rtf/.docx/.doc）
- btn-ai-co-create: 切换AI共创区域显示
- btn-generate-outline-skills: 根据大纲生成技能建议
- btn-lock-outline: 锁定大纲并解析卷章结构
- btn-close-outline-workspace: 关闭面板
- btn-export-outline-md / btn-export-outline-txt: 导出大纲

**文件导入智能编码检测 (_smartDecode)**:
- 先尝试 UTF-8 解码
- 如果无替换字符(\ufffd)，返回 UTF-8 结果
- 否则尝试 GBK 解码
- 仍有替换字符则返回 GBK 结果（容忍）

**DOCX解析 (_parseDocx)**:
- 手动解析 ZIP 结构（不依赖 JSZip 等库）
- 找到 word/document.xml 条目
- 支持 method=0（存储）和 method=8（deflate压缩）
- 使用 DecompressionStream("deflate-raw") 解压
- 提取 <w:t> 标签文本，按 <w:p> 分段

**RTF解析**:
- 读取文件后用 _smartDecode 解码
- 正则去除 RTF 控制码: /\\[a-z]+-?\d*\s?/g
- 去除花括号和转义字符

**AI共创 (toggleAICoCreate)**:
- 切换 ow-chat-area 的 display (flex/none)
- 绑定 btn-ow-send 发送事件
- 构建上下文: "[上下文：当前大纲]\n" + 大纲内容 + "\n\n[用户消息]\n" + 用户输入
- 使用当前选择的模型调用 API
- 支持 streamMode 流式和非流式
- 流式: 逐行解析 data: 前缀的 SSE，提取 delta.content
- 非流式: 解析 JSON choices[0].message.content

**锁定大纲 (lockOutline)**:
- 如果没有 currentProjectId，自动创建项目（用大纲第一行作为项目名）
- 保存大纲内容到项目
- 设置 outlineLocked = true
- 同步大纲文本到 project-{id} 数据
- 如果没有卷章结构，解析大纲创建卷和章:
  - `# 标题` 或 `第X卷` 开头 → 创建卷
  - `## 标题` 或 `第X章` 开头 → 创建章
  - 如果有卷无章，在第一卷创建默认章
- 关闭大纲工作台
- 渲染章节树
- 同步树到 pipeline
- 如果API已配置，自动触发设定拆解

**大纲工作台缩放**:
- .ow-resize-handle 右下角拖拽手柄
- mousedown 记录起始位置
- mousemove 实时调整宽高（最小400x300）
- mouseup 结束拖拽
- 设置 right:auto, bottom:auto 以支持自由调整

### 3.3 工作流3: 生成流水线

**触发**: btn-pipeline 或 Ctrl+3 → showPipeline()

**5步流水线**:

**Step1 - 大纲**:
- 编辑大纲文本 + 设置总字数 + 选择SKILL
- 确认后进入Step2

**Step2 - 设定**:
- AI生成设定（调用绑定SKILL）
- 编辑设定内容
- 保存设定
- 确认后进入Step3

**Step3 - 卷纲**:
- 4种生成模式: AI生成/自动生成/逐卷生成/手动添加
- 卡片式编辑每卷纲要
- 字数分配显示
- 确认后进入Step4

**Step4 - 章节**:
- 设置每章字数 + 批次大小 + 选择卷
- 生成章节（批量生成，带断网续接）
- 卡片式编辑每章剧情梗概
- 章节数硬性控制: 必须等于卷纲分配的数量

**Step5 - 正文**:
- 选择章节 + 设置字数
- AI生成正文
- 插入编辑器

### 3.4 工作流4: AI对话

**触发**: 在右侧聊天面板操作

**消息发送**:
- btn-send 点击 → sendMessage()
- user-input keydown Enter（无Shift）→ sendMessage()
- input 事件: 自动调整高度 + 更新字数统计 + 发送按钮禁用状态

**消息操作（事件委托）**:
- messages-list click → e.target.closest(".msg-btn")
- msg-btn-copy → _copyMessage(idx)
- msg-btn-regen → _regenerateMessage(idx)
- msg-btn-apply → _applyToEditor(idx)
- 索引计算: Array.from(msgEl.parentElement.children).indexOf(msgEl)

**Agent和Model选择**:
- agent-select change → 更新 currentAgentId, populateModelSelect, _autoSelectAgentModel, renderAgentInfo
- agent-select-chat change → 同步到 agent-select 并触发 change
- model-select-chat change → 同步到 model-select
- model-select change → 同步到 model-select-chat + 保存到 settings.model + updateUIState + _updateFlowPreview

**清除对话**:
- btn-clear 或 Ctrl+K → clearChat()

### 3.5 工作流5: 去AI味

**触发**: 编辑器中选中文本后点击去AI味按钮

**执行流程**:
1. 显示进度模态框 (deai-progress-modal)
2. 根据 agentMode 分支:
   - chain: 串行链式（SKILL1→SKILL2→SKILL3）
   - split-merge: 切分+并行+拼接
   - multi-step: 多步代码控制（事件核→视角偏转→重组）
3. 硬规则处理: hardrule-pre（全量20条）→ SKILL处理 → hardrule-post（安全子集）
4. 风格样本注入: 只注入最后一个SKILL（当前行为，已知问题）
5. 进度更新: 每步完成更新进度条
6. 可取消: abortController
7. 完成后写回编辑器或显示diff对比

**迁移注意**: 
- 去AI味执行顺序应为: S1改写（原文）→ 硬规则清洗 → S2验证 → 硬规则安全网
- 当前代码硬规则在S1之前跑，这是已知bug
- 风格样本应注入S1而非S2

### 3.6 工作流6: 设置供应商

**触发**: btn-settings → toggleSettings(true) → 切换到API设置tab

**供应商管理**:

**表单脏标记 (_formDirty)**:

**数据导入导出**:

### 3.7 工作流7: 章节树操作

**触发**: tree-body 上的多种事件

**点击操作（事件委托 data-a 属性）**:
| data-a | 行为 |
|---|---|
| view-outline | openOutlineWorkspace() |
| toggle-vol | toggleVolume(id) — 展开/折叠卷 |
| view-vol-outline | openVolumeOutline(id) — 在编辑器显示卷纲要 |
| view-ch-plot | openChapterPlot(vid, cid) — 在编辑器显示章节梗概 |

**右键菜单 (contextmenu)**:

**双击重命名 (dblclick)**:
- 双击章节节点 [data-a='open-ch']
- span 设置 contenteditable=true
+- 全选文本: document.execCommand("selectAll", false, null)

- keydown 事件: Enter保存，Escape取消并重新渲染

**拖拽排序**:
- dragstart: 记录 dragNode，设置 opacity=0.5，effectAllowed=move
- dragover: preventDefault，目标节点显示上边框线
- dragleave: 移除目标节点边框线
- drop: 
  - preventDefault，移除边框线
  - insertBefore 到目标节点前
  - 收集新顺序的 chapter IDs
  - 调用 ChapterManager.reorderChapters(projectId, vid, orderedIds)
- dragend: 恢复 opacity，清空 dragNode

## 8. 交互模式总结

### 8.1 事件委托模式

旧架构大量使用事件委托（event delegation）:
- tree-body click: 通过 data-a 属性分发不同操作
- messages-list click: 通过 .msg-btn 类名分发
- project-list click: 通过 data-a 属性分发
- skill-list click: 通过 data-a 属性分发
- agent-list click: 通过 data-a 属性分发
- ctx-menu click: 通过 data-a 属性分发
- export-dropdown click: 通过 data-format 属性分发

**迁移注意**: Vue3 中事件委托可改为 v-for + @click，但大数据列表（如章节树200+节点）仍建议用事件委托避免性能问题

### 8.2 状态-视图同步模式

旧架构的状态-视图同步是命令式的:
- 修改状态后手动调用渲染函数（renderChapterTree, renderSkillArea, updateUIState等）
- 容易遗漏渲染调用导致UI不同步

**迁移注意**: Vue3 的响应式系统自动处理状态-视图同步，但需注意:
- 深层嵌套对象的响应式追踪（用 reactive 或 ref）
- 数组变更需要正确触发响应式（splice/push 或直接赋值）

### 8.3 面板互斥模式

旧架构的面板是互斥的（一次只显示一个主要面板）:
- _closeAllPanels() 先关闭所有
- 再打开目标面板
- app-main 的 visible 类控制主区域显示/隐藏

**迁移注意**: Vue3 中可用路由或状态变量控制面板显示，互斥逻辑更简洁

## 9. 行为契约清单

1. **启动恢复**: 应用启动时必须恢复上次会话（项目/卷/章），失败时回退到最近项目第一卷第一章
2. **面板互斥**: 同时只能显示一个主要面板，打开新面板前关闭其他
3. **ESC关闭**: ESC键关闭当前最上层面板，查找替换栏优先
4. **表单脏标记**: 供应商编辑表单任何字段变更都标记 _formDirty，防止丢失修改
5. **自动保存**: 编辑器input触发自动保存，退出前执行最终保存
6. **会话持久化**: 退出时保存 lastSession（pid/vid/cid/ts），启动时恢复
7. **章节树事件委托**: 所有树操作通过 data-a 属性事件委托，不直接绑定每个节点
8. **拖拽排序**: 章节支持拖拽排序，drop 后立即调用 ChapterManager.reorderChapters 持久化
9. **双击重命名**: 章节双击进入 contenteditable 模式，Enter保存/Escape取消
10. **右键菜单**: 自定义右键菜单，点击其他区域关闭
11. **内联AI菜单**: 选中文本显示内联菜单，点击外部关闭
12. **导出下拉**: 点击按钮显示下拉菜单，点击外部关闭
13. **快捷键分层**: init() 注册基础快捷键，hotkeys-js 注册增强快捷键（覆盖基础）
14. **IPC退出流程**: 关闭窗口时弹出退出确认，三个选项（保存退出/直接退出/取消）
15. **数据迁移**: 启动时执行数据迁移（如卷名重命名），迁移失败不阻塞启动

## 10. 迁移注意事项

1. **面板 → 路由/组件**: 13个面板改为Vue3路由或条件渲染组件，backdrop用 @click.self
2. **事件委托 → v-for+@click**: 大部分事件委托可改用 v-for + @click，但200+章的树保持事件委托
3. **命令式渲染 → 响应式**: renderChapterTree() 等命令式渲染改为响应式数据绑定
4. **CSS类切换 → v-show/v-if**: ow-hidden/sc-hidden/pl-hidden/mem-hidden 类改为 v-show
5. **快捷键统一**: 合并 init() 和 hotkeys-js 的快捷键注册，消除重复和冲突
6. **IPC封装**: onFinalSave/onCloseRequest 封装为 useElectronIPC() composable
7. **会话恢复**: 拆分为独立 composable，多级回退逻辑保持不变
8. **拖拽排序**: Vue3 中可用 vuedraggable 或自实现，保持 reorderChapters 持久化调用
9. **右键菜单**: 封装为 ContextMenu 组件，支持动态菜单项
10. **内联AI菜单**: 封装为 InlineAIMenu 组件，监听编辑器选区
11. **差异对比**: 封装为 DiffModal 组件，支持逐项接受/拒绝
12. **退出确认**: 封装为 ExitConfirmModal 组件，IPC 集成
13. **面板缩放**: 封装为 usePanelResize() composable，支持多面板
14. **文件导入**: 智能编码检测和DOCX解析逻辑保持不变，封装为独立工具函数
15. **数据迁移**: 启动迁移逻辑独立为 migration 模块，幂等执行

## 11. 已知缺陷与风险

1. **快捷键冲突**: init() 和 hotkeys-js 都注册了 ESC 和 Ctrl+S，行为不一致
2. **document.execCommand废弃**: 双击重命名使用了废弃的 document.execCommand("selectAll")，Vue3 应使用 ref + select()
3. **去AI味执行顺序错误**: 硬规则在S1之前执行，应在S1之后
4. **风格样本注入位置错误**: 样本只注入最后一个SKILL，应注入S1改写师
5. **_closeAllPanels vs closeAllPanels**: 两个方法命名相似但行为不同（前者不显示app-main，后者显示）
6. **面板缩放全局监听**: resize 的 mousemove/mouseup 监听在 document 上，多面板时可能互相干扰
7. **退出确认按钮重复绑定**: init() 中绑定了退出确认按钮，如果 init() 被调用多次会导致重复绑定
