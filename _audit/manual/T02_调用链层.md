## 2. _aiRequest(cfg) — 统一AI请求底层方法

**位置**: renderer_v2.js L2317-L2520
**职责**: 所有AI API调用的唯一底层入口，支持流式/非流式、8次递增重试、空闲检测断流保护、心跳重连、400自适应max_tokens减半

### 2.1 参数契约

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| cfg.baseUrl | string | this.settings.baseUrl | API基础URL |
| cfg.apiKey | string | this.settings.apiKey | API密钥 |
| cfg.messages | array | (必填) | OpenAI格式消息数组 |
| cfg.model | string | this.settings.model或_getSelectedModel() | 模型ID |
| cfg.temperature | number? | 不传则不设 | 温度 |
| cfg.maxTokens | number | 8192 | max_tokens(自适应减半) |
| cfg.stream | boolean | true | 是否流式 |
| cfg.signal | AbortSignal? | 无 | 外部取消信号 |
| cfg.timeoutMs | number | 600000(10分钟) | 单次请求超时 |
| cfg.retry | boolean | true | 是否自动重试 |
| cfg.onChunk | function? | 无 | 流式chunk回调，参数为累积全文 |
| cfg.onReasoning | function? | 无 | reasoning_content回调 |
| cfg.onUsage | function? | 无 | token用量回调 |
| cfg.onPause | function? | 无 | 暂停检查钩子(每chunk前调) |

### 2.2 请求构建

请求体构建:
- model: cfg.model || this.settings.model || this._getSelectedModel()
- messages: cfg.messages
- stream: cfg.stream !== false (默认true)
- max_tokens: cfg.maxTokens > 0 ? cfg.maxTokens : 8192
- temperature: 仅当cfg.temperature != null时设置

URL: baseUrl + '/chat/completions'
Headers: { Authorization: 'Bearer ' + apiKey, 'Content-Type': 'application/json' }

### 2.3 重试机制(8次递增+心跳无限)

**maxRetries**: retry!==false时为8次
**retryDelays数组**(20个递增值，单位ms):
[2000, 4000, 6000, 8000, 10000, 12000, 15000, 20000, 25000, 30000, 35000, 40000, 45000, 50000, 55000, 60000, 65000, 70000, 75000, 80000]

**重试条件**:
- HTTP 429/502/503: 等待retryDelays[attempt]后重试
- TimeoutError/AbortError(非用户取消): 等待后重试
- 其他错误(非客户端错误): 等待后重试

**不重试的条件**(客户端错误永不成功):
- 消息包含'API Key'(401)
- 消息包含'访问被禁止'(403)
- 消息包含'接口不存在'(404)
- 消息包含'请求参数错误'(400且非max_tokens问题)
- cfg.signal.aborted(用户主动取消)

**400自适应max_tokens减半**:
当resp.status===400且max_tokens>1024且attempt<maxRetries时:
1. 尝试读取body，检查是否包含max_tokens/max output/maximum/too large/token关键词
2. 如果匹配，max_tokens = Math.floor(max_tokens / 2)，continue重试
3. 即使无法读body也尝试减半
4. 每次减半后等待1秒

**心跳重连**(所有8次重试用完后):
1. 进入while(true)无限循环
2. 每次等待60秒
3. 发探测请求到同一个baseUrl/chat/completions
4. 如果hbResp.ok: 重新执行完整流式/非流式读取，返回结果
5. 如果失败: 继续循环，永不放弃
心跳模式无限重试直到API恢复。

### 2.4 流式SSE解析

1. resp.body.getReader()获取reader
2. new TextDecoder()创建decoder
3. while(true)循环读取chunk
4. chunk.done时break
5. 每次读取前调用cfg.onPause()(暂停检查钩子)
6. buffer += decoder.decode(chunk.value, {stream:true})
7. 按换行符分割buffer，保留最后不完整的行
8. 每行: 去空格，检查'data: '前缀，slice(6)取数据
9. '[DONE]'标记跳过
10. JSON.parse解析，取choices[0].delta
11. delta.reasoning_content: 累积到reasoningText，调onReasoning
12. delta.content: 累积到fullText，调onChunk(传累积全文而非增量)

**reasoning回退**: 如果fullText为空但reasoningText有内容，用reasoningText作为输出。

### 2.5 空闲检测(防断网)

在流式读取循环中，使用Promise.race实现空闲检测:

1. 创建_idlePromise: setTimeout(_idleThreshold)后resolve('idle')
2. 创建_chunkPromise: reader.read().then(包装为{type:'chunk',data:c})
3. await Promise.race([_chunkPromise, _idlePromise])
4. 如果结果是'idle':
   a. _idleCount++
   b. 如果_idleCount >= 3，_idleThreshold从15000降为10000
   c. await reader.cancel()释放资源
   d. throw new Error('stream_idle_timeout')
5. 如果结果是chunk: clearTimeout(_idleTimer)，正常处理

行为契约:
1. 首次空闲15秒触发断流
2. 断流后throw，被外层重试机制捕获
3. 3次空闲后阈值降为10秒(更激进)
4. reader.cancel()确保资源释放

### 2.6 诊断集成

每次_aiRequest调用:
1. 生成唯一_diagKey = 'api-' + Date.now() + '-' + random
2. DiagLogger.perfStart(_diagKey)开始计时
3. 成功后: DiagLogger.perfEnd(_diagKey, 'api', 'API'/'API stream') + trackApiCall(model, 0, elapsed, 'ok')
4. 失败时: DiagLogger.trackApiCall(model, 0, 0, 'error', e.message)

### 2.7 返回值

返回 { text: string, reasoning: string }
- text: 模型输出的正文内容(或reasoning回退)
- reasoning: reasoning_content全文(如有)

非流式模式: 解析resp.json()，取choices[0].message.content和reasoning_content
流式模式: 返回累积的fullText和reasoningText

### 3.2 Agent集成(参数覆盖)

当opts.agentId存在时:
1. AgentManager.get(opts.agentId)获取Agent配置
2. 如果ag.systemPrompt存在: 覆盖sysContent(替换默认系统提示词)
3. 如果ag.model存在: 覆盖agentModel
4. 如果ag.temperature != null: 覆盖agentTemperature
5. 如果ag.maxTokens存在: 覆盖agentMaxTokens

Agent只是配置容器，覆盖4个参数: systemPrompt, model, temperature, maxTokens。无调度逻辑。

### 3.3 maxTokens保障(永不使用默认4096)

三重取最大值:
1. opts.maxTokens (调用方传入)
2. agentMaxTokens (Agent配置)
3. this._getAgentMaxTokens() (全局设置)

如果结果<=0或falsy，兜底128000。确保不会使用API默认的4096。

### 3.4 技能链执行分支

当opts.skillIds存在且长度>0时:
1. 过滤空ID，映射到SkillManager.get(id)，过滤null
2. 如果有有效技能:
   a. 读取文本过滤开关(#pl-text-filter-toggle)
   b. 计算maxTokens(三重取最大值)
   c. SkillExecutionEngine.getAutoValidators(type, {expectedCount})获取自动验证器
   d. ProviderManager.getVerifyProvider()获取验证供应商
   e. 构建engineOpts: {aiRequest, model, temperature, maxTokens, stream:true, onChunk, validators, finalValidators, verifyProvider, expectedCount, minProseLength}
   f. await SkillExecutionEngine.chain(prompt, _skills, _engineOpts)
   g. 如果_textFilterEnabled且非JSON: _applyTextFilter过滤
   h. 返回_finalText
3. 如果无有效技能: 降级到无技能模式

无技能时走_aiRequest直连:
1. messages = [{role:'system',content:sysContent},{role:'user',content:prompt}]
2. await _aiRequest({messages, model, temperature, maxTokens, stream:true, onChunk, onReasoning})
3. onReasoning回调: onChunk('[AI思考中] ' + rt.slice(-200))
4. 返回result.text

### 3.5 文本过滤集成

1. 读取#pl-text-filter-toggle的checked状态
2. 存入this._textFilterEnabled
3. 链式输出后: 如果_textFilterEnabled且!_looksLikeJSON(_finalText)
4. _finalText = _applyTextFilter(_finalText, _deAiFilterWords)
过滤只对非JSON输出生效(不影响结构化数据)

## 4. streamChat(userText, aiMsg) — 聊天流式

**位置**: renderer_v2.js L2599-L2720
**职责**: 右侧对话面板的流式聊天，支持Agent注入、技能注入、reasoning显示、消息按钮

### 4.1 调用参数

await this._aiRequest({
  messages: this.buildMessages(userText),  // 8层消息组装
  model: this._getSelectedModel(),
  temperature: this._getAgentTemperature(),
  maxTokens: this._getAgentMaxTokens(),
  stream: true,
  signal: this.abortController.signal,
  retry: false,  // 聊天不自动重试
  onPause: function() { return self._waitIfPaused(); },
  onChunk: 更新aiMsg的innerHTML为marked.parse(t),
  onReasoning: 显示[AI思考中]+reasoning末尾200字,
  onUsage: 更新token计数
})

关键: retry:false — 聊天不自动重试，失败直接显示错误。

### 4.2 buildMessages 8层组装顺序

1. 全局系统提示词 (settings.systemPrompt)
2. Agent系统提示词 (unshift到最前，最高优先级覆盖全局)
3. 上下文设定 (getContextSettings -> 格式化注入，含name/category/attrs)
4. 触发词扫描 (_scanTriggerKeywords -> 匹配的设定条目，含triggerKeywords)
5. 技能 (getContextSkills -> _renderSkillTemplate渲染，injectMode标注)
6. 长文记忆
7. 编辑面板模式上下文 (editorMode注入当前编辑内容+对应层pipeline SKILL)
8. 历史消息 + 用户消息

组装优先级: Agent systemPrompt > 全局 systemPrompt > 设定上下文 > 触发词 > 技能 > 记忆 > 编辑上下文 > 历史 > 用户

### 4.3 消息按钮(3个)

流式完成后动态注入3个操作按钮到msg-actions div:
1. 复制(msg-btn-copy): 复制消息文本到剪贴板
2. 重新生成(msg-btn-regen): 用相同输入重新调用streamChat
3. 应用到编辑器(msg-btn-apply): 将消息文本写入编辑区

每个按钮含内联SVG图标(14x14)。

### 4.4 错误处理

- AbortError: 显示[已停止生成]
- 其他错误: 显示红色错误信息
- 移除streaming-cursor类

### 4.5 Token估算

_estimateTokens(userText, aiText):
est = Math.ceil((inputLen + outputLen) / 1.5)
粗略估算，调用_updateTokenCount更新UI

## 6. fetchModelList() / testConnection() — IPC代理

**位置**: renderer_v2.js L1980-L2080
**职责**: 通过IPC绕过CORS获取模型列表

### 6.1 fetchModelList

1. 读取baseUrl和apiKey从DOM输入框
2. 调用window.electronAPI.fetchModels(baseUrl, apiKey)
3. result = { ok: boolean, data?: {data:[{id}]}, error?: string, status?: number }

5. 如果_editingProviderId存在: ProviderManager.update(id, {models: modelIds})
6. renderProviderModelList + 填充datalist

### 6.2 testConnection

与fetchModelList几乎相同，区别:
- 10秒超时(AbortController)
- 显示loading状态(_showLoading + _setBtnLoading)
- 按钮状态管理(测试中...disabled)

### 6.3 IPC vs 直接fetch

fetchModels走IPC的原因: 浏览器环境CORS限制，主进程无CORS问题。
fetchModels使用invoke(异步)，其余IPC使用sendSync(同步)。

## 9. 关键行为契约(15条)

1. _aiRequest是唯一底层: 除_callAiApi外所有AI调用都走_aiRequest
2. max_tokens永不默认4096: apiGenerate三重取最大值兜底128000
3. 8次递增重试: 2s到80s，覆盖网络波动
4. 心跳无限重连: 8次用完后60秒间隔无限探测，永不放弃
5. 400自适应减半: max_tokens过大导致400时自动减半重试
6. 客户端错误不重试: 401/403/404直接抛出
7. 用户取消立即抛出: signal.aborted不重试
8. 空闲检测15s/10s: 首次15秒，3次后降为10秒
9. reasoning回退: content为空时用reasoning_content作输出
10. 流式onChunk传累积全文: 不是增量delta，是累积值
11. buildMessages 8层优先级: Agent > 全局 > 设定 > 触发词 > 技能 > 记忆 > 编辑上下文 > 历史
12. 聊天不重试: streamChat的retry:false
13. _callAiApi历史遗留: 直接fetch无重试无reasoning，需统一到_aiRequest
14. fetchModels走IPC: 绕CORS，invoke异步
15. 诊断全链路: 每次_aiRequest都有perfStart/perfEnd/trackApiCall

## 10. Vue3迁移注意事项(10条)

1. _aiRequest -> apiService: 封装为Vue3 composable或service类，保持8次重试+心跳+空闲检测+400自适应完整移植
2. retryDelays数组: 20个值硬编码，提取为配置项或常量
3. 心跳无限重连: 必须保留，这是防断网核心机制。Vue3中用async generator或递归async实现
4. 400自适应减半: 保留逻辑，但注意减半后仍可能触发400(需设下限1024)
5. _callAiApi统一: 迁移时统一到apiService，消除直接fetch的历史遗留
6. buildMessages 8层: 迁移为消息构建器，保持优先级顺序。Agent systemPrompt的unshift(最高优先级)必须保留
7. streamChat onChunk DOM操作: Vue3改为响应式ref更新，不直接操作DOM
8. 消息按钮: Vue3改为组件化，3个按钮用lucide图标
9. fetchModels IPC: Vue3中preload.ts暴露fetchModels，主进程代理逻辑不变
10. 诊断集成: Vue3中DiagLogger迁移为Pinia store或composable，perfStart/perfEnd/trackApiCall接口不变
