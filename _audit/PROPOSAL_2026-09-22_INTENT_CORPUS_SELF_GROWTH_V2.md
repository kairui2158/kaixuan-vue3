# 意图路由语料自成长系统 V2 方案

日期：2026-09-22
状态：待用户审核
方案成熟度：成熟（执行边界、数据分层、失败路径、验证门、安全不变量均已闭合）

## 1. 问题定义

当前意图路由的工程结构、安全阈值、校准流程已经达到可交付水平，唯一成熟度短板是真实评估语料不足：

- 阈值选择语料仅 28 条真实 trace 样本，train/dev/test 分别为 10/9/9。
- 社区调研已补充生产示例库（151 条）、短语语料和对抗方法，但社区语料没有真实用户意图标签，不能直接充当校准考卷。
- 让客户反复导出运行记录会造成使用负担，不可持续。

V2 的目标是：客户零额外操作，应用在本地自动积累真实意图语料；用户在兜底交互中的显式选择自动转为高置信标注；社区语料作为影子诊断层使用，但不污染校准集。

## 2. 核心设计原则

1. **真实考卷只来自真实使用。** 阈值校准集只允许 confirmed 级真实样本进入。
2. **社区语料只做影子诊断。** 社区句式用于观察分数分布和发现盲区，不参与阈值选择。
3. **采集永远 fail-open。** 语料采集是观测层，任何失败不得阻塞对话、生成或编辑器写入。
4. **生产行为不变。** V1 不自动修改路由阈值、不自动改示例库、不改变 fallback 语义。
5. **本地优先。** 语料默认保存在本机 userData 目录，导出是用户显式动作。
6. **写入安全不变。** writeFalseTriggers / missedRejections 硬约束继续由 M52 门禁保护。

## 3. 数据分层

### 3.1 真实语料层

来源：真实用户在大纲工作台、主页 API 对话中的路由现场。流水线路由观测是后续预留能力，V2 不接入生产采集。

记录字段：

- 用户输入文本
- 路由结果、决策层、分数、阈值、margin、OOS 判定
- fallbackMode 与 fallback 结果
- trace runId / turnId / API call 关联
- 工作台来源、项目作用域、时间戳
- 标注等级：confirmed / inferred / observed
- 标注依据与关联 turn

### 3.2 社区影子语料层

来源：社区调研沉淀的意图句式、通用 NLU 改写、领域化改写、负样本。

用途：

- 观察生产路由在新旧版本下的分数分布
- 发现某类句式被系统性压低或误判
- 为下一批人工审核示例提供候选

限制：

- 永远不进入 train/dev/test
- 永远不参与阈值选择
- 影子报告只能生成“候选改进建议”，不能自动改生产常量

## 4. 标注体系

### confirmed（显式确认）

触发条件：用户在 fallback 气泡或路由确认交互中做出显式选择。

用途：可进入真实语料候选池，经治理后参与校准。

### inferred（行为推断）

触发条件：跨轮行为明确暴露真实意图，例如：

- 被路由为 discuss 后，用户下一轮用明确写入动词重述
- 用户对输出结果采纳、拒绝或要求重做
- 用户对位置咨询回答后继续讨论，未触发写入

用途：进入分析池和候选池，不直接参与阈值校准。

### observed（纯观测）

触发条件：只有路由记录，无用户反馈信号。

用途：只做分布统计、疑难样本筛查和回归观测，不作为标签使用。

## 5. 架构设计

### 5.1 采集服务

新增 `src/services/intentCorpusCollector.ts`：

- 消费路由决策结果，而不是从 UI 反推
- 异步写入内存队列，批量落盘
- 写盘失败记录 DiagLogger，不抛入主链路
- 与 runTrace 事件同源关联，避免双源分叉

### 5.2 本地存储

位置：`userData/intent-corpus/`

结构：

- `samples.jsonl`：append-only 样本流
- `manifest.json`：schemaVersion、样本数、写入状态、保留策略
- `index.json`：输入哈希索引与去重记录

策略：

- schemaVersion 从 1 起步
- 单机默认保留 10,000 条，环形覆盖
- 写入使用主进程 IPC + 原子临时文件替换
- 损坏文件按 manifest / index / samples 顺序恢复，恢复失败时隔离旧文件并重建，不阻塞应用

### 5.3 标注回流

- fallback 气泡点击事件携带 turnId，直接生成 confirmed 样本
- 下一轮用户输入通过 runTrace turn 关联生成 inferred 候选
- 无法关联或证据不足时一律降级 observed

### 5.4 语料治理

- 输入归一化后计算哈希，同输入只保留最新路由现场
- 超长输入截断，避免语料库变成项目全文存储
- 项目作用域保留，导出默认按当前项目过滤，避免跨项目混装
- confirmed / inferred / observed 分池存储
- 影子语料与真实语料物理分文件，避免误导入

### 5.5 导出

导出物为“语料包”，不再要求客户导出完整运行记录：

- `corpus-package.json`：manifest + 分级样本
- 默认导出当前项目作用域
- 显式勾选才导出全局语料
- 可选附带影子语料报告
- 不包含项目正文、API response 全文、供应商密钥

### 5.6 影子校准

扩展 `scripts/calibrate-intent-routing-thresholds.mjs`：

- 输入：真实语料包 + 社区影子语料包
- 输出：当前生产配置 vs 候选配置对比报告
- 指标：accuracy、writeFalseTriggers、falseRejections、missedRejections、discussBlocked
- 硬约束：writeFalseTriggers = 0 且 missedRejections = 0 才可成为候选
- 输出只是“建议升级包”，不自动改生产常量

## 6. 执行阶段

### Phase 0：基线与影响圈

- 复读 M52、M8、M34、M40、M42 与最新 DEV_LOG
- 盘点路由决策点、fallback 事件、runTrace turn、IPC 存储入口
- 输出影响圈清单，未列入影响圈的文件不动

验收：

- 影响圈清单完成
- 现有 66 项意图路由测试基线通过

### Phase 1：采集与存储底座

- 新增 intentCorpusCollector
- 新增主进程 intent corpus IPC
- 实现 append-only JSONL、manifest、index、原子写
- 实现写盘失败 fail-open 与 DiagLogger 记录

验收：

- 单测覆盖写入、恢复、环形覆盖、损坏隔离
- 主链路失败注入后对话不受影响
- DiagLogger 与 runTrace 均有采集事件

### Phase 2：标注回流

- fallback 点击生成 confirmed 样本
- 跨轮行为生成 inferred 候选
- 无反馈样本落 observed
- 证据不足自动降级

验收：

- 单测覆盖三级标注与降级
- Electron 级实测：真实对话触发 fallback → 用户点击 → 文件中出现 confirmed 样本

### Phase 3：语料治理与导出

- 归一化去重
- 长度钳制
- 项目作用域过滤
- 语料包导出

验收：

- 同输入重复出现只保留最新现场
- 跨项目样本默认不混入
- 导出包体积显著小于 run trace，且无敏感字段

### Phase 4：社区影子语料层

- 新增 SHADOW_INTENT_CORPUS 数据源
- 影子语料与真实语料物理分离
- 影子报告输出分数分布与盲区清单

验收：

- 影子语料无法进入 train/dev/test 的约束由测试锁定
- 影子报告可标注疑似盲区，但不改生产阈值

### Phase 5：影子校准与升级包

- 校准脚本接入真实语料包与影子语料报告
- 输出当前配置 vs 候选配置对比
- 产出建议升级包，不自动应用

验收：

- writeFalseTriggers / missedRejections 硬约束有效
- 候选包包含完整指标与样本来源统计

### Phase 6：Electron 级真实 UI 验证

场景：

1. 正常 discuss 对话自动采样
2. 低置信输入触发 fallback，用户点击后生成 confirmed 样本
3. 用户重述写入意图生成 inferred 样本
4. 写盘失败注入后对话继续正常
5. 多轮对话后导出当前项目语料包
6. 社区影子语料只出现在影子报告，不进入真实语料包

验收：

- 每个场景都有落盘证据
- 采集失败不影响 API 返回与编辑器写入
- runTrace / DiagLogger 双侧日志覆盖

### Phase 7：文档与经验回写

- 新增 DEV_LOG
- 更新路由说明文档
- 若发现新事故模式，升级经验文件门禁

## 8. 风险与防护

| 风险 | 防护 |
| --- | --- |
| 采集阻塞主链路 | 异步队列 + fail-open + 失败注入测试 |
| 语料标签污染 | 三级标注，只有 confirmed 可进校准 |
| 社区语料混入考卷 | 影子语料物理分离 + 测试锁定 |
| 写盘损坏 | 原子写、manifest/index/samples 分层恢复 |
| 跨项目泄漏 | 项目作用域过滤，导出默认当前项目 |
| 隐私外泄 | 本地存储，显式导出，导出包字段审计 |
| 自动改阈值 | V1 不自动应用任何候选配置 |
| UI 行为回归 | fallback 交互语义不变，仅增加事件回流 |

## 9. 交付边界

本方案完成后：

- 客户正常使用即积累真实语料
- 客户无需导出完整运行记录
- 路由生产行为不变
- 开发方获得可审计的语料包与影子校准报告

后续版本再基于真实语料包人工审核示例库与阈值，不在本方案内自动上线。
