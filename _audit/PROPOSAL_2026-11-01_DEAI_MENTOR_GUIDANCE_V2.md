# 内嵌降AI“方法论指导者”升级方案 V2

日期：2026-11-01  
状态：待用户审核；审核通过前不改生产代码  
前置方案：`_audit/PROPOSAL_2026-11-01_DEAI_DIAGNOSE_ROUTE_RETURN_V1.md`  
适用范围：生成流水线正文层内嵌降AI、folder SKILL `meta.deai` 契约、降AI提示词、trace 与运行记录、手动降AI入口  
核心定位：**编译器不改稿，导师不抢权；生成前教方法，生成后教反馈，风格永远归作者与风格卡片**

## 1. 目标重定位

### 1.1 用户原始问题

用户在 V1 基础上解除了“只做编译器”的核心限制，提出新的方向问题：

> 从第二作者的身份退去变成编译器这个想法很好，这样不会再有正文层输出后被你打碎、打乱和语义破坏的现象。那么降AI味的本质作用是什么？是不是可以变成指导者？你给的资料能不能足以支撑你成为一个指导者？

这句话包含三个要求：

1. 保留 V1 的确定性边界：降AI不得打碎、打乱、破坏正文语义。
2. 重新审视降AI的本质作用：不只是事后找问题，而是让正文层输出质量不再有AI味。
3. 判断 `D:/codex/去AI味资料说明.md` 所述 story-deslop 资料是否足以支撑“指导者”角色。

### 1.2 V2 对“降AI本质作用”的定义

降AI的本质作用不是“把稿子洗干净”，而是：

1. **生成前**：把已知的AI味成因转成可执行的创作方法论，教给当前步骤，让模型在生成时就避开。
2. **生成中**：不干预。降AI不修改请求、不中断执行、不替换模型输出。
3. **生成后**：给出位置化诊断与教学反馈，让下一次尝试或下一次修复知道“哪里、为什么、按什么方法改”。
4. **门禁处**：只对确定性缺陷（截断、占位符、协议泄漏、复读退化）执行编译器式阻断；统计类AI味信号只做 advisory。

因此 V2 的角色不是纯编译器，而是“方法论指导者 + 确定性门禁”。它比 V1 多了教学职责，但没有拿回改稿权。

### 1.3 与 V1 的关系

V1 解决的是“降AI不要当第二作者”。V2 解决的是“降AI不要只会事后报警”。两者不是替代关系：

- 继承 V1：位置化 findings、退化指纹、owner 路由、复扫门禁、skill-wins 默认化、legacy-auto/deep-fix 退役。
- 新增 V2：生成前方法论指导包、生成后教学反馈、指导职责所有权声明、旧三段提示词迁移。

## 2. 资料支撑度评估

### 2.1 足以支撑的部分

story-deslop 资料足以支撑应用成为“方法论指导者”，证据如下：

1. **三层诊断框架可用**：表达、叙事用笔、故事因果的分层方法见 `D:/codex/oh-story-claudecode/skills/story-deslop/SKILL.md:4`、`:17`、`:20`。它提供了“AI味不是单一词频问题”的教学框架。
2. **白话位置化报告原则可用**：作者报告必须用白话、原文位置与阅读后果，不把检测类别名当评价，见同文件 `:20`。这正好补上 V1 findings 只有技术字段的用户侧缺口。
3. **确定性与语义分层可用**：脚本命中是定位线索，零命中不代替三层扫描，见同文件 `:48`。这支撑“编译器门禁与语义教学分离”。
4. **表达层方法可教**：套词是内容缺口而非词汇问题、同义词替换无效，见 `references/expression.md:21`；台词要放回对象、场合与意图，见 `:36`；情绪直写与身体反应按删除测试判断，见 `:42-44`。
5. **叙事用笔层方法可教**：找最需要被经历的地方、关键过程不能被概述吞掉，见 `references/narrative-focus.md:9-15`；删除、压缩、展开三测试见 `:21-27`。
6. **故事因果层边界可教**：逐项有问题才记录、不能为填表加戏，见 `references/story-logic.md:18`；改变事件、动机、结果需授权，见 `:36`。
7. **风格裁决优先级可用**：当前请求 > 本书文风 > 传入偏好 > 主对标 > 默认值，见 `references/style-resolution.md:7`；reference 中的默认写法不得升级为作者不可覆盖规则，见 `:11`。

### 2.2 不足以支撑的部分

资料不足以支撑以下三种“更强指导者”形态，方案必须诚实降级：

1. **不足以支撑自动语义导师**：叙事用笔与故事因果判断需要 LLM 阅读完整语境。本地脚本只能覆盖表达层与确定性缺陷，无法可靠判断“这场戏是否值得经历”。
2. **不足以支撑自动评分导师**：现有正负样本仍是 provisional，阈值、词库、评分权重不能因引入教学提示就解除限制。经验门禁 G1.22 明确整体判定只能由样本结构解锁：`_audit/神意开发经验总结_v9.md:412-424`。
3. **不足以支撑自动改稿导师**：story-deslop 自己也把故事级修改转成设计提案并要求授权，见 `references/story-logic.md:36`。应用侧若据此自动改稿，就是重新制造 V1 要退场的第二作者。

### 2.3 判定结论

资料支撑度判定表：

- 方法论指导者：**支撑**。可以把三层框架、表达方法、三测试、风格优先级转成步骤化指导包。
- 确定性门禁：**支撑**。可继承 V1 的退化指纹与位置化 findings。
- 自动语义导师：**不支撑**。语义判断只能交给 folder SKILL 的叙事 verdict。
- 自动评分导师：**不支撑**。provisional 校准状态不变。
- 自动改稿导师：**不支撑且方向错误**。改稿权必须按 owner 路由。

一句话结论：资料能让应用“教方法”，不能让应用“替作者写、替SKILL判、替校准器评分”。如果说资料足够让应用自动教模型写好小说，那就是撒谎。

## 3. V2 总体架构

### 3.1 三层职责

第一层：**确定性编译器门禁**

- 输入：候选正文。
- 检测：截断、占位符、协议泄漏、逐行复读、长句复读、工程词 tier1。
- 输出：`line / column / ruleName / severity / excerpt / owner`。
- 权限：可阻断平台合同缺陷，不修改正文。

第二层：**方法论导师层**

- 生成前：按当前步骤角色生成 `deaiGuidancePack`，只教与本步骤职责相关的方法。
- 生成后：生成 `DeaiTeachingFeedback`，携带失败指标、位置摘录、判断方法与 owner 路由。
- 权限：提示词教学、反馈教学；不做叙事 verdict，不做自动重试语义类问题。

第三层：**风格裁决层**

- 唯一 owner：创作风格卡片。
- 应用指导包只声明“默认方法”；作者或风格档案明确选择优先。
- 降AI不得反向改写风格语义。

### 3.2 指导包分步分发

不再把同一段 17 条方法论注入所有步骤。指导包按职责分发：

- S1 骨架层：教事件密度、因果骨架、场景作用、删除/压缩/展开测试，最多 6 条。
- S2 生成层：教表达核心、叙事用笔、风格优先、禁止机械执行检测指标，最多 6 条。
- S3 打磨层：教最小修复边界、语义保真、表达微调、禁止扩写压缩，最多 6 条。

每条指导必须包含：方法名、一句话原则、判断方法、边界说明。禁止只给禁令，例如“禁止短句堆叠”必须附带“短句只用于关键转折，连续碎片链才是问题”。

### 3.3 生成后教学反馈

生成后反馈结构：

- `failedContract`：明确的合同失败项。
- `positions`：位置摘录，有界，不携带全文。
- `methodologyHints`：判断方法与修复方向。
- `ownerRoute`：`app-contract / skill-narrative-style / normalize-format`。
- `candidateFullTextIncluded: false`：硬性约束，防止旧稿成为强先验。

语义类 findings 默认 advisory，只进入教学报告，不自动触发重试。若 SKILL 自己判 `not_ready`，应用只路由回上游，不二次判叙事。

## 4. 接口设计

### 4.1 指导包服务

新增 `src/services/deaiGuidancePack.ts`，替代 `de-ai.js` 三段提示词的生产注入职责。

```ts
export interface DeaiGuidanceItem {
  id: string
  method: string
  principle: string
  judgment: string
  boundary: string
}

export interface DeaiGuidancePack {
  stepRole: 'skeleton' | 'generator' | 'polisher'
  stylePriorityNotice: string
  guidance: DeaiGuidanceItem[]
  omittedOverlaps: string[]
  source: 'story-deslop-methodology' | 'app-default'
}
```

要求：

1. `guidance` 每步最多 6 条。
2. `omittedOverlaps` 记录与 folder SKILL 模板重复而被省略的条目。
3. 指导包必须声明 `stylePriorityNotice`：风格卡片优先。

### 4.2 教学反馈结构

```ts
export interface DeaiTeachingFeedback {
  failedContract: string[]
  positions: Array<{
    line: number
    column: number
    excerpt: string
    ruleName: string
    readingEffect: string
    repairHint: string
  }>
  methodologyHints: string[]
  ownerRoute: 'app-contract' | 'skill-narrative-style' | 'normalize-format'
  candidateFullTextIncluded: false
}
```

`readingEffect` 来自 story-deslop 的“阅读后果”原则，见 `skills/story-deslop/SKILL.md:20`、`:54`。它让反馈说“读者在这里会失去因果承接”，而不是只说命中 `cliche-density-tic`。

### 4.3 `meta.deai` 契约 V2

契约版本升级为 2：

```json
{
  "deai": {
    "contractVersion": 2,
    "generation": "on",
    "finalStepDetection": "on",
    "conflictPolicy": "skill-wins",
    "guidanceOwnership": "skill"
  }
}
```

`guidanceOwnership` 合法值：

- `skill`：folder SKILL 自己声明完整方法论，应用只保留编译器门禁。
- `app`：应用指导包负责生成前教学。
- `split`：SKILL 声明部分方法，应用补充缺失方法。

未声明 `guidanceOwnership` 的推导规则：

- `conflictPolicy = skill-wins` 视为 `skill`。
- `app-wins` 视为 `app`。
- `report` 或缺失默认视为 `app`，但只做教学，不改稿。

## 5. 20轮深入推演

### 第1轮：角色重定义

问题：降AI到底该是编译器还是指导者？  
推演：编译器解决“不破坏”，但无法减少AI味产生；指导者可以在生成前降低问题发生率。  
结论：V2 定位为“方法论指导者 + 确定性门禁”，不是“诊断器或改稿器二选一”。

### 第2轮：教学的时机

问题：生成前教还是生成后教？  
推演：只事后教会把成本压在重试上；只事前教缺少针对失败位置的纠偏。  
结论：生成前指导包 + 生成后教学反馈双阶段。

### 第3轮：资料是否足够

问题：story-deslop 能否支撑指导者？  
推演：表达、叙事用笔、故事因果三层方法论完整，且强调位置与阅读后果；但脚本不能做完整语义判断。  
结论：支撑方法论指导者，不支撑自动语义导师。

### 第4轮：评分与教学的边界

问题：指导者是否要给正文打分？  
推演：评分依赖校准样本；当前正负样本结构仍不足以解除 provisional。  
结论：教学反馈不输出总分，只输出位置化建议与合同失败项。

### 第5轮：与风格卡片的关系

问题：指导包会不会变成新的风格 owner？  
推演：story-deslop 明确当前请求与本书文风优先，reference 默认值不得升级为不可覆盖规则。  
结论：风格卡片是唯一 owner，指导包必须声明优先级让位。

### 第6轮：与 folder SKILL 的重复

问题：SKILL 模板已含大量写作方法，应用再注入会不会挤压？  
推演：当前 S1/S2/S3 模板已覆盖事件密度、表达、打磨边界；重复注入是历史规则挤压根因之一。  
结论：指导包必须做 overlap 省略，输出 `omittedOverlaps` 供 trace 对账。

### 第7轮：指导条数上限

问题：方法论很多，是否全量注入？  
推演：V1 已发现 17 条方法论与 S2/S3 规则重复；全量注入会稀释关键指令。  
结论：每步最多 6 条，按步骤职责选择。

### 第8轮：S1 的教学边界

问题：S1 是否需要表达层教学？  
推演：S1 只出骨架，不写正文；表达教学没有落点。  
结论：S1 教事件密度、因果骨架、场景作用与三测试。

### 第9轮：S2 的教学边界

问题：S2 是否需要故事因果教学？  
推演：S2 按骨架施工，不能擅自改变事件与结果。  
结论：S2 教表达与叙事用笔，故事因果只作为“发现缺口时上报，不自行补设”的边界。

### 第10轮：S3 的教学边界

问题：S3 是否需要事件密度教学？  
推演：S3 只打磨表达，不能补事实与结构。  
结论：S3 教最小修复、语义保真、禁止扩写压缩与机械去重。

### 第11轮：反馈是否携带旧稿

问题：教学反馈带全文是否更有效？  
推演：历史事故证明旧稿全文会成为强先验，诱发复述或压缩。  
结论：反馈只带失败指标、位置摘录与判断方法，`candidateFullTextIncluded: false`。

### 第12轮：语义 findings 是否触发重试

问题：语义类问题是否由应用触发重试？  
推演：G2.9 规定叙事有效性归 SKILL，平台合同归应用；应用触发语义重试会变成第二裁判。  
结论：语义 findings 默认 advisory 教学报告；重试由 SKILL verdict 或合同失败触发。

### 第13轮：教学反馈的路由

问题：反馈生成后交给谁？  
推演：合同缺陷归应用编排；叙事/风格归 SKILL；确定性格式归规范化层。  
结论：复用 V1 owner 路由，教学反馈只是让任务包更可执行。

### 第14轮：trace 展示

问题：教学反馈如何让用户看见？  
推演：只有技术字段用户无法判断是否合理；story-deslop 的白话与阅读后果原则可借鉴。  
结论：trace 增加指导包摘要、省略项、教学反馈与 owner 路由。

### 第15轮：UI 是否新增阻塞状态

问题：教学报告是否需要用户裁定？  
推演：用户明确反对“暂停等待作者裁定”状态。  
结论：教学报告非阻塞，可折叠查看；不新增等待状态。

### 第16轮：并行流水线影响

问题：指导包是否影响并行生成？  
推演：指导包是本地字符串构造，无额外 API 请求；风险在 trace 膨胀。  
结论：trace 保存结构化摘要，不保存全量指导包文本重复副本。

### 第17轮：folder SKILL 是活的

问题：固定指导包会不会锁死 SKILL 迭代？  
推演：用户明确说明 folder SKILL 会持续测试迭代。  
结论：`guidanceOwnership` 允许 SKILL 声明接管教学；应用只保留编译器门禁与 trace。

### 第18轮：旧提示词退役

问题：`DEAI_METHODOLOGY_PROMPT` 等三段提示词如何处理？  
推演：直接并存会新旧语义打架；直接删除会破坏未迁移路径。  
结论：分阶段退役，按 G0.10 七层清零与五证验收。

### 第19轮：分阶段放行

问题：一次性上线教学是否安全？  
推演：教学有效性未验证，需真实生成样本。  
结论：Phase 1 影子观察，Phase 2 接管路由，Phase 3 旧语义退役。

### 第20轮：反向质询

问题：V2 最可能错在哪？  
推演：

1. 指导包过长，重新制造规则挤压。
2. overlap 判断漏项，SKILL 与应用重复教学。
3. `guidanceOwnership` 推导错误，SKILL 声明被应用覆盖。
4. 教学反馈携带位置错误，误导修复。
5. advisory 被误接成重试触发器。
6. 三段旧提示词残留在测试或文档中继续守护旧行为。
7. 教学效果被单测数量证明，而非真实生成样本证明。

结论：以上七项全部进入验收门禁；任何一项未通过不得进入下一阶段。

## 6. 实施方案

### Phase 1：指导包重构与影子观察

目标：建立教学能力，但不改变生成行为。

任务：

1. 新增 `deaiGuidancePack` 服务。
2. 实现三步角色指导包与 `omittedOverlaps`。
3. trace 输出指导包摘要：条数、方法名、省略项、ownership。
4. 保留现有三段提示词，但记录新旧注入对照。
5. 至少 20 章真实生成影子观察，覆盖 2 个题材、2 个模型。

验收：

- 指导包每步不超过 6 条。
- overlap 省略有正向与负向测试。
- Phase 1 正文输出与旧路径逐字节一致。
- 影子样本报告包含合同失败率、重试次数、耗时、blocking/advisory 分布。
- 未达标不得进入 Phase 2 默认放行。

### Phase 2：教学反馈接管与 skill-wins 默认化

目标：教学反馈成为修复任务包的信息来源，旧注入退场。

任务：

1. 实现 `DeaiTeachingFeedback`。
2. 修复任务包携带失败指标、位置摘录、方法提示、owner 路由。
3. `conflictPolicy` 默认迁移为 `skill-wins`。
4. `meta.deai` 升级 contractVersion 2，新增 `guidanceOwnership`。
5. UI 展示教学反馈，非阻塞可折叠。

验收：

- skill-wins 迁移五证：旧持久化自动迁移并落盘、旧磁盘包健康检查阻断、覆盖导入保留新语义、执行面消费磁盘权威源、物理请求不再出现旧语义。
- 语义 advisory 不触发自动重试的负向断言。
- 真实 UI 验证教学反馈展示，不允许脚本注入冒充交互。
