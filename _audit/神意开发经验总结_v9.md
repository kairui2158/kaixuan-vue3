# 神意助手开发经验总结 v10

> 版本：v10.3.0　更新日期：2026-11-06
> 本文件是当前唯一有效的开发经验规则文件。v1-v9 的有效语义已并入本版；L3 归档映射外置到 `_audit/神意开发经验总结_v9_L3_ARCHIVE.md`；过程细节只查 `_audit/DEV_LOG_*.md` 与 `_audit/DEV_LOG_MASTER_INDEX.md`。

## v10 结构与维护规则

1. 门禁分四层：L0 永恒门禁、L1 通用工程门禁、L2 领域门禁、L3 归档映射。执行时必读 L0-L2 中与本任务相关条目；L3 只作追溯，不作为执行依据。
2. 每条门禁必须写明：规则、适用范围、失效条件、来源。无法写失效条件的规则归入 L0；其余必须写可判断的失效条件。
3. 禁止无限追加特殊优先级条目。L0 内所有门禁同为最高优先级；新事故先判断是既有 L0/L1 原则未执行，还是 L1/L2 细则缺失。确需新增 L0 时，必须说明既有 L0/L1/L2 为什么无法覆盖。
4. 禁止尾部日期修订章节。新经验先提炼进对应层级；无法提炼为规则的过程只写 DEV_LOG。
5. 同一语义禁止多处维护。本文件正文是唯一规则源；速查表、重复修订记录、并行经验文件一律禁止。
6. 版本升级必须更新本文件头部版本号；门禁变更必须写 DEV_LOG，并在 DEV_LOG 中登记旧编号去向。
7. 旧经验文件在新版合并完成后必须删除，禁止旧版与当前版并存。
8. 修订史维护：头部只保留当前版本号、更新日期与本结构规则，禁止逐版新增要点在头部累积。v8.0-v8.20 的规则语义已并入 L0-L2 正文；过程细节由 `_audit/DEV_LOG_MASTER_INDEX.md` 索引到对应 DEV_LOG、TASK_LEDGER 与 Git 历史追溯。
9. 门禁冲突裁决：L0 优先于 L1，L1 优先于 L2；同层冲突时，更贴原始目标且更严格者生效，且必须在任务台账登记冲突与选择理由。禁止用“更宽的门禁”覆盖“更严的门禁”。

## L0 永恒门禁

### G0.1 目标对齐

每轮任务先复述原始目标与最终可感知行为；执行中偏离目标必须显式登记原因。方案、实现、验证、交付物无法对应同一目标时，禁止声称完成。

- 适用范围：所有任务，包括代码、方案、文档、封装、调研。
- 失效条件：永不失效。
- 来源：v5 使用路由、M17、M18。

### G0.2 无预算铁律

用户明确表示不设预算后，任务执行不得设置 token、时间或轮次预算上限，不得以预算耗尽、上下文接近上限、任务过长为由中断或降级目标。长任务只按目标完成度终止，不按消耗量终止。

- 适用范围：所有任务、目标模式、自动化任务。
- 失效条件：用户明确重新要求设置预算。
- 来源：v5 §6 规则 16。

### G0.3 诚实闭环

完成声明必须区分已验证、未验证、无法验证、历史证据保留。mock、仿真、离线基线不得冒充真实链路；无真实链路证据时必须写“未验证”，禁止用“理论可行”“主体完成”“测试全绿”冒充闭环。

- 适用范围：所有完成声明、方案成熟度结论、验证报告。
- 失效条件：永不失效。
- 来源：M10、M18、M38、M41、M47、M53、M67。

### G0.4 门禁复读

动手前复读最新 DEV_LOG 与本文件相关层级；修复后回写 DEV_LOG 与经验。跳过复读造成的重复事故，责任在执行者，不在规则缺失。

- 适用范围：所有修改、修复、封装、调研任务。
- 失效条件：永不失效。
- 来源：M6。

### G0.5 回头看

每次任务收尾前必须执行回头看：对账原始目标、逐行审 diff、盘点生产入口与旁路、双向扫描生产与验证器、核对日志与测试证据、核对本轮证据真实属于本轮。未执行回头看不得声称完成。

- 适用范围：所有任务。
- 失效条件：永不失效。
- 来源：M17、M53。

### G0.6 方案成熟度

方案提交用户审核或执行前，必须分别评估执行器/工具层、应用方案/交互闭环、实现接线、验证标准四层，并给出 `成熟`、`半成熟（列断点与放行条件）`、`不成熟（禁止执行）` 三种结论之一。半成熟方案若断点涉及目标行为本身，禁止进入写码阶段。

- 适用范围：新功能、修复方案、双方案融合、架构改造。
- 失效条件：永不失效。
- 来源：M18。

### G0.7 正反推研磨

非平凡修改必须完成：目标倒推、爆炸半径矩阵、正推生效证据、反推质询、优先级证据化修订。正反推结论必须锚定真实用户路径或真实代码入口；只看逻辑成立、只测执行器、mock 强制中间态均视为假研磨。

- 适用范围：非平凡修改、架构调整、跨模块修复。
- 失效条件：永不失效。
- 来源：M12。

### G0.8 任务收尾清理

任务完成声明前必须分层清理：可再生成旧产物、临时探针、解包残留、旧安装产物、blockmap。删除前核对绝对路径，删除后复核不存在并写入 DEV_LOG。禁止把未提交源码、测试、方案、DEV_LOG、经验文件、当前验证证据当“旧留存”删除；git 脏状态必须先分类再动。

- 适用范围：所有任务收尾。
- 失效条件：永不失效。
- 来源：M29、M42、M50。

### G0.9 影响圈声明

动手前先列“打算改的”和“可能碰到的”；未列入影响圈的不碰。修改 A 前必须建立旧链路矩阵，至少覆盖生产入口、服务层、UI、测试、脚本、规格文档、日志/trace 字段七面；任何一面试图继续消费 A 的旧假设即未闭环。

- 适用范围：所有修改。
- 失效条件：永不失效。
- 来源：M1、M26。

### G0.10 新旧并存清零与执行路径迁移防御

删除或替换链路时必须覆盖源码、测试、脚本、规格、日志、运行状态、构建产物七层。现役规格、教学、测试不得继续要求已删除链路；旧状态名、旧工具名、旧 UI 入口、旧日志语义在执行层命中 0 才算闭环。负向断言命中不等于残留，必须先区分“断言不存在”与“仍在执行”。

执行路径迁移后，旧入口必须保留防御断言：旧执行器收到新路径模式时必须显式失败并给出迁移错误，禁止静默回退成“看似可用但缺少新 runtime/guidance/协议保障”的旧执行形态。具体 compose/chain 事故见 `DEV_LOG_2026-10-03_phase7-a3-compose-unified-runtime.md`。

门禁语义升级本身属于协议/执行语义变更：升级时必须反查全仓存量测试、共享实现与工作区验收包装层，找出仍守护旧行为的前置用例，并同批迁移为断言新语义 + 负向断言旧形态。只迁移事故触发链路，未横向清零共享执行器、composite、workspace 验收与测试守护，视为 G0.12 台账缺口；禁止以“测试当前全绿”证明旧语义已删除。

- 适用范围：删除功能、协议变更、执行形态变更、生产入口迁移。
- 失效条件：永不失效。
- 来源：M20、M26、M28、M49、M72、2026-10-03 Phase 7-A3、2026-10-31 contextPolicy 退役。

旧语义退役验收不能停留在“新入口正确”：必须包含旧持久化数据自动迁移且落盘、旧磁盘包被健康检查阻断、覆盖导入保留新语义、执行面消费磁盘权威源、物理请求不再出现旧语义五项证据。只证明新配置正向通过而未让旧状态穿完整迁移链，视为 G0.10 未闭环。

### G0.11 真实交互冒充禁令

验证目标包含“用户可通过 UI 完成 X”时，X 本身必须由真实 DOM 点击、输入或选择完成；脚本注入只允许用于准备外部依赖、隔离数据和安装素材，不允许直接写入业务选中态、会话状态或运行结果冒充用户操作。验证器必须同时证明：操作前状态为未选中，操作目标存在于真实下拉/控件中，操作后由应用自身状态和 UI 共同确认。违反此规则的验证结果一律无效，且必须重新执行。

- 适用范围：所有 Electron 级真实 UI 实测、E2E、发布验收、SKILL 加载验证。
- 失效条件：验证目标本身是数据导入、持久化恢复或后端链路，且用户交互不是被测行为。
- 来源：2026-10-02 Phase 7 SKILL 选择注入冒充事故。

### G0.12 门禁执行台账

经验门禁不得靠口头声明执行。所有非平凡任务（修复、方案、封装、调研、经验回写、跨文件改动）必须产出任务台账，写入 `_audit/TASK_LEDGERS/` 并由当轮 DEV_LOG 链接；简单单点任务可把精简台账并入 DEV_LOG。台账必须包含七节，缺任何一节不得进入完成声明：

1. 目标与原话：用户原始目标原文、最终可感知行为、本轮交付物。
2. 门禁读证：列出本轮适用的 G 编号，并为每条引用经验文件实际行号或关键句；只写“已读 G0-G2”视为未读。
3. 路由判定：列出加入与排除的门禁；每个排除项必须写“为什么不适用”；无理由排除视为跳读。
4. 影响圈与作者反证：打算改的、可能碰到的、方案最可能错的假设及证伪方式。
5. 停止条件：机器可判定的完成/失败条件；“看起来完成”“测试全绿”不是停止条件。
6. 执行证据：关键命令、原始输出关键行、file:line、before/after；替代证据必须写明不能证明的行为面。
7. 缺口清单：未执行、降级、不可验证、遗留项；无缺口时也必须写“本轮无登记缺口”，禁止省略。第七节必须同时包含 G1.14 缺陷面枚举清单与命中处置，禁止用“无缺口”替代枚举证据；枚举清单缺失视同台账缺节，任务状态只能是未完成。

台账是门禁执行凭证，不是新报告形式主义：重复信息可引用 DEV_LOG 与验证文件，但七节结构必须可见。回头看必须逐项对账台账；台账缺失或空白节未说明原因时，任务状态只能是未完成。

防偷懒硬闸：完成声明 GATE 模板必须包含 `[DEFECT-SWEEP]` 行并引用台账枚举清单；缺失、空白或只写“无”而无枚举过程证据时，GATE 判 FAIL，禁止以“改动点回归通过”冒充缺陷面清零。发现式扫描若在事后才由用户实测触发，必须在台账登记“本条门禁失效事故”并回写来源，不得静默补记。

- 适用范围：所有非平凡任务与简单任务的精简并入形式。
- 失效条件：永不失效。
- 来源：2026-10-06 用户追问「经验文件里是否能让你偷懒的漏洞」；漏洞审计确认口头合规、自判路由、无凭证回头看、作者自评成熟度、不可判定停止条件、无冲突裁决顺序六类偷懒通道。2026-11-06 追加第七类偷懒通道：改动点回归冒充缺陷面清零；以 GATE `[DEFECT-SWEEP]` 硬闸与台账第七节枚举清单封堵。

### G0.13 最小必要性与过度设计禁令

新能力、新配置、新状态、新报告或新验证链路，必须先证明“用户目标必须依赖它”。观测数据未完成校准前，不得产品化为 prompt、规则包、阈值或自动决策；禁止为了验证体系本身引入新的复杂链路，也禁止把“更多配置、更多状态、更多报告”当成质量提升。

新增机制前必须回答五问：用户目标是否必须依赖它；现有机制为什么不够；是否会增加延迟、状态纠缠或语义冲突；删除它会不会损失真实用户价值；是否有更小实现。答案不支持必要性时，必须冻结或删除。应用不越界管理 folder SKILL 迭代，只提供契约、情报、报告和观测；指导应发生在生成前，应用是指导者或情报提供者，不是第二作者或后处理改稿者。不必要的 20 章配对对比验证属于过度设计，禁止再引入。

- 适用范围：新功能、修复方案、验证设计、观测产品化、SKILL 协同、任何新增复杂度。
- 失效条件：永不失效。
- 来源：2026-11-03 正文层内嵌降AI V6.1 过度设计冻结；用户明确要求重视过度设计问题。

## L1 通用工程门禁

### G1.1 精准编辑与 diff 自审

禁止跨分支/worktree 整文件复制，禁止“重写整个文件顺手清理”。必须用 apply_patch 逐行编辑；提交前 `git diff` 逐行过，每行必须能归入本次目标，回答不了的行剔除或单独说明。改显示/隐藏逻辑前先确认是有意状态控制还是死代码，不确定时不动。

- 适用范围：所有源码、测试、脚本修改。
- 失效条件：永不失效。
- 来源：M2、M3、M4。

### G1.2 删除与引用闭包

删除类操作前必须对生产源码、测试脚本、历史资料三面搜索引用；引用未隔离前只关闭入口，不删实现。为兼容工具链保留的入口副本必须和生产入口同步校验；生产入口迁移后，封装脚本、构建配置、运行时引用三面同步指向新入口再删旧副本。

- 适用范围：删除函数、组件、工具、协议、入口副本、旧构建产物。
- 失效条件：永不失效。
- 来源：M5、M49、M28。

### G1.3 全局层与同款逻辑统一

改全局层级、状态折叠、终态归并、映射表时，必须审计全部入口和旁路；同一状态语义多入口出现分叉视为 P0，必须抽共享映射函数收口，禁止只修本次触发入口。UI 展示清单禁止手抄服务层注册表，必须消费单一事实源。

- 适用范围：z-index/Overlay、状态映射、清单展示、计划类变量、路由后工具面、事件同步。
- 失效条件：永不失效。
- 来源：M7、M16、M27、M35、M36。

folder 模板变量注入必须双向闭环且无条件扫描：调用方提供的变量未在模板中使用要报诊断；模板中的占位符未被调用方提供值时必须报 error 并阻止请求发出——包括调用方完全未传 `templateVariables` 的分支，禁止让字面 `{{var}}` 静默进入模型 prompt。SKILL preProcess 的链式输入残留占位符改写为可见 `[未替换占位符:var]` 标记作为纵深防御，不得依赖它替代应用侧硬闸。

- 适用范围：folder SKILL 变量注入、设置页技能测试、生成流水线四层链路。
- 失效条件：注入器架构重设计或模板引擎替换。
- 来源：2026-11-05 folder 模板占位符守卫；SKILL 层报告 `cleanChainInput` 盲区后定位到应用 `injectResolvedVariables` 反向缺口。

### G1.4 验证真实性与分层

验证报告必须分层：能力矩阵、协议仿真、mock E2E、真实供应商、真实 Electron UI、真实用户可见操作。各层只声明自己证明的范围；live 未执行只能写 `untested`。本轮缺少前置条件时只新增本轮 `untested`，禁止覆盖历史 pass 证据，并标记 `preserved` 与最近成功探针来源。

源码字符串断言只能归类为“接线守护”，不能归类为“运行时集成验证”。凡新增 prompt 注入、字段消费、候选选择类行为，验证至少要有：纯函数/组合层运行时断言，或执行器级 requestMessages/trace 断言；只读取生产源码并断言字符串存在，禁止在完成声明中冒充真实链路验证，必须登记 `untested` 边界。

协议块计数类断言必须按协议边界计数，禁止按词面出现次数计数。说明文字、错误文案、交付合同中合法提及协议名时，`split('协议名')` 会把说明当协议块，产生假失败；必须使用独立行、前后分隔符或结构化解析器作为断言口径，并在修正前先判定是测试语义误伤还是产品回归。

被测原生事件未触发时，必须登记为环境边界而不是产品缺陷或替代事件通过。原生 `unresponsive/responsive` 与应用级 `renderer_safe_mode` 属于不同观测层：前者由 Electron/平台判定，后者由应用自身监控产生。验证器必须保留原生事件真实捕获值（即使为 false），并写明 OS、DevTools 附加状态、Electron 版本、阻塞方式与时长；禁止把安全模式、`render-process-gone` 或恢复事件冒充原生事件，也禁止在未定位平台差异前把 false 误报成产品失败。

中途被压缩或交接的类型改造，禁止直接进入构建声明：必须先跑 `type-check` 并清零错误，再跑 build；一个参数从标量升级为结构体时，调用点、服务层诊断投影、trace 字段三面同批对账，禁止只改函数签名。

- 适用范围：所有验证报告、供应商矩阵、Electron 验证、发布验收。
- 失效条件：永不失效。
- 来源：M38、M47、M53、M67、M73；2026-10-26 大纲 V6.3 原生 `unresponsive/responsive` 环境边界登记。

### G1.5 验证器自身质量

验证脚本必须显式设置启动/单步超时、阶段日志和 finally 清理；挂起不算运行中。验证器修改后必须完整重跑脚本本体，禁止用局部测试、导入检查或历史产物冒充闭环。断言、采集器、证据载体必须同批升级；读不到新字段、规则收窄或 mock 序列分叉时，先判验证器口径缺口，禁止为绿灯放宽产品断言。

验证器的隔离配置目录、Electron profile、临时数据根必须在每轮启动前清理；清理只作用于隔离运行态，禁止影响真实用户数据。证据目录启动前先归档旧现场到时间戳目录，运行无论成败保留当前现场；payload、summary、trace、截图是不可再生证据，清理脚本不得越过 KEEP 开关。证据丢失时如实登记“原件未留存”和降级口径；证据复制必须做源/目标尺寸或哈希校验。

用户报告的 UI 失效必须先定位真实失效区域，禁止用相邻可用区域冒充目标区域。对用户原话中的实际控件执行真实鼠标/滚轮操作，采集几何、hit stack、overflow、事件响应与结果；注入只允许准备隔离数据与测试钩子。断言同时覆盖普通实现与阈值分支（如普通列表和虚拟列表）。带自动恢复的状态必须在同一渲染轮次内完成交互断言，负向断言至少观察一个恢复周期。

UI 控件形态迁移时，必须先对账数据模型的持久化语义；能力资格必须在 UI 选择、配置导入/保存、执行前门三面同时生效。产品 UI 的“用途”类能力必须并入既有用途栏单源入口，点击后用同一行内的下拉或选项承载细分目标；禁止为同一语义另立区块、独立按钮组或第二入口。实现与验证器都必须负向断言旧独立入口不存在，且新入口只对具备对应基础用途的条目显示。

供应商通道类验证必须同时断言 `providerId` 与 `model`，且生产 trace 事件、apiCall 记录、供应商物理请求体三面同源。验证器新增断言时，必须先跑一次确认断言在红灯路径会红，再接入绿灯路径。产品语义迁移时，验证器口径同批迁移：请求文案、外呼分支、断言值对准新语义，mock 覆盖真实链路全部外呼；请求“复合语义”或返回旧协议命令均视为造假。供应商物理请求断言必须按 HTTP method 分流：模型探测等 GET 请求不得与 POST 生成请求共用“模型必填”口径；live 辅助链关闭、目标字数缩容或 fixture 代理都必须作为显式验证通道边界写入报告，禁止用绿灯冒充完整功能闭环。

验证器不得只断言事件或字段存在，必须对账“决策值 + 消费面 + 后续物理调用”。守卫拒绝时证明昂贵外呼未被调用、旧产物未被下游消费；“先支付一次请求再拒绝”必须显式判定为产品缺陷或设计例外。观测面冻结与活性必须单源对账：不能只断言事件或快照存在，必须与生产活性字段（run 状态、physical call 最近执行活动、心跳/deadline、终态事件）同源对账。

跨模块 ID 必须先校验域（trace runId、pipeline runId、attempt ID、批次 ID 互不通用），失败诊断文件无条件写入。多目标并行验证必须把断言绑定到真实 artifact 目标，禁止跨目标比较 hash 或状态。验证器选择“被测对象”时必须绑定不可变身份键，禁止用列表顺序、显示文本、目录修改时间、最新文件名推断当前对象。

证据文件写入属于验证器外围，不得让它掩盖主结果：主断言 PASS/FAIL 必须先行打印或先行返回；证据写盘使用重试 + 时间戳兜底文件，失败只降级证据完整性，不得吞掉主结果或把主失败误报为写文件失败。

验证器的面板与选择器假设也是被测对象：切换面板前必须显式打开目标面板；selector 必须来自当前真实 DOM 结构并在失败时落盘诊断；可选控件存在才操作，不存在时走产品设计的替代路径；点击前必须确认目标可见且不被遮挡。等待/停滞检测的签名不得包含观测器自身生成的时间戳或序号；签名只能由被测业务状态组成，否则每秒心跳会持续刷新“最近活动”，把真实停滞伪装成活跃。

- 适用范围：所有 scripts/ 下的校准、评估、E2E、封装核验脚本。
- 失效条件：永不失效。
- 来源：M44、M45、M48、M53、M54、M60、M63；2026-10-16 至 2026-10-28 验证器事故族。2026-10-28 流水线流式归属验证补入“运行中反馈不可隐藏”与“面板/selector/终态控件假设必须过门禁”判则。逐事故索引见 `_audit/神意开发经验总结_v9_L3_ARCHIVE.md` 的「G1.5 来源事故索引」。

### G1.6 mock 与夹具契约

mock 必须区分场景全局计数与单轮阶段计数，场景切换与每轮发送都要重置；触发条件必须与真实请求序列对齐，禁止全局请求计数做分支开关。“请求账本 + 响应队列”式 mock 在场景重置时必须同时清空已记录请求与未消费响应队列；只清账本会让上一场景残留响应错位供给下一场景，把验证器缺陷伪装成产品断言失败。遇到“输出像上一步、账本缺失、多次验收拿到相同旧产物”时，先对账物理请求实际消费的响应预览与队列余量，确认响应归属后再决定是否修改产品；根因推翻误判后，已落地的产品补丁必须回退并完整复跑。夹具注入必须与真实 store 类型/字段逐项对账；面板空白或卡住时先收集 page error、console error 与真实 store 形状，再判产品缺陷，禁止先改产品迁就夹具。产品守卫拦截 mock 重复写时，先判定是守卫生效还是测试制造假失败。

mock 返回值本身必须通过产品守卫与结果断言双重证明：只允许提交当前协议合法的命令；结构性结果必须断言前后的真实顺序变化，禁止用“目标文本本来就存在”冒充写入成功；截断会导致 JSON 解析失败的辅助请求，mock 也必须按真实响应形状返回。

- 适用范围：所有 mock E2E、Electron 夹具、状态桥注入。
- 失效条件：永不失效。
- 来源：M40、M48、M54、M68；2026-10-30 去AI V3 Electron 验证器响应队列错位事故。

### G1.7 构建产物新鲜度

E2E、验证脚本或人工验收读取 `dist-renderer`/`dist` 前必须校验产物新于全部源码与构建配置；源码模式发现旧 bundle 直接拒绝执行并要求重建。旧 bundle 残留旧事件格式、词表或工具面时会出现“源码已修好但验证失败”的假失败，禁止用旧产物做完成声明。

- 适用范围：所有 Electron 验证、发布验收、人工实测。
- 失效条件：永不失效。
- 来源：M28。

### G1.8 日志与观测同步

任何新链路、降级、旁路、执行形态变更，runTrace 与 DiagLogger 必须同批覆盖并双侧对账。trace 是观测层：落盘失败、目录锁定、磁盘满必须记录并 fail-open，禁止观测故障冒泡成生成失败；schema 变更同步 `schemaVersion`、导出通道与旧数据兼容测试。runTrace 请求与真实 API 请求必须同源，禁止空数组、子集、旧消息源冒充；长流式 run 必须 debounce 快照与 API call 完成即落盘，崩溃前现场不得只存在于内存。trace/API call/event 三层用 `turnId + apiCallId + toolCallId` 对账，新增字段时存储类型、服务返回、入口回填、导出通道、验证器白名单同批扩展。

修复反馈类 trace 必须绑定“最终物理请求口径”：任何 pass/attempt 记录长度、上下文来源、schema 重试反馈时，取值必须来自最终发送 messages，禁止用上游 prompt 长度或首帧缓存冒充物理请求。多 pass `input=previous`、S2 瘦身、schema 裸重试属于三种容易互相误读的口径：每个请求必须能从 trace 读出 inputMode、重试轮次、system/user 实长与反馈是否存在；旧 trace 缺字段时按 `EXPECTED-FAIL` 登记为新能力边界，禁止补写历史数据。

校验失败后的任何重试不得裸重试：下一轮请求必须携带具体错误、违反项和“只输出修复结果”的约束；章节/卷纲修复请求还必须携带历史清单等禁止重复事实。续写/修复类防滚雪球只能限制“已输出回显窗口”，不得丢掉原始 system/SKILL/Agent 上下文；重试一次后仍不合格就保留可用输出并显式降级，禁止无限重试。

事件 payload 与标签同权：桥接层只允许改事件名前缀，不允许丢弃 payload；验证器必须能从 payload 读出关键字段，否则先修观测桥再判产品语义。

测试不得只打存储层或入口 helper：新增/变更的 trace 字段必须有“生产事件 → 入口回填 → 存储导出”同链路断言，至少覆盖一个成功事件与一个拒绝/失败事件；直接调用 `appendToolCall` 之类落库函数只能证明存储能力，不能证明真实事件链路闭环。

外置观测字段必须同步提供消费入口与导出可读索引：凡导出时把 `responseText` 等关键字段替换为 payload 引用，必须在主 JSON 提供可机器遍历的响应索引（含 ref、文件名、hash、长度、preview），导出清单必须校验索引与 payload 表一致。只新增外置字段而不提供消费入口，会让运行记录、验证器和 SKILL 层同时失去正文，属于观测协议断层，禁止交付。

跨 `Worker`、`postMessage`、`structuredClone`、IPC 的边界输入必须先解除响应式代理再发送：Vue/Pinia reactive proxy 会在 Worker 入口抛 `DataCloneError`，表现为按钮无反应而不是可读异常。边界服务必须提供 unwrap/cloneable 单源、处理循环引用与 Date/Map/Set、剥离 Vue 内部字段；`postMessage` 抛错要清理 pending 并返回受控错误。UI 入口必须显示导出/复制的进行中、成功、失败与取消状态，禁止把失败压缩成 console.warn 或静默 return；测试必须用 `structuredClone(message)` 钉住真实可克隆性，并覆盖 reactive 输入、timeout、`postMessage` 抛错三面。

- 适用范围：所有 AI 外呼、后台任务、工具循环、trace schema、运行日志。
- 失效条件：永不失效。
- 来源：M8、M13、M14、M19、M23、M34、M63；2026-10-26 运行记录导出按钮 Pinia proxy 触发 `DataCloneError` 的静默失效事故。

### G1.9 状态机与终态收敛

模块生命周期与资源状态必须经过状态守卫、统一收口函数或带原因的 `stateHistory`；新状态在映射表注册，禁止语义随调用方漂移。终态必须三方同步收敛：活动状态清空、UI 任务条消失、trace 保留终态事件；禁止终态兜底把终态任务重新挂回活动 UI。控制类工具必须在 handler 层校验状态，终态任务返回明确错误而不是 `ok:true`。测试必须覆盖成功、取消、失败三类终态，Electron 断言方向与单测一致。失败收口必须用 failed 语义关闭 API/物理调用；禁止把供应商失败、额度失败或运行异常用 canceled 收口，导致 UI 与 trace 把真实失败伪装成用户取消。同一入口的所有失败、取消、降级分支必须逐一对账终态函数，不允许“canceled/failed 共用同一个 cancel API”的旧实现残留。

滚动类交互必须区分“用户滚动意图”与“程序自动滚动”：scroll 容器必须真实可滚（普通列表与阈值分支如虚拟列表都要可滚），scroll 事件不冒泡，跨层监听必须用 capture；流式自动跟随必须由统一跟随状态守门，用户向上滚动后不得被 `scrollToBottom()` 抢回，滚回底部附近才恢复跟随。程序滚动写入必须节流，组件卸载必须清理 timer 与监听；禁止把“输入框可用”冒充“滚动区可操作”。

- 适用范围：任务状态机、工具循环、终态归并、恢复链路。
- 失效条件：永不失效。
- 来源：M15、M16、M22、M59；2026-10-06 R1 Phase 4 首页 failed run 被收成 canceled 的事故；2026-10-26 大纲消息区 `overflow: hidden` 加自动跟随抢滚动导致的鼠标失效事故。

### G1.10 权限与安全门

写入工具必须在服务层统一授权；入口传参不能替代权限门。工具面与权限面由最终路由/任务状态单源计算，真实 API 请求与 runTrace 共用同一份 `actualToolSurface`。服务层守卫不得为测试绿灯削弱；mock 强行调用未授权工具时，必须断言服务层拒绝且编辑器未变更。

写入授权必须由“意图 + 操作类型 + 执行计划模式”三元组单源重算；`long-document-workflow` 只能作为来源与诊断标识，禁止当成布尔旁路。任何 helper 名含 `authorization` 时必须命名真实授权决策，禁止只透传字符串标记；`discuss/analyze` 即使句中出现修改词，也不得因 workflow 标记变成 `edit`。

- 适用范围：所有写入工具、权限面、API 直写、长文档工作流。
- 失效条件：永不失效。
- 来源：M9、M19、M36、M58、M66。

### G1.11 测试契约

测试守护设计意图，禁止为绿灯固化错误契约或只测成功路径。删除/修复/新增链路时，同款逻辑在测试、脚本、规格中的旧断言同批更新；替换字段名后跑全量服务测试而非单文件。协议、游标、分页类测试必须先定语义口径再写断言；工具提示类字符串按包含校验，禁止锁定完整清单。

- 适用范围：所有测试、E2E 契约、验证脚本断言。
- 失效条件：永不失效。
- 来源：M10、M27、M64。

### G1.12 封装与工作区收尾

先核验新安装包（版本、NSIS、asar、真实启动、electronAPI、安装路径、SHA256）再删旧产物；删除后确认只剩当前版本一套。任何修改 preload/主进程 IPC 的任务，在 type-check/test/build 前先 `node --check electron/preload.js`。要消除长期脏状态，唯一安全路径是完整 commit 固化当前版本，禁止用清理未提交文件制造“干净”。收尾清理必须脚本化、带路径守卫、删除后复核并写 DEV_LOG。

删除旧产物遇 `Access is denied` 时必须先做锁定证据链：读属性、ACL、进程列表、历史会话是否出现过同文件同错误，再决定走 Move 隔离还是登记边界；禁止把单个锁定文件当成整批清理失败，也禁止绕过安全策略强删。Move 隔离目录必须先写入 `.gitignore`，防止大批量安装包意外进入 git。

发布封装前必须执行“用户可见回归面”最小矩阵：本轮触碰组件的每个历史可用用户入口至少一条真实 Electron UI 路径，并覆盖旁路能力（导出、复制、取消、恢复、滚动、弹窗、流式状态）。回归修复后的再发布同样适用，且必须追加原事故路径。发布记录必须写明回归面、证据目录与未覆盖边界；用户实测发现的新回归视为门禁失效，需按 G1.5 做引入点追账并回写本条。
- 复用产物验收或诊断函数时，调用前必须读入口真实状态机；`failed/blocked` 若已在路由层抛错，就不得为了“防线完整”伪造不能到达的测试通路；真正可达的 degraded 证据丢失和 verdict 未透传才需要修。来源：2026-11-05 工作台 blocking 补修把“假设有静默放行”反转为“路由已抛错”，随后只修真实夹缝。

- 适用范围：所有封装、发布、仓库收尾。
- 失效条件：永不失效。
- 来源：M29、M42、M43、M50；2026-10-26 3.108.0 发布验收只覆盖专项路径，导致运行记录导出与消息滚动两处历史可用入口回归穿透到用户实测。2026-11-06 收尾清理：3.110.6.exe 文件系统锁死（历史当日已存在），Move 隔离 3.114.2 系列后 dist 只留当前版本一套；文件锁边界登记台账而非强行删除。

### G1.13 Electron 验证执行标准

### G1.14 深层根因追踪

复杂问题禁止只修触发入口。动手前沿“用户入口 → 意图/任务状态 → 工具面 → 执行器 → 服务层校验 → 诊断文案 → 循环收敛 → trace → 测试契约”全链追踪，每环登记 file:line 与真实证据；任何环节仍消费旧假设、旧协议或旁路工具面即未闭环。修复后必须反查同链路其他入口与旁路；验证事件按实际执行路径归类，禁止把 final-draft、chain、compose 的证据互冒充，也不得用注入式“SKILL 已加载”冒充真实 UI 选择。

修复完成后禁止只做“改动点回归”即声称闭环，必须执行缺陷面枚举并产出清单：本次触碰模块的其余分支与状态清理点（`= null` / `delete` / `finally`）、同款逻辑的全部 sibling 调用点（写入者-读取者成对列出）、迁移协议的旧字段全仓残留（含字符串、注释、测试夹具）、链式传递字段的“谁写 / 谁读 / 丢失后果”三列对账。枚举命中项逐条登记修复或豁免理由；清单与命中处置写入台账第七节，GATE 模板无 `[DEFECT-SWEEP]` 字段或字段内容为空时视为未完成，禁止 PASS。发现式扫描依赖用户实测触发视为本条失效，必须回写事故。

- 适用范围：直写、工具循环、Agent、路由、长文档、终稿恢复类问题。
- 失效条件：永不失效。
- 来源：M74。2026-11-06 正文层断点死锁复盘：发现动作长期依赖用户实测触发，响应式修复链缺失主动枚举，四类发现式扫描（分支枚举、sibling 横扫、旧协议残留、链式字段三列对账）固化为本条强制动作。

### G1.15 系统层递进诊断

复杂症状禁止停在触发点修复。动手前必须按四层递进定位：症状层（用户看到什么）、链路层（请求从入口到写回经过哪些组件）、组件组合层（多个单看合法的组件组合后是否互相改写对方的假设、状态或预算）、机制层（保守假设、旧默认值、历史协议是否被当成执行合同）。每层必须有 file:line 或运行证据；只完成症状层诊断不得进入修复方案。

必须显式假设“正常组件组合后互相干扰”：预览状态机、模型窗口误判、预算保留区、读取上限、滚动上下文、固定工具轮次、子 Agent 控制类工具，任何单看合理的组件，组合后都可能造成伪状态、权限矛盾、任务拆分放大或假慢。判定组件存在必要性时必须同时评估：用户入口、不可替代价值、架构一致性、组合风险、修复成本与删除收益；删除过时组件是根治手段之一，不允许只为保留能力而续命。

方向性假设经常来自用户质询，而不是执行者自主发现。复盘与归档时必须保留“谁提出方向、原始问题是什么、执行者验证了什么”三段证据链；把用户提出的方向改写成执行者自主发现，属于溯源造假，后续会再次丢失高价值诊断输入。

- 适用范围：直写卡死、长文档慢、权限矛盾、工具循环、预览/确认层、供应商速度异常、跨模块状态漂移。
- 失效条件：永不失效。
- 来源：2026-10-04 预览状态机根治、2026-10-05 组件组合审计、2026-10-06 长文档干扰源审计。核心方向（预览干扰、正常组件互相打架、SKILL 之外组件干扰模型、子 Agent 是否过时）均由用户提出，执行者负责验证与展开。

### G1.16 对话因果复盘

经验回写与重大方案复盘不得从日志结论反推。归档或修订门禁前，必须先回放逐轮对话因果：用户触发原话、这轮讨论为什么发生、当时分歧或我的默认倾向、被验证的方向、执行者验证了什么、下次遇到同类问题的第一步动作。过程因果写入专用 RETROSPECTIVE 文档；经验正文只保留规则，不复制过程流水账。

复盘必须诚实标注证据边界：可恢复的原文逐字引用；不可恢复的回复只允许用“用户原话 + 当轮交付物 + DEV_LOG/方案/代码证据”重建因果，禁止冒充逐字回放。每条从复盘中提炼的规则必须能回答四问：为什么会有这轮讨论、方向由谁提出、验证证据是什么、下次第一步做什么；只写结论不写因果，视为机械复读，不得入库。

- 适用范围：经验文件回写、门禁修订、阶段性复盘、同类问题复发后的教训归档。
- 失效条件：对话原文与当轮证据均不可恢复时，允许只登记可证实的交付物事实，但必须写明“因果不可重建”，禁止编造讨论动机。
- 来源：2026-10-06 用户要求“逐轮对话原文……为什么会有这种讨论……而不是做机械式的复读和复制”；复盘见 `RETROSPECTIVE_2026-10-06_DIALOGUE_ROUND_REPLAY.md`。

### G1.17 执行者自盲区

- 执行者不得把“方案执行完成”当“问题已解决”，不得把自己的设计意图当产品证据。验证默认证伪：优先构造真实用户路径中最可能暴露失败的用例。非平凡方案在写码前必须完成作者反证：列出至少三个最可能错误的假设与真实路径证伪方式；不可验证的假设必须标注 `不可验证`，禁止默认成立。
- 自建组件不得因单点测试通过就默认正常；必须检查组合行为中 A/B 是否互相改写对方的假设、状态、预算、协议或错误处理。实现异常必须先区分“实现偏差”与“方案假设错误”；修验证器、补断言或归因环境前，先复述方案原始目标与关键假设。
- 替代证据必须声明证明边界：注入、mock、静态检查、离线基线只能证明准备环境或局部能力，不得冒充被测行为；真实用户可见行为必须用真实交互与真实请求验证。
- 持久化状态必须输出“写入 / 读取 / 清理 / 终态语义”四行生命周期对账，证明没有第二套槽位、清理与写入同键、终态后读取方拒绝旧状态。验证矩阵覆盖 `{执行模式} × {新鲜启动 / 断点恢复 / 成功终态后再次进入 / 失败终态后再次进入}`；修复、重试、续跑至少包含一条成功终态后再进入的证伪用例。
- 查账必须用“写入 / 读取 / 清理”三列对账，每列带 file:line 与槽位键，清理列能追溯到写入列同一键。契约修复先对账测量文本面与下游消费文本面；raw 与 extracted 分离时，必须构造“raw 合格、extracted 不合格”的样稿。
- 副作用断言必须先定义断言面；断点清理与 attempt 产物生命周期同步传递，成功清理不得切断后续定点复用读取。attempt 观测状态必须先对账 run/attempt 归属，至少断言写入后立即可读、新 attempt 清空旧状态、trace/export 读取同一份记录。
- 多 run 观测对象必须绑定不可变身份键，并显式声明读取最早还是最新 run；观测器变更后用“旧 run 已终态 + 新 run 已创建”组合场景重跑。验证器修复与产品修复必须分账，分别登记根因、diff 与验证。
- 负向门禁必须检查最终调用对象上相关字段物理不存在，不得只断言行为未触发；同时保留显式工具路径的前向测试，防止负向断言误伤仍需工具的链路。

- 适用范围：所有方案成熟度评估、修复验证、测试设计、组件审计、复盘总结。
- 失效条件：永不失效。
- 来源：2026-10-06 用户纠偏「根源在你为什么自己没发现问题在更深层」；五类自盲区：证明式验证、设计意图当验收标准、自建组件默认正常、替代证据顶替真实证据、确认后停止怀疑。2026-10-16 owner 断点事故补入第六类：状态生命周期盲区——改动写入槽位时未对账读取、清理与终态语义，验证矩阵未覆盖成功终态后的二次进入。2026-10-17 四漏事故补入第七类：验证器自盲区——验证脚本与断言锚点未跟随实现迁移、样稿未模拟真实职责差异、验证器自身未进入查账对象。2026-10-17 降级越权事故补入第八类：测量面盲区——caller 状态、raw 输出、extracted 消费面三者在不同组件分别判断，未先对账它们是否测量同一文本面。2026-10-22 正文 V3 契约收口补入第九类：门时序盲区——守卫逻辑正确但求值时机在昂贵外呼后，验证器未把请求次数纳入断言，导致“拒绝有效但仍多付一次请求”的缺陷长期隐形。2026-10-22 正文候选账本协议补入第十类：runId 单源盲区——attempt 观测状态的写入、清空与读取混用多个 run 标识来源，导致审计挂错 run 或永远为空。2026-10-23 Phase J 并行验证补入第十一类：观测对象盲区——多 run 场景下验证器读取最早 run，把应用正常完成的再入 run 误判为 8 分钟卡死。2026-10-26 流水线 V4 补入第十二类：断言目标盲区——多目标并行下快照缺 `target`，跨章节比较 hash 制造假失败；证据外围写入失败还可能掩盖主结果。

### G1.18 本地确定性路径的 trace 与收口契约

本地确定性执行不是模型链路的降级影子。任何本地变换路径必须同时满足三条契约：trace 中的 `turn.userRequest` 记录用户原话而非进度标签；活动执行任务在写入后的真实 `contentVersion` 与 content hash 上收口，禁止用写入前快照收口；模型路径的语义分支保持可回落且未经真实 API 验证时如实登记 `untested`，禁止用本地全零请求冒充 live 语义验证。

判定“本地已更快完成”不能只看耗时与请求数。必须逐项反查：用户原话是否仍在 trace、活动任务是否落后于编辑器版本、会话终态是否符合设计语义、验证断言是否把用户没有说的目标（如标点处理）强加给实现。测试语义错误同样属于深挖产出，不得为通过测试而改产品行为。

- 适用范围：local-transform、确定性格式化、本地重排、任何无模型请求的编辑路径及其活动任务收口。
- 失效条件：本地确定性执行架构整体替换。
- 来源：2026-10-07 长文档执行效率修复；用户确认执行并要求遇到问题按 G1.15 深挖到底。执行中发现首页 trace 原话被 `progressLabel` 覆盖、活动任务用写入前版本收口，属于“本地路径绕过了模型链路已有契约”的组合盲区。

### G1.19 耗时观测先于性能决策

性能优化禁止先凭感觉改上下文、并发、重试或模型路由。第一步必须建立只读耗时账本：物理请求数、重试请求数、物理耗时、首 token、流式输出、本地构建/校验/重试/后处理分段，且各分段边界不得重叠；分段重叠、漏记或用上游口径冒充物理口径时，账本视为失真，必须先修观测再分析。账本字段必须全部可选并兼容旧 trace，不得改变执行行为；在真实运行数据排序出 Top 耗时来源前，任何“看起来慢”不得成为优化依据。

分析阶段必须区分结论与线索：API call 总耗时减物理耗时合计只能作为本地等待候选线索，同起点的物理重试可能重复计入，禁止直接当成本地开销结论。性能优化完成后必须用同一环境、同一指标重新采账，报告 before/after 与功能等价，不得只报告主观变快。

预算与超时属于执行形态的一部分，不是通用常量。执行形态从“单次调用”升级为“逐卷四步链”“三步正文链”“含 schema retry 的链”后，验证器预算、注释与断言必须同批迁移；禁止用旧调用次数、旧措辞或旧单步预算守护新形态。健康流式任务因结构性总预算被切断时，必须先登记预算缺陷，停滞监控与死亡监控保持不变，禁止通过放宽产品断言、缩短链路或降低真实 API 强度造通过。

真实账本落地后必须做三类一致性体检：逻辑 call 时长不得小于其物理请求合计，重试后不得重置逻辑起点；有持续 heartbeat 与流式增量的物理请求被总时长超时切断时，必须把“超时策略与长生成冲突”登记为缺陷而不是把失败归因给模型；单一供应商、单次 run 的耗时分布只能作为下一阶段假设来源，不能直接推导并发或路由改动。

观测仪器自身必须在失败路径上验证：物理重试、断流恢复、无输出超时、活跃长流都要有独立测试证明账本口径和挂死保护没有把正常行为误判为失败。墙时钟总时长超时只能保护“连接与首输出前”的挂死；一旦流式增量出现，停滞判定必须交给 idle / progress watchdog，禁止用总时长切断仍在输出的长生成。编排层的 idle supervisor 必须把正文与思考增量都视为进度，否则会在模型正常输出时误判 idle。

- 适用范围：生成流水线、API 直写、长文档链路、任何以“慢/耗时/效率”为目标的行为优化。
- 失效条件：耗时观测架构整体替换。
- 来源：2026-10-12 流水线耗时账本 Phase 1；回头看发现 schemaValidate 计时起点覆盖 postProcess，证明观测口径本身必须进入回头看。Phase 2 真实 run 发现 retry 后逻辑起点重置导致负 local overhead、600 秒总时长超时切断已持续输出的长生成，以及编排器 idle supervisor 不把流式增量视为进度；Phase 3 已按 per-attempt 起点与活动信号修复。

### G1.20 预算派生与回放锚点契约

direct 写任务的工具预算、物理请求预算与验证器预算必须从同一份真实执行计划派生，而不是沿用通用常量。执行计划中的读取批数、写入批数、授权确认、定位失败重试都会改变预算形态；修改执行计划而不重算预算，属于未验证形态。验证新形态前必须先证明预算覆盖计划，再跑长链；预算不足导致的“计划要求继续、模型报轮次耗尽”是预算派生缺陷，不是模型能力缺陷，禁止通过缩减用户目标或放宽计划来通过验证。

预算实例必须单源：运行时只能存在一个 live 预算实例，编排器、对话运行时与 UI 只能透传和消费同一实例，禁止在执行中途重建第二预算。双预算的典型症状是外层按新计划放行、内层仍按旧常量切断，或 trace 中同一任务出现两套剩余额度。改动预算语义时必须审计所有消费方，防止 snapshot 预算和 live 预算并存。

历史 trace 回放必须携带协议迁移账本。旧位置型锚点只能迁移在回放器/验证器边界，禁止把兼容逻辑塞回产品层；产品必须保持新语义协议单源。回放迁移必须逐项登记旧锚点与新语义 ID 的映射，并保留负向断言：当前客户文档不得再产生旧协议锚点。历史失败在回放中转为成功时，必须同时验证新行为符合用户授权语义，而不是只看技术调用成功。

- 适用范围：API 直写、Agent 工具循环、执行计划派生、历史 trace 回放、Electron/真实 API 验证器。
- 失效条件：直写执行计划、预算实例架构或回放验证器整体替换。
- 来源：2026-10-21 大纲编辑器回头看。修复 direct 写任务预算与执行计划脱节、双预算实例，以及旧位置型 sectionId 回放锚点；三个历史 `write_only_mode` locate 失败在新语义下转为成功，删除授权被单源门拦截并得到用户确认。

### G1.21 脚本质量与生命周期

脚本本体是交付物，不是一次性手段。写前必须先查同类既有脚本；同一语义第 3 次出现时必须收敛为稳定入口并用参数承载差异，禁止继续新增版本化副本或 `tmp` 副本。多行、含嵌套引号/JSON/正则/PowerShell 变量的命令禁止 inline 执行，必须落为脚本文件后执行；文件编辑仍优先 `apply_patch`，脚本批量改写只允许在可备份或可从 git 恢复的前提下进行。

破坏性动作必须先证明可恢复，再允许执行。强杀进程、递归删除、目录改名、junction、跨盘复制、批量重命名必须在脚本内做绝对路径守卫，并具备备份或回滚路径；复制/迁移的完成条件是 SHA-256 哈希全量对账，数量比较只能作辅助。固定 sleep 不得承担同步语义，等待必须由事件、退出码、文件状态、进程状态或测试断言承担。涉及 Codex/Electron/API 流的脚本不得把“进程退出”当作资源释放或任务完成。

脚本必须有显式超时、阶段日志、非零退出码和 `finally` 清理；清理失败要显式报告。禁止 `catch {}`、`.catch(() => '')`、`SilentlyContinue` 吞掉关键失败；失败时必须输出完整错误与当前阶段。大文件输入必须流式或分块读取，禁止整读后把读取失败伪装为空数据。

验证器与审计器自身必须进入查账对象。任何验证/审计脚本必须证明：输入文件数符合预期、解析失败被计数、统计字段存在、异常缩水先判仪器再判数据；并至少有一条负向测试证明失败数据会让脚本失败。审计结果出现“大文件变成 0/空值”时，必须先检查读取失败是否被吞，再下结论。

有状态 mock 供应商和桥接脚本的 reset 必须恢复完整观测面与响应队列；场景夹具不得依赖上一场景剩余响应续跑。fixture 脚本经 Electron bridge 序列化时，正则必须使用真实字符字面量或码点语义，禁止依赖字符串级 `\\uXXXX` 转义链；夹具统计逻辑与应用计数器对账后才能进入验收断言。

临时脚本必须有生命周期：命名带 `tmp`，落位到本轮任务目录，创建时写明删除/归档条件，任务收尾必须处理；证据数据可以保留，tmp 脚本本体不得长期留存。

- 适用范围：所有验证器、审计器、迁移器、临时探针、诊断脚本、清理脚本、打包脚本，以及任何会写文件、杀进程、改目录结构或跨盘移动数据的脚本。
- 失效条件：脚本执行体系被统一脚本框架替代，且该框架已内置路径守卫、哈希对账、阶段日志、超时、finally 清理与生命周期登记。
- 来源：2026-10-29 脚本质量全量复盘（479 个物理会话文件、235 个已统计会话、449,106 次工具调用、46,679 条脚本命令、16,526 条可疑脚本事件、704 个仓库脚本）；旧审计脚本 `readFile().catch(() => '')` 吞错导致 5 个巨型会话被误报为 1 行 / 0 调用；2026-10-29 `switch-to-root-junction.ps1` 半迁移事故（强制关闭 Codex、数量比较、原目录改名、junction、无哈希对账、无回滚、无异常恢复）；2026-11-05 E2E 场景 D 先消耗场景 C 残留队列，夹具正则经 bridge 变成字面 `\u4e00` 后恒计 148 字。

### G1.22 检测/评分类校准

检测、评分、阈值与词库类改动，禁止把“测试全绿”当校准结论。必须先用真实负样本测误伤、真实或显式声明的正样本测召回，再输出分层指标；分层指标 PASS 不等于整体判定可放行。词库必须区分“报告/评分用途”与“硬规则提示用途”：全量词库包含自然语言通用词时，直接进入评分或阻断会造成系统性误伤，只能作为提示；评分与阻断只允许消费高置信子集，且子集必须用真实负样本证明误伤可接受。

整体判定的 provisional 只能由样本结构解锁，不能由单测数量解锁。移除 provisional 前必须至少具备：多来源真实负样本、真实或如实声明的正样本、按作者/题材分层的误伤与召回报告，以及每条阻断 finding 的产品预期确认。单一作者、单一题材、合成正样本下，即使四条分层放行标准全部通过，整体 verdict 也必须保持 provisional，并如实报告当前误伤率。

校准与门禁仪器改动时，先证明指标定义与分数刻度一致，再解释数据结论。blocking 要区分 verdict 口径与 finding 口径；阈值敏感度必须使用与评分输出同一刻度。校准器输出产物时，日志必须与数据通道分离；出现 0 字节或日期错位产物时，先判 UTC 命名/写入失败，再决定删除或覆盖。评分信号候选必须先做比选并同时报告负样本误伤与正样本召回，禁止只报召回增益；选择方案时不得把误伤转移到召回上来制造提升。

观测型统计不得自动升级为生成前提示注入。样本计数门槛只证明“出现过”，不证明“值得注入”；在校准 verdict 仍为 provisional/NOT READY 时，任何由统计账本派生的模型画像、规则包或词库都必须保持冻结，trace 只能记录候选与 release gate。解冻前必须有真实负样本误伤、真实正样本召回、分层指标与产品预期确认；测试必须断言冻结期 guidance 为 0，而不是只断言候选筛选正确。

- 适用范围：降AI检测、AI 痕迹评分、意图路由阈值、质量门禁、任何输出 verdict/blocking 的启发式内核。
- 失效条件：检测内核被替换为有外部基准和多作者数据集维护的成熟检测器，且误伤/召回指标由该数据集持续验证。
- 来源：2026-10-29 DEAI V2 Phase 10《踏星》200 章校准：首轮 V2 报告层复用 255 词全量 `BANNED_VOCAB`，真实人写章节 100% blocking、82.5% suspicious+；拆出高置信子集后 suspicious+ 仍 56%，四条分层放行标准 PASS 但整体判定保持 provisional。
- 补充来源：2026-11-03 V6.1 过度设计复查。模型画像原设计仅凭 `sampleCount >= 5` 注入，与校准 NOT READY 冲突；已冻结为 `released=false / calibration-not-ready`，并补 Electron/live 断言防止统计噪声进入 prompt。
- 补充来源：2026-11-03 V6.1 缺口闭环。冻结/未发布语义不得依赖“存在 eligible 规则”这类附加条件：无规则样本同样必须输出 `releaseGate`，否则后续审计无法区分“未达候选”与“旧实现漏字段”。0 finding 的检测执行也必须留观测事件，但只能标记 `injected=false`，不得为证明检测存在而注入空 prompt 或影响终态；单条样本摘录必须有独立截断上限，防止总预算内单条超长挤压其他证据。

### G1.23 契约开关四件套

对外暴露的契约开关（包括 `on/off/suffix-only` 类模式）发布前必须同时具备四件套：真实消费点、测试锚定、手册如实说明、主进程与渲染进程共享实现一致性。真实消费点必须由源码 `file:line` 证明；测试必须同时覆盖正向消费和关断行为，禁止只用“默认路径可用”冒充开关可用；手册必须写明等价模式、检测边界与预检入口，禁止承诺未落地的能力；主进程若复用渲染进程校验，构建产物路径必须可加载并有 CJS 测试锚定。

审计对手册提出质疑时，必须逐条判定“真实缺陷 / 设计边界如实披露 / 指控已过时”，禁止把全部质疑合并成一个“已修复”。修复后要反向检查测试断言在红灯路径会红，再跑绿灯路径；`null` fixture 只能证明“未声明”路径，不能冒充“声明被消费”的集成链路。

权威源迁移必须在同一批次更新对外手册与体检/预检口径：手册必须写明字段清单、合法值、最小示例与缺失后果；体检与运行时诊断必须使用同一字段名和判定口径。运行时新增 warn/error 观测时，必须反查既有外部包按旧手册交付时能否满足新口径，不能实现端收口后依赖外部协作方猜测合同。

- 适用范围：SKILL/应用契约字段、模式开关、策略投影、技能包预检、跨进程共享校验。
- 失效条件：契约被移除或替换为无模式开关的单态实现。
- 来源：2026-10-30 folder SKILL 方对 `meta.deai` 手册 8 条质疑对账：`finalStepDetection` 缺关断测试、agent 集成测试传 `null`、compose 模板丢失 `meta`、主进程 require 破洞属真实缺陷；`suffix-only` 等价语义与冲突词表边界已在手册如实披露但被误报为未实现。2026-11-01 folder SKILL `meta.json` 磁盘权威源上线未同步声明规范，导致全层 `intents/contextPolicy` 缺失 warning，补入权威源迁移条款。

### G1.24 语义域口径与测试替身

同一个指标名不得跨语义域共用测量函数。候选账本、重试反馈与最终验收都叫“净字数”时，必须先声明测量域：完整候选、剥离账本后的正文本体、JSON envelope 的 `body` 三者不可混用。数值反馈（当前值、缺口值、距离值）必须从最终消费同一测量域的函数取值，禁止在反馈层重新用另一个函数计算一遍。

生产代码新增间接 import 后，全仓模块级 mock 必须逐项对账：`vi.mock` 工厂至少提供当前调用链实际消费的全部导出；缺导出会让业务路径抛错并被 catch 块吞掉，把实现缺陷伪装成“测试失败”。数值断言禁止用 `\d+`、`\d+字` 一类通配掩盖口径漂移，应锁定精确值；测试夹具输出长度必须满足契约，禁止让执法门测试误伤无关用例。

- 适用范围：正文契约、候选比选、重试反馈、任何跨层共用的字数/长度/计数指标，以及消费这些指标的 spec 与集成测试。
- 失效条件：测量域由类型系统强制区分（完整候选与正文本体不再共享 string 类型），且模块 mock 统一由共享测试工厂生成。
- 来源：2026-10-31 正文层 SKILL 复查：`measureProtectedBodyCandidate` 与 word-gap 把【正文交接】账本计入净字数，最终验收却剥离账本；`realSkillExecutor.spec.ts` 的 aiService mock 缺 `filterThinkingTags`，3 个契约用例被误判 failed。

### G1.25 同一语义多入口与 CJS 测试替身

同一业务对象有多个入口时，禁止各入口手写记录构造或协议序列化。导入、安装、回退、重绑定、配置导出必须收敛到唯一构造器/序列化器；运行时只允许一个磁盘元数据水合源，store 快照仅用于首屏渲染。协议升级时必须把“旧版本兼容读、新版本完整往返”写成同一测试用例，并显式区分协议版本号与业务字段名，避免同一字段名承载两种语义。

CJS 模块内的 Electron API 不能靠 ESM mock registry 覆盖。测试需要控制文件系统根目录时，优先给生产模块提供显式测试钩子（例如注入库根目录），让测试走真实文件系统；禁止用更复杂的 mock 语义去“修复”CJS 与 ESM 的加载差异。二进制资源测试必须校验 ZIP 写入方法标记与实际压缩行为一致，未压缩数据必须标记 store（method 0）。

- 适用范围：多入口数据构造、配置导入导出协议、folder SKILL 运行时水合、Electron CJS 模块测试、ZIP 二进制资源。
- 失效条件：数据构造与运行时加载统一由一个领域服务承担且所有入口强制走该服务；CJS 测试体系被可拦截的模块加载器替代。
- 来源：2026-10-31 技能/智能导入链路八步收口：四处 folder 记录构造器漂移、Markdown 协议版本与 folder 版本同名字段冲突、CJS `require('electron')` 绕开 Vitest ESM mock、ZIP method=8 标记未压缩数据导致二进制保真风险。

### G1.26 守卫意图收窄与活体外契约定界

结构性测试守卫禁止按标识符名做全仓禁令。删除或新增共享状态源时，必须先复述旧禁令要防的事故意图（例如“单一活跃 run 槽位劫持”），再把禁令收窄到仍然危险的具体形态；如果新实现天然支持多 run 并发，应迁移为结构性行为断言，而不是让旧全仓禁令误伤新接线。

外部 folder SKILL 是活体契约。其模板新增必填字段导致集成测试夹具漂移时，先判定失败是应用回归还是外部契约演进：缺字段只会让集成结果从 `success` 变 `degraded`，应修夹具并登记字段演进；禁止把外部契约漂移误判成应用缺陷，也禁止为让测试变绿放松生产验收。

观测事件白名单按事件 owner 登记，不按功能页面登记。`deai-change-rate` 这类手动深修与流水线历史共用的事件，退役某个功能路径时必须全量检索其他消费方；只删除当前页面的引用会把另一条链路的观测静默清零。

- 适用范围：Phase0 并行守卫、多 run 状态源、外部 folder SKILL 集成测试、trace 事件白名单、任何新旧语义迁移。
- 失效条件：守卫由语义意图测试统一生成且外部 SKILL 契约纳入版本化兼容矩阵，事件 owner 由单一注册表声明。
- 来源：2026-11-01 V5 FINAL：`activePipelineRunIds` 误伤 A5 多 run 快照；S2 新增 `chapterIntent` 导致集成夹具漂移；`deai-change-rate` 白名单误删后被手动深修消费面复核恢复。

### G1.27 链步暂存状态与导入闭包

链式执行的暂存状态必须显式声明 owner 与存活窗口。终步、else 分支、异常恢复、attempt 重置清理状态时，必须先列出该状态的所有写入者和读取者；只有当前 owner 且已完成消费的状态才允许清理。终步清理分支不得顺手清空上游暂存状态，否则会把“下游完成”误判成“上游数据可丢”。

per-run 状态变量进入 attempt 或恢复分支前，必须建立“清空点 / 回填点 / 冷启动、定点重试、断点恢复三入口各自值”三列审计表；三入口中任一入口依赖后续执行才回填而当前入口立即消费该值时，禁止清空后等待回填。同一语义的识别逻辑必须抽为带 `source` 的共享解析器，入口测试覆盖三入口矩阵；wiring 测试只允许守护真实行为、精确断言与新语义负向形态，不得用纯 `toContain` 冒充语义测试。

维护长期累积文件（DEV_LOG 总索引、经验文件、变更日志）时，新增条目必须用追加写（`Add-Content` / `>>` / apply_patch），禁止 `Set-Content` / `>` / `w` 模式覆盖全文件；写入后必须做行数或条目数对比，发现历史内容丢失立即从 git HEAD 恢复再追加。覆盖丢失视为 P0 观测断层，历史索引是追溯依据，禁止静默重建摘要替代。

清理死亡标识符时，必须先对 import 块内每个成员做消费点扫描，再决定删除范围；禁止按“附近都是死的”扩大删除。类型导入被函数签名、局部变量声明或泛型约束消费时，即使值成员已死，类型成员也必须保留。清理后必须跑类型检查，禁止只依赖定向测试。

空集合默认值禁止依赖 `arr.map(...) || fallback`。`[].map()` 返回空数组，是 truthy，`||` 分支永不生效；必须用 `arr.length ? arr.map(...) : fallback`。同类陷阱包括 `filter().map() || fallback`、`String.prototype.match()` 为 null 时的反向误用、以及 `.length || fallback` 把合法 0 当缺失。

UI 或报告类验证器的断言必须覆盖数值本身（如 `S2诊断：3条`、`变体: methodology, creative, polish`），禁止只断言文件存在、按钮可点、导出成功。导出成功只能证明通道可用，不能证明内容正确；数值断言必须与 trace 结构化字段同源对账。

- 适用范围：链式执行、per-run 状态、attempt 生命周期、导入清理、报告/观测产物、Electron UI E2E。
- 失效条件：暂存状态由状态机框架统一管理且 owner/存活窗口由类型强制声明；报告内容由 schema 级快照测试自动锁定。
- 来源：2026-11-03 V6.1 Phase B/C 回头看：S3 终步清理误清 S2 诊断；死亡变量清理误删 `type DeaiStageDiagnosis` 导入；报告空数组默认值依赖 `||`；E2E 初版只验按钮与文件存在，未验报告数值。2026-11-06 正文层断点恢复：attempt 清空 `bodyGeneratorStepIndex` 后等待执行回填，S3 直跑立即消费导致 `generator_not_identified`；同批升级为 `resolveAttemptStartGeneratorIndex` 三入口单源与行为测试。同日收尾发现 `DEV_LOG_MASTER_INDEX.md` 被覆盖写入删掉约 1390 行历史，git HEAD 恢复后追加登记。

## L2 领域门禁

### G2.1 工具循环与救场请求

工具循环状态必须区分 reading、locating、write_pending、write_success、write_failed、permission_denied、write_limit、tool_missing、no_progress、loop_limit，禁止把连续无正文折叠成“正在查找信息”。循环上限由 `toolLoopPolicy` 按场景单源声明，调用方只能向下钳制；新场景必须先声明 `scenario`。救场/收敛请求不得继承原请求的外层 `signal` 与 `timeoutMs`。同一迭代内并行工具失败只计一次，跨连续迭代达到阈值才中止；失败统计必须携带 `scope`。

- 适用范围：API 直写、Agent 工具循环、folder SKILL、救场请求。
- 失效条件：工具循环架构整体替换。
- 来源：M22、M25、M39、M77。

### G2.2 工具协议与执行器

适配层输出给工具执行器的对象必须与 `inputSchema` 逐字段一致；内部存储字段不得混入工具入参，可选字段缺省必须物理删除而不是置 `undefined`。收紧 schema 前先盘点既有解析器输出形状，并用真实兼容路径回归。结构级全文重排必须收敛为单条 `reorder_sections` 原子命令；混批、非 reorder 命令、无效 `order` 返回协议错误，禁止多条 `move` 拼接造成半应用状态。

- 适用范围：原生 tool call、JSON 兼容协议、供应商降级协议、长文档重排。
- 失效条件：协议层整体重构。
- 来源：M37、M79。

### G2.3 意图路由与语料

意图语义必须由 `classifyChainIntent()` 与 `routeChainIntent()` 共享单源；权限问句不得短路终判，命中权限问句后必须二次判定句内是否含祈使或试探写入。语料集单源驱动，补正样本必须同步补负样本、位置咨询样本与短答复承接样本。阈值、margin、OOS 判定由校准脚本输出完整指标，以写入误触发为硬约束；阈值只在 dev 集选择，test 集只做最终报告，禁止为降误拒放宽写入安全阈值。扩库种子物理隔离在 factory-only 数据源，永不进入 train/dev/test。`no_match` 与 `ambiguous` 是两类输入，兜底策略分别断言，禁止共用同一气泡/继续请求断言。

- 适用范围：意图路由、路由校准、语料工厂、fallback 气泡。
- 失效条件：路由架构整体替换。
- 来源：M11、M21、M46、M51、M52、M55、M56、M57。

### G2.4 API 直写与 EditTask

权限面与任务状态机归一联动，禁止用“是否传入 task 对象”推断写权限；终态后必须移除 task 控件并恢复普通工具面。长文档工作流授权同时贯通工具面 `writeAuthorization` 与服务层 `evaluateWritePermission`，主页与大纲工作台双入口走同一单源。直写/长文档策略/EditTask/工具面任一变更，必须回归路由正负样本；结构性范围词（第N章/节/段/卷、首尾/全文）与名词目标等价参与 edit 计分。API 对话框滚动状态只显示连接、流式字数、重试与终态；工具名、入参、JSON、结果只进 RunTrace 与 `tool-activity` 编辑器联动，公共出口统一过滤。

- 适用范围：API 直写、EditTask、长文档工作流、API 对话框 UI。
- 失效条件：直写交互形态整体重构。
- 来源：M40、M58、M65、M66、M72。

### G2.5 长文档重排与完整性

整篇替换的完整性校验不得把容器标题 body 当独立小节正文比较；只收集叶子/非容器节点正文，容器节点至多校验自身直接引言，并保留“真实重排通过”与“真实删节仍阻断”两向证据。真实长文档工具循环单轮可达 15-20 分钟，验证步进超时不得低于 30 分钟且可环境变量覆盖；超时先判脚本口径，再判应用卡死。结论区分“完全一致复刻”与“起点/终点对齐复刻”，路由差异、授权后语义残留、看门狗告警不得被验收绿灯吞掉。

多段写入任务的完成判定必须基于“可信覆盖记录”，禁止用成功调用次数、批次 ID 推断或模型自述充当完成。可信覆盖必须同时具备：计划 `segmentId` 绑定、真实命令范围与 segment 相交、执行后 `documentVersion/contentHash` 证据；未绑定 segment 的写入允许执行但不得计覆盖，错误 segment 或范围不符必须进入 invalid records。Agent 与 steering 共用同一覆盖摘要，不允许新旧两套完成判定并存。测试夹具必须先证明计划确实是多段，短文档在小上下文预算下可能只切出单段，导致“多段断言”实际在验证单段语义。

- 适用范围：10万字以上大纲重排、S200/S1M 验证、长文档工具循环。
- 失效条件：长文档架构整体替换。
- 来源：M62、M78、M79、2026-10-05 partial-write 假完成收口。

### G2.6 编辑器

textarea 原生 selection 永远只承载 primary，其余光标是虚拟选区集合；offset 先经行索引/虚拟化映射，禁止直接用 DOM range。外部/API 写入期间降级单主光标，用 `documentVersion` 冲突检测拒绝并发多光标命令；IME 组合期间锁多光标编辑。交互态溢出扫描必须读取真实 used geometry（含伪元素），区分真实文本宽度与伪元素贡献；两侧放不下自然宽度时选择空间更大一侧并收窄。

- 适用范围：编辑器光标、多光标、API 写入联动、tooltip/溢出验证。
- 失效条件：编辑器底座整体替换。
- 来源：M60、M69。

### G2.7 上下文与预算

上下文压缩只认模型输入窗口，未知窗口必须跳过并留痕，禁止把输出 `maxTokens` 冒充输入窗口；多 workspace 分桶路由，禁止全局 budget 互相覆盖。折叠历史消息必须按 retained 消息稳定身份反推折叠集合，禁止用过滤后下标切原始数组；`MAX_STORED_MESSAGES` 截断不得移除最新 marker。压缩预算 `reservedOutputTokens` 来自本轮真实请求最终 maxTokens（含重试/降级后的有效值），经 apiMeta/meta 显式传递，缺省才回落 workspace 路由桶；folder、text、direct、成功轮、失败轮各自有独立接线与回归。

- 适用范围：上下文压缩、会话折叠、预算接线、多 workspace。
- 失效条件：上下文治理架构整体替换。
- 来源：M30、M31、M33。

### G2.8 存储与写队列

会话追加/折叠/清空类写操作必须在项目级写队列临界区内读取最新 state 后修改并落盘；禁止队列外先读快照、队列内再合并旧快照，必须补并发追加回归。storage 导入采用临时文件 + 备份 + 原子替换，并按 key 进入与 `storage:write` 相同写队列；导入绕开队列会与自动保存竞态覆盖。持久化函数只负责写盘，禁止重新赋值整个响应式 config。

- 适用范围：会话存储、storage 导入、配置持久化。
- 失效条件：存储架构整体替换。
- 来源：M32、§1 通用规则 6、§1 通用规则 10。

### G2.9 终稿与流水线

- 每层进度反馈绑定独立 step 与独立日志数组，禁止跨层泄漏；UI 有配置入口不等于链路接入，必须追到真实 API 调用点。计划卷数、已生成卷数、当前卷预算由统一计划服务计算，single、continue、auto、prompt 构建与模板上下文全部消费同一结果。
- 终稿任务跨中断/重试传递前先做纯数据快照，禁止对 Pinia reactive proxy 使用 `structuredClone()`；慢流已有输出后不得再触发物理重连；活动 API 记录按 call-id 匹配关闭；分段回放 mock 精确分段块优先，验证器与生产 normalize 同源。
- 显式整篇交付语义优先于“整理排序 / 统一格式”词法；约束性否定不得推翻显式交付请求。意图路由与执行计划是两层语义，修任一层后必须重跑既有成功验收场景。
- 正文修复按 `none / targeted / full_chain` 三态收敛：非空草稿先定点修复，full_chain 只允许一次兜底，之后进入失败终态。每次模型尝试、hard signal 与 DeAI 后处理写入同一 attempt 台账；trace 只保存结构化摘要与有界预览。
- chain 断点按 owner 隔离，章节批次共享槽是唯一显式例外；生成中锁住目标选择、编辑与删除入口。每个 owner 写入点存在同 owner 成功清理路径；“已完成链”断点不得作为恢复点消费旧产物；每次修复 attempt 记录请求指纹，零物理请求却产生新验收结果是执行缺陷。
- targeted 修复复用同一 attempt 生命周期内的上游产物；链成功清理断点前把 completed step outputs 回传 attempt 闭包。attempt 产物缺失时显式降级整链并写 `body-targeted-repair-artifact-missing`，禁止静默把定点修复降级成整链重跑。
- caller 状态与产物契约分权：`degraded` 只描述执行器状态，不授予产物越过契约门的权限。唯一生成步消费前统一验收下游真实消费的提取面；`degraded + 契约失败` 阻断，`degraded + 契约通过` 才允许继续；无契约复合 SKILL 显式登记 `no_contract`，禁止静默放行。
- 双层验收按维度单一裁判：叙事有效性归 SKILL，平台合同归应用。应用只消费 SKILL 显式机器可读 verdict，不得从正文推导叙事质量；`not_ready` 路由回上游，合同失败才进入应用修复编排。同一字段两层都能判失败时，先登记 owner 并退役另一侧语义。
- 测试边界必须覆盖双层裁决的全部真值组合：`degraded + SKILL blocking fail + 应用契约通过` 是最危险的夹缝区间，修复闸只测"自己定义的失败"而漏测"上游 SKILL 定义的失败"，等于没测裁判权交接线。构造用例时枚举 caller 状态 × SKILL blocking verdict × 应用契约 verdict 的完整矩阵，禁止只取事故复现的单点。来源：2026-11-05 S2 三次 blocking 耗尽 3150 字 > 2800 被验收放行，run 标 success。
- warning-only 降级不能静默：SKILL verdict 通过但保留 warning 时，executor 标 `degraded`，流水线事件与步骤日志必须携带机器可读错误/警告清单；UI 不得只显示成功而不提示降级来源。blocking 失败与 warning-only 用真实 UI E2E 分开验证，禁止用同一夹具混测两种语义。
- 剧情释放语义由 SKILL verdict 单通道裁决：应用只解析显式 `contractStatus` 与 `contractReason`，未声明即 `undeclared`；禁止本地揭示词表、窗口共现推断或旧三态。结构合同校验使用 `Structure` 命名；生产调用为 0 的旧导入口同步删除源码、import 与测试。
- 唯一生成步识别覆盖多步 chain 与无 SKILL/compose 单次调用；显式区分 `null` 与 `0`，禁止隐式转换或把多步链口径写成全局假设。compose 契约失败把修复决策权交回编排器，不得在无下游链步位置直接抛错。
- 终步角色与终步反馈单源化：从 step 语义、模板声明或 SKILL 角色显式推断，推断失败产出 warning；终步 retry 反馈由单源函数组装，携带失败指标、命中片段与必要上游输入，禁止回传上一版候选全文。metadata 按受控摘要流转；缺字段走结构化修复，语义漂移只 warning，禁止自动改写事实。
- 重试候选进入 per-attempt 候选账本，记录候选、valid、错误清单与 attempt 序号；耗尽时按 valid 优先、错误更少优先、早 attempt 优先保留，并写入 `retainedCandidateIndex`。反馈绑定当前候选，可回传失败指标与确定性片段；质量/风格类失败禁止候选全文与模块级旧候选，结构/格式/字数类失败必须携带完整候选作为定点修复基础（G0.13 收窄语义，来源 2026-11-06 candidate-anchored）。反馈审计随 attempt 清空并随 trace 导出。
- SKILL 运行基准钉死必须在每个 attempt 开始时复查且失败先于物理调用；禁止 probe 指纹只记录不执法。运行中途磁盘包变更必须显式 failed 并留 trace 事件，禁止 TTL cache 静默采用新包。composite 链剥离 pin 让子 folder 独立指纹。来源：2026-11-06 folder-skill-version-mismatch 防护。
- 工作台、复合链或历史编排器消费 folder 产物时，`blockingGateFailed` 与 blocking postProcess issue 是同一裁决的结构化证据，必须透传到 run meta、产物验收和终态归并；`failed/blocked` 抛错不能替代 `degraded + blocking` 的二级防线。来源：2026-11-05 工作台审计。

- 适用范围：生成流水线、卷纲、终稿分段、停滞恢复。
- 失效条件：流水线/终稿架构整体替换。
- 来源：M80、M35、§8 规则 42、§8 规则 94；2026-10-16 正文修复台账与断点 owner 隔离；2026-10-17 断点清理与 attempt 产物生命周期错位事故；2026-10-17 正文层降级越权事故；2026-10-17 无 SKILL compose 单调用回归事故；2026-10-19 终步元数据保真与终步反馈复述事故；2026-10-22 正文候选账本与修复反馈协议；2026-10-31 双层验收边界收口；2026-10-31 卷契约语义观测退役与结构校验命名收口；2026-11-05 SKILL blocking 夹缝区间验收放行事故。

### G2.10 真实 trace 回放

直写/Agent/工具循环改动必须用最近客户 run-trace 复刻回放，读取真实 `run-trace.json` 与外置 `payloads/` 载荷，禁用摘要、README 或自造序列冒充客户现场。回放保留原始调用顺序、失败码与耗尽路径；旧失败码对应已修复历史缺陷时必须做双语义断言：旧 trace 期望 `failed + 旧错误码`，当前实际执行断言 `success`，差异写入 result.json 显式字段，禁止恢复历史缺陷让复刻变绿。

- 适用范围：客户问题复现、直写/Agent 回归、历史缺陷对账。
- 失效条件：永不失效。
- 来源：M75、M76。

### G2.11 供应商与网络

供应商能力矩阵、协议仿真、mock E2E、真实供应商四层独立报告；网关差异（如函数名带点被拒）登记为能力事实，不伪装成应用缺陷。API key 只能经环境变量临时传入，禁止写进仓库、日志、脚本或证据文件。浏览器入口 re-export 的传递依赖必须真实安装。开发态调试装包依赖且怀疑预构建缓存陈旧时，重启 Vite dev server；该动作不是发布验收的必经步骤。

HTTP 状态码不是业务成功语义。供应商可能用 HTTP 200、SSE data 或纯文本返回额度耗尽、余额不足、套餐过期等软错误；所有外呼分支必须先按响应正文/协议错误做业务终态判定，命中额度类软错误时转 `quota_exhausted` 终态并停止续发请求，禁止把通知文本当正文、工具结果或降级文案继续消费。测试必须覆盖纯文本、SSE 与正文/小说中自然出现额度词三种形态，并断言不会产生第二次物理请求。

- 适用范围：供应商接入、协议适配、网络桥、依赖变更。
- 失效条件：永不失效。
- 来源：M38、§1 通用规则 12；2026-10-06 R1 Phase 4 HTTP 200 纯文本 Coding Plan 额度通知事故。

### G2.12 窗口与进程

窗口状态防抖且退出立即落盘：resize/move 走 500ms debounce，close/before-quit 清 pending timer 后同步保存。utilityProcess worker 内用 `process.parentPort` 通信，不假设 `ipcRenderer` 或父级全局回调；第三方 SKILL 脚本持续隔离，blocked 尝试后同一 worker 继续服务。

- 适用范围：Electron 主进程、worker、窗口生命周期。
- 失效条件：Electron 架构整体替换。
- 来源：§1 通用规则 8、§1 通用规则 9。

### G2.13 SKILL 执行中立

SKILL guidance 只允许改变提示词、领域能力与上下文组织；禁止改变应用执行协议、权限语义、runtime 路由、长文档路由、工具面、写回协议和 trace 字段。有 SKILL 与无 SKILL 必须消费同一执行方案，差异只允许体现在 guidance 与领域能力上。

compose、chain、final-draft 按路径语义分别接线：compose 统一走 Agent runtime 并注入 guidance；chain 保留流水线执行；final-draft 保留终稿 wiring。验证 guidance 是否注入时，必须对实际请求与 trace 的事件归属做同路径对账；guidance 缺失时先判执行路径是否走旧引擎，再判构建函数是否失效，禁止只修注入函数而不查执行入口。禁止用注入式“SKILL 已加载”冒充真实 UI 选择。

SKILL 中立验收矩阵：权限、工具面、写入执行三类断言都必须双态运行——无 SKILL 与真实 UI 选择 SKILL 各一轮；两态期望值必须完全一致，唯一允许差异是 guidance 是否注入。空 guidance 事件必须显式 `skillGuidancePresent: false`，禁止显示“SKILL 已接入”。

folder guidance 取数必须覆盖导入形态：真实导入的 folder 技能在 store 中没有 `systemPrompt`，领域能力保存在 `template.md`。构建 guidance 时必须按“显式 systemPrompt → folder template.md → description”取值；验证夹具不得把 folder 技能 seed 成 `markdown`，否则会把 folder 路径静默降级为模板路径。

未来任何跨轮确认必须三元绑定：`toolCallId` 或批次 ID、工具名、参数 canonical hash；任一不一致即拒绝执行。确认语义不得回退为“按文本相似确认”，也不得新增默认确认层改变无 SKILL / 有 SKILL 的同一执行方案。

- 适用范围：SKILL 接入、compose 对话、Agent runtime、guidance 构建、执行路径迁移。
- 失效条件：SKILL 与应用执行协议整体重新设计。
- 来源：2026-10-01 SKILL / 无 SKILL 统一；2026-10-03 Phase 7-A3；2026-10-04 R1-R5 加固实测。

### G2.14 默认存储位置与跨盘迁移

默认数据根必须单源化：主数据、Electron `userData`、legacy 目录共用 `electron/defaultPaths.js`，禁止生产入口硬编码用户目录。启动早期设置 `userData` 前禁止调用 `app.getPath('userData')`，因为 Electron 会以读取默认值为副作用重建 `%APPDATA%\<app>` 空目录；fallback 路径应从环境变量推导。迁移必须按“哈希全量对账 -> 删除源 -> 启动后复核源不重建”执行，运行态缓存差异走白名单豁免，业务数据零差异才允许删除源。删除源后必须用真实安装版启动回归，证明数据读取只落新盘且退出无残留进程。

- 适用范围：Electron 存储默认值、跨盘迁移、安装器文案、诊断与验证脚本路径。
- 失效条件：应用整体迁移到非 Electron 架构或存储根改由用户级配置中心统一管理。
- 来源：2026-10-28 C 盘满载后的数据根迁移；启动空目录复发定位到 `app.getPath('userData')` 副作用。

## 使用路由

1. 任何任务开始前：读 G0 全部 + 最新 DEV_LOG 相关条目。
2. 新功能、修复方案、验证设计、观测产品化或 SKILL 协同：先执行 G0.13 最小必要性五问；答案不支持必要性时冻结或删除，不得进入方案。
3. 修改代码/脚本：加读 G1 相关条目；涉及测试、验证、封装时分别加读 G1.4-G1.13；多入口数据构造、配置协议、CJS 测试或二进制导入导出时加读 G1.25；清理死亡代码、链步暂存状态或报告产物时加读 G1.27。
4. 按触碰系统加读 L2：直写 G2.1-G2.4；长文档 G2.5；编辑器 G2.6；上下文 G2.7；存储 G2.8；流水线/终稿 G2.9；客户问题 G2.10；供应商 G2.11；窗口/进程 G2.12；SKILL/runtime G2.13；默认存储/跨盘迁移 G2.14。
5. 复杂症状、性能异常、权限矛盾、长文档问题：加读 G1.15，必须完成症状、链路、组合、机制四层定位后再出修复方案。
6. 方案输出前：执行 G0.6，给出成熟度结论；执行 G0.7，列出正反推证据。
7. 收尾前：执行 G0.5、G0.8、G0.10；写 DEV_LOG；提交后确认工作区干净。
8. 经验回写或复盘总结：加读 G1.16，先回放逐轮对话因果，再提炼规则；过程因果写入 RETROSPECTIVE 文档，正文只保留规则。
9. 方案确认后与写码前：加读 G1.17，完成作者反证；验证设计必须包含至少一条真实用户路径的证伪尝试，替代证据必须声明边界。
10. local-transform 或任何无模型请求编辑路径：加读 G1.18，验证用户原话 trace、写入后版本收口、语义回落边界三项契约。
11. 非平凡任务开始时：执行 G0.12，先建任务台账七节骨架；收尾时逐节补证据并回头看，无台账不得声称完成。
12. 任何脚本编写、临时脚本、验证器、审计器、迁移器、诊断或清理脚本：先读 G1.21；执行前完成路径守卫、恢复路径与数据规模评估，收尾时处理临时脚本生命周期。
13. 检测、评分、阈值、词库或 verdict 逻辑：先读 G1.22；改动前后必须跑真实负样本误伤与正样本召回，分层指标与整体判定分开报告，provisional 只能按样本结构解除。
14. 检测/评分任务的校准器、分析器或门禁脚本自身有改动时：先判仪器口径与产物通道，再做评分或数据结论；候选比选必须同时报误伤与召回。
