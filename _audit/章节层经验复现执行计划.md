### 必须先懂的三条结构事实

1. `stepSkillSelect[4]`、`stepAgents[3]`、`stepSkillModes[3]`、`stepSkills[3]` 表面上 key 不同，但 `addStepSkill()` / `removeStepSkill()` 内部使用 `step - 1` 把用户层选择映射到内部 0-based 存储。禁止为了“数字一致”把它改坏。
2. 章节层只应显示当前卷下 `pipelineGenerated === true` 的章节；底层可能还保留未生成的旧数据，不要清空或覆盖。
3. 只有 `vol.isBound === true` 的卷能进入章节工作区；这是卷纲层到章节层的锁定契约，不能放宽。

## 2. 铁律

1. 中文回复；每轮首行带 `[Objective: ...]`。
2. 不设 token 预算，不做算力节省式偷工。
3. 一次只修一个闭环；禁止批量重排无关 UI。
4. 行为等价优先：改 UI 不改业务语义、数据结构、生成链路、锁定规则、断点逻辑。
5. 每个阶段：精准修改 → `npx vite build` → 杀干净 Electron → `start-electron.bat` → CDP 真实操作 → DOM / 状态 / 持久化递归验证 → 截图和日志。

7. 未完成真实行为验证，不得勾选完成。
8. 临时数据必须可恢复；不允许污染真实项目。
9. 每阶段记录到本文件或独立结果 JSON：问题、根因、修改文件、用户操作、预期结果、实际结果、证据路径。
10. 阶段收尾后更新经验文件和 `DEV_LOG.md`；全部完成后提交并推送 GitHub。
11. 最终收尾只保留 DEV_LOG 和经验文件核心更新；清理 `_audit/tmp/`、临时脚本、临时截图、临时 JSON。

## 4. 经验复现清单

1. **设定层分类单行 / 四列小卡片**：只复用“控制区收敛、网格密度、状态颜色、弹窗详情”的方法，不复用卡片样式到章节表格。
2. **卷纲层生成弹窗**：复用居中 overlay、进度条、滚动日志、取消生成和终态反馈。
3. **卷纲层配色统一**：使用语义 token；不批量替换所有颜色；隐藏 DOM 不算运行时证据。
4. **章节层现有生成逻辑**：保留断点、重试、去重、校验和 `chapterExecutionPackage`。
5. **CDP 验证经验**：入口要稳定；toggle 要先判断当前状态；脚本必须显式退出；原生对话框证据要分层；临时数据必须恢复。
6. **工作区清理经验**：任务开始前清旧遗留，任务结束后清本轮临时产物；DEV_LOG 和经验文件核心更新保留。
