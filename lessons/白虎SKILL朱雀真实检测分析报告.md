## 三、核心问题诊断

### 问题1：白虎单独对朱雀真实检测完全无效

白虎改了34.3%的段落，句长变异系数从43.2%提升到61.3%，极短句从1个增到8个，最长句从61字扩到106字。

这些量化指标确实改善了。但朱雀真实检测仍判100% AI，置信度71.7%（甚至比原文的71.4%还高了一点点）。

原因分析：
朱雀检测的不是句长分布、极短句数量这些表层统计。它检测的是token序列的深层统计特征——词汇选择模式、句法结构深度、token转移概率分布。白虎的改动全部停留在表层（拆句子、合句子、换语序），没有触及深层。

### 问题2：65.7%的文本完全未改动

白虎只改了12/35段（34.3%），其余23段是原文一字不动。

朱雀看的是整篇文章的语言规律。65.7%的文本是纯AI生成文本，这个比例足以让朱雀判定全文为AI。

即使改动的12段中，白虎的改动方式也有固定模式（见问题3），可能被检测器识别为"修改痕迹"。

### 问题3：改动模式单一化

白虎的12个改动段落，改动类型高度集中：

- 拆碎长句制造短句：段3/6/8/20/30/33/35 = 7段（58%）
- 合并短句制造长句：段13/18 = 2段（17%）
- 信息重排：段24 = 1段（8%）
- 微调（几乎没变）：段27/32 = 2段（17%）

58%的改动都是"拆碎长句"——把一个长句拆成几个短句。这种统一的改动模式本身就是一种可检测的特征。如果朱雀能检测"这段文本被系统性拆碎过"，那白虎的改动反而增加了可检测性。

### 问题4：极短句制造方式有规律

白虎制造的8个极短句（<=5字）：
- "金属味。"（3字）
- "声响。"（2字）
- "走廊尽头。"（4字）
- "弯腰。"（2字）
- "钻过缝隙。"（4字）
- "深吸了一口气。"（6字，边界）
- 等

这些极短句都是"名词+句号"或"动词+句号"的固定结构。人类写作中的极短句更多样化——有时是感叹、有时是断句、有时是碎片化意识。白虎的极短句模式太统一了。

### 问题5：段35过度删减

段35：172字->106字（-66字，仅保留61.6%）。这一段的删减幅度过大，可能丢失了原文的叙事节奏和情感铺垫。

### 问题6：与硬规则V54的配合

白虎->V54的测试结果（54.6%）比V54单独（56.9%）好2.3个百分点。说明白虎的改动确实有额外贡献。

但V54的mergeShortSentences会合并白虎制造的25字以下极短句，部分抵消了白虎的重尾分布效果。正确顺序应该是V54先跑完->白虎后跑，这样白虎创造的极短句不会被V54碰到。

## 四、白虎当前能力边界

### 能做到的
1. 诊断AI分布特征（S1八维度扫描）
2. 段落级重写（S2八种模式）
3. 制造重尾分布（变异系数43.2%->61.3%）
4. 制造极端值（极短句1->8个，最长句61->106字）
5. 信息基本完整（15/16关键信息点保留）
6. 修改密度控制（34.3%，低于40%上限）
7. 叠加V54后有2.3pp额外贡献

### 做不到的
1. 降低朱雀真实AI率（100%->100%，零效果）
2. 改变token序列的深层统计特征
3. 覆盖未标记段落（65.7%文本不变）
4. 制造多样化的极短句（模式单一）
5. 制造不可检测的修改痕迹（改动模式58%都是拆碎）
6. 与V54正序配合（V54的mergeShortSentences会破坏白虎的极短句）

## 五、优化建议

### P0：解决"65.7%文本未改动"问题

当前标记密度34.3%是基于V53的"删除甜点33%"经验。但V53的33%是在"删除"操作下验证的，白虎的"重写"操作性质不同——重写改变的信息更多，痕迹更明显，可能需要更高的密度才能有效。

建议：测试标记密度从34.3%提高到50-60%的效果。如果朱雀仍判100%，说明问题不在密度而在深层特征。

### P1：改动模式多样化

当前58%的改动是"拆碎长句"。建议增加：
1. 词汇替换（不是删词，是把AI偏好词换成更具体的词）
2. 句法结构变化（不只是拆/合，改变句子内部结构）
3. 叙事视角微调（在同一POV内改变叙事距离）
4. 节奏注入方式多样化（不只有极短句，还有节奏停顿、段落呼吸等）

### P2：极短句多样化

当前极短句都是"名词/动词+句号"。建议：
1. 感叹式："不对。"
2. 碎片式意识："该走了……"
3. 动作反应："手停了。"
4. 环境碎片："风停了。"
5. 对话碎片："'走。'"

### P3：深层特征触及

白虎目前只改表层（句长、段落结构）。要降低真实AI率，需要触及：
1. 词汇多样性（AI偏好某些词汇组合）
2. 句法树深度（AI句法结构较浅）
3. 过渡方式（AI有固定过渡模式）
4. token转移概率（需要通过完全不同的表述方式来改变）

建议：S2增加一个"完全换说法"模式——不拆不合，用完全不同的词语和句式重新表达同一段的信息。这才是"整段重写"的真正含义。

### P4：与V54的协调机制

建议白虎输出后，V54只跑安全网规则（句首代词删除、套话替换等），跳过mergeShortSentences和mergeShortParagraphs。

或者在应用层面实现：V54先跑（安全网+结构修改）->白虎S1-S2-S3（在V54清理后的文本上重写）->白虎输出即最终输出（不再跑V54）。

## 六、朱雀检测逻辑推测

基于V54的测试数据（V54能把AI率从100%降到56.9%），朱雀检测器可能关注以下特征：

V54做了什么而白虎没做的：
1. 句首代词删除（"他"删除）- 改变了句首token分布
2. 短句合并 - 改变了句子边界token分布
3. 套话替换 - 改变了词汇选择
4. 连接词替换 - 改变了过渡方式
5. 感官压缩 - 改变了信息密度
6. 中转词删除 - 改变了叙事距离

V54有效而白虎无效，可能说明：
- 朱雀更关注"词汇层面"和"token层面"的改变，而非"句子结构层面"
- 删除句首"他"这种小改动，可能比拆碎一个长句更有效——因为它改变了token序列的起始模式
- 合并短句可能比拆碎长句更有效——因为它改变了句子边界分布

## 七、测试方法说明

### 测试文本
3500字科幻小说正文，35段，苏铭/观测站/叶澜失踪故事。

### 朱雀检测
真实API调用，端口9224守护进程。每次提交文本，等待45-90秒获取结果。
AI率 = 被判为AI的段落数 / 总段落数。

### 白虎执行
S1分布诊断师 -> 输出JSON策略
S2重写执行师 -> 按策略重写标记段落
S3完整性校验师 -> 校验通过后输出S2文本

### V54硬规则
修复版（段落bug已修）。process()函数执行17条规则（12条安全网+5条结构修改）。
