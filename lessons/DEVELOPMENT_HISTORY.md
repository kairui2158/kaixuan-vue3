# 第一章: 项目起源与核心架构

## 1.1 用户的愿景

用户凯瑞想做一个AI驱动的桌面小说写作应用，核心理念是：
- API = 大脑 (提供逻辑推理能力，调用大语言模型)
- Agent = 身体 (协调全局行为，注入systemPrompt和模型配置)
- Skill = 四肢 (执行具体写作任务，template追加到prompt)

三者的协同关系：用户在设置里配置API供应商和模型、添加Agent和Skill，然后在生成流水线里把Agent和Skill绑定到每个步骤，AI根据大纲递归生成设定、卷纲、章节、正文。

## 1.2 参考项目

用户提供了 sunflower816.writerhelper-1.6.5.vsix 作为参考，我分析了其15层架构，提取了42项可移植功能清单。但用户明确要求"按照我们的想法来"，不照搬。

## 1.3 技术选型

用户要求纯HTML5+CSS3+JavaScript ES6+，不使用任何前端框架。原因：
- 降低打包体积
- 避免框架学习成本
- 保持单文件可运行
- 便于AI直接修改

存储用IndexedDB（通过Electron的file storage后端持久化到本地文件）。

## 1.4 核心功能链路

大纲编辑器(导入/AI共创) -> 设定合集(角色/世界观/物种/物资) -> 生成流水线(大纲确认->设定->卷纲->章节->正文) -> 编辑器(正文写作)

每一步都可以绑定Agent和Skill，Agent注入模型配置和systemPrompt，Skill的template追加到用户prompt后面。

# 第三章: 应用当前架构

## 3.1 文件结构

main.js                    # Electron主进程(GPU/CDP端口/单实例锁/IPC)
renderer.html              # 渲染进程HTML(面板/模态框/编辑器结构)
renderer_v2.js             # 主渲染逻辑(apiGenerate/面板显隐/对话)
panels.js                  # 面板逻辑(_plData/_scData/设定合集/记忆)
style.css                  # 主样式(~8000行)
styles/tokens.css          # 设计令牌(:root变量定义)
styles/buttons.css         # 按钮组件
styles/modal-panel.css     # 模态框/面板
styles/form-editor.css     # 表单/编辑器
js/storage.js              # IndexedDB存储管理(get返回深拷贝)
js/project-manager.js      # 项目管理
js/chapter-manager.js      # 章节管理
js/skill-manager.js        # Skill管理
js/agent-manager.js        # Agent管理
js/provider-manager.js     # API供应商管理
js/pipeline-manager.js     # 生成流水线(5步链路)
package.json               # 版本2.7.6 + electron-builder配置

## 3.2 核心数据流

用户创建项目
  -> 大纲编辑器(导入txt/md/docx 或 AI共创)
    -> 锁定大纲 -> 自动拆解到设定合集
    -> 大纲同步到生成流水线第1步
      -> 第2步设定: 绑定Agent+Skill -> AI生成设定JSON -> 保存到设定合集
        -> 第3步卷纲: 选择卷数 -> AI根据大纲+设定生成卷纲卡片
          -> 第4步章节: 选择章节数 -> AI根据卷纲生成章节卡片
            -> 第5步正文: 选择章节+字数 -> AI根据全部上下文生成正文
              -> 正文写入编辑器 -> 可编辑/导出

## 3.3 API调用链路

apiGenerate(type, params, onChunk, opts)
  -> 读取Agent配置(agentId -> agentManager.get -> systemPrompt + temperature + maxTokens + model)
  -> 读取Skill配置(skillIds -> skillManager.get -> template追加到prompt)
  -> 构建请求: {model, messages:[{role:system,content:systemPrompt},{role:user,content:params+template}], temperature, maxTokens, stream:true}
  -> fetch(provider.baseUrl + "/chat/completions", {headers: {Authorization: Bearer provider.apiKey}})
  -> 流式响应: TextDecoder.decode(chunk, {stream:true})
  -> Skill链式: 多个Skill时，Skill1输出->Skill2输入->Skill3输入
  -> 返回完整文本

## 模式4: "不做删减只做叠加"

正确: 先删后改，新增规则前先删同选择器旧定义

# 第五章: 关键教训精选

## 教训#1: 正则匹配JSON必须配合parse验证
正则 /\[[\s\S]*\]/ 是贪婪匹配，校验报告中的 [WARN]、[OK] 方括号会误匹配。
修复: 正则匹配后必须 try { JSON.parse(match[0]) } catch(e) {} 验证。

## 教训#2: StorageManager.get返回深拷贝
JSON.parse(raw) 每次返回新对象，修改后必须显式调 _saveProjectData 写回。
出现: 10+次数据丢失。

## 教训#3: CSS变量在transition shorthand中解析失败
var()在transition shorthand中返回完整值时无法正确分割，导致transition-duration=0s。
修复: 86处 all var(--transition) 替换为硬编码。

## 教训#4: Electron file://有CSS缓存
修改CSS后必须清缓存重载(Page.reload ignoreCache:true)才能验证。

## 教训#5: PowerShell Set-Content破坏中文UTF-8
修改含中文源文件必须用Node.js fs，不用PowerShell。

## 教训#6: 美容成果未提交git就丢失
8290->8026行的美容成果因未提交，在清零重写时全部丢失。
修复: 每完成一个功能点就提交git。

## 教训#7: GPU全局禁用影响所有用户
为解决个别黑屏问题全局禁用GPU，导致所有用户卡顿。
修复: 删除disable-gpu-compositing，保留硬件加速。

## 教训#8: CDP Runtime.evaluate绕过DOM事件链路
直接调函数->函数返回成功->声称PASS。但用户点击按钮不触发函数。
修复: 必须用Input.dispatchMouseEvent模拟真实点击。

## 教训#9: API Key硬编码
开发时注入的测试API Key(sk-IuR4...)未清理，打包后用户能看到。
修复: 零假数据规则(规则8)。

## 教训#10: Skill链式执行
多个Skill不是自动交互的，需要显式实现Skill1输出->Skill2输入的传递机制。
修复: v2.7.1 Skill链式执行。

## 教训#11: lockOutline反复修复8次
同一个函数，8次提交，每次都声称"修复"，每次用户打开都有问题。
根因: 每次只修一个环节，没有走完完整链路验证。

## 教训#12: .docx不是简单文本文件
.docx是ZIP压缩包，包含XML。必须完整实现ZIP解析+deflate解压+XML提取。
修复: v2.7.3/v2.7.4两轮修复才解决。

# 第七章: Agent协作经验

## 尝试过的协作模式

### 模式1: 主线程独自干(全程大部分时间)
- 问题: 效率低，单线程串行
- 原因: 我总以"线程限制"为借口拒绝使用Agent

### 模式2: 主线程+子Agent分工(07-17 UI美容阶段)
- 尝试: 3个Agent并行完成1583行动态元素样式
- 问题: 子Agent频繁触发429，阻塞主线程
- 教训: 子Agent和主Agent共享API配额

### 模式3: 独立线程(07-25多线程架构)
- 尝试: 创建独立线程处理不同模块
- 问题: 线程间信息不对称，需要监控
- 教训: 主线程负责监控，不抢子进程工作

## Agent协作最佳实践(从失败中总结)
1. 主线程负责架构决策和监控，不抢子进程工作
2. 子Agent负责独立模块的执行(不重叠文件)
3. 429时关闭旧子Agent释放配额再重新spawn
4. 子Agent必须有明确文件范围，避免冲突
5. 所有Agent都必须用目标模式防止断网
6. 主线程时刻监测子进程进展，停止就重启

# 第九章: 给未来自己的备忘

## 永远不要忘记的5件事
1. 验证不是读代码：每次声称PASS前，必须CDP实际操作+截图+行为验证。Runtime.evaluate不算。
2. 正则不是解析器：用正则提取JSON后必须JSON.parse验证。方括号在自然语言中极其常见。
3. get返回深拷贝：StorageManager.get每次返回新对象，修改后必须显式save。
4. 先删后改不做叠加：任何修改前先删除旧代码，不要在上面叠加新规则。
5. 含中文文件用Node.js：永远不用PowerShell Set-Content修改含中文的源文件。

## 用户最在意的事
1. 诚实：用户多次强调"诚实是你最高的标准"。不要声称完成如果没验证。
2. 效率：用户要调用Agent分工合作，不要独自干。
3. 质量：不要为了快而简化，超时就持续等待。
4. 不臃肿：修改要先删后改，不做叠加。
5. 防断网：用目标模式防止网络中断。
