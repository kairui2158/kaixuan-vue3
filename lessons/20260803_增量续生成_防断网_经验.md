## 三大功能模块

### 功能1: 卷纲层增量续生成
- **锁定机制**: 每卷卡片新增"锁定"按钮, vol.locked = true, 锁定后金色边框
- **智能补全按钮**: 工具栏新增, 扫描锁定卷之间的空缺, splice插入新卷
- **续生成后续按钮**: 每卷卡片上, 删除本卷之后未锁定卷, 批量生成后续卷
- **双向上下文**: 智能补全时传入上文卷蓝图+下文锁定卷摘要
- **SKILL联动**: 每卷生成走s3Skills链式执行
- **用户场景**: 8卷中锁2/5/8, 删3/4/6/7, 点智能补全自动检测4个空缺

### 功能2: 章节层分批增量生成 (核心改动)
- **分批生成**: 每批默认5章 (用户可调1-20), 不再一次请求全部章节
- **实时保存**: 每批完成后立即_plPersist落盘 + _plRenderChapterCards刷新UI
- **进度持久化**: pl.genProgress记录 {layer, volIdx, completedCount, expectedCount, status}
- **断点即终点**: API断网时, 已生成章节已保存, 不丢失
- **恢复条UI**: 中断后显示"⚠ 生成中断: 35/214章 [恢复生成]"按钮
- **续生成按钮**: 章节卡片区域常驻, 从当前数量继续分批生成
- **批次大小配置**: HTML新增input, 持久化到pl.chapterBatchSize
- **上下文衔接**: 每批请求传入前10章的标题+剧情梗概摘要

### 功能3: 流式空等检测 + 心跳重连
- **空等检测**: _aiRequest流式读取中, 15秒无新数据 -> abort -> 重试
- **阈值动态调整**: 前3次15秒, 之后缩短到10秒
- **心跳重连**: 8次重试全部失败后, 每60秒发送探测请求, API恢复后自动重试
- **不设上限**: 心跳模式无限循环, 直到API恢复

## 关键设计决策

1. **批次大小默认5章**: 一章一章太慢(300次API), 一次全部又回到老问题, 5章/批约60次调用
2. **上下文传前10章摘要**: 平衡token消耗和剧情衔接质量
3. **心跳60秒间隔**: 不太频繁(避免429), 不太慢(用户等待)
4. **进度条3秒后自动消失**: 完成后给用户确认时间, 然后清理UI

## 教训
1. PowerShell -e "..." 处理中文和转义字符有严重问题, 必须用@'...'@管道传给node
2. apply_patch对包含特殊字符的行号匹配不稳定, Node.js fs.replace更可靠
3. 模拟测试时monkeypatch apiGenerate是验证分批逻辑的最佳方式, 不需要真实API
4. 进度条用sticky定位确保滚动时可见
