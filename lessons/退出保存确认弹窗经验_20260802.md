# 退出保存确认弹窗功能经验 (2026-08-02)

## 需求
用户点击退出键时，弹出全局保存确认弹窗，让用户知道信息是否已保存。

## 原始状态
- main.js的close事件只保存窗口位置，无确认弹窗
- renderer有beforeunload做最终保存，但无UI反馈
- 保存逻辑是同步的（每次修改立即写盘），但用户看不到保存状态

## 实现

### 架构设计
三层联动：main.js拦截close事件 -> 显示native dialog -> 根据用户选择触发renderer保存或直接退出

### main.js修改
1. 用`_forceClose`标志防止close事件死循环
2. `e.preventDefault()`阻止默认关闭
3. `dialog.showMessageBoxSync`显示三个选项的native弹窗
4. "保存并退出"：发送`app:finalSave` IPC到renderer，500ms后强制关闭
5. "直接退出"：直接强制关闭
6. "取消"：不执行任何操作

### preload.js修改
1. 添加`onFinalSave(callback)`：监听`app:finalSave` IPC事件
2. 添加`forceQuit()`：发送`app:quit` IPC

### renderer_v2.js修改
1. 构造函数中初始化`_lastSaveTime = Date.now()`
2. 注册`onFinalSave`回调：执行autoSave + syncTreeToPipeline + plPersist + lastSession保存
3. `autoSave()`中更新`_lastSaveTime`
4. 新增`getSaveStatusInfo()`方法：返回{hasProject, lastSaveTime, projectCount}

## 保存逻辑检查结果
保存覆盖面完整：
- _saveProjectData -> StorageManager.set -> IPC storage:write -> 同步写盘
- _plPersist -> _saveProjectData -> 同上
- autoSave -> 保存编辑器内容到pipeline + ChapterManager
- saveOutlineBlur -> 保存大纲编辑器内容
- beforeunload -> 最终保存（autoSave + syncTreeToPipeline + plPersist + lastSession）
- 30秒自动保存定时器

所有保存都是同步IPC调用，数据在修改时立即写盘。

## 经验教训
1. Electron的close事件用`e.preventDefault()`+`_forceClose`标志的模式是最可靠的关闭拦截方案
2. `dialog.showMessageBoxSync`是同步的，会阻塞直到用户响应，适合做退出确认
3. 保存状态追踪应在每次save调用时更新`_lastSaveTime`，给用户时间反馈
4. `beforeunload`和native close事件是互补的——beforeunload做renderer层保存，native dialog做用户确认
