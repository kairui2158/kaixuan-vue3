# 20260803 硬规则默认启动Bug修复

## 问题描述
用户在生成正文时看到硬规则(降AI方法论)在滚动，但用户并未开启去AI味功能

## 发现的三个问题

### 问题1 (严重): DEAI_METHODOLOGY_PROMPT 无条件注入
- **位置**: renderer_v2.js apiGenerate方法 ~L1111
- **原代码**: `if (type === "body" && typeof DEAI_METHODOLOGY_PROMPT !== "undefined")`
- **问题**: 只要type是body就注入一大段降AI方法论系统提示词，不管用户有没有开去AI味
- **影响**: 每次正文生成都会注入超长系统提示词，增加token消耗+影响生成风格
- **修复**: 改为 `if (type === "body" && this._deAiEnabled && typeof DEAI_METHODOLOGY_PROMPT !== "undefined")`
- **效果**: 只有用户显式开启_deAiEnabled才注入

### 问题2: _deAiEnabled 未初始化
- **位置**: App构造函数
- **问题**: _deAiEnabled属性从未在构造函数中初始化，值为undefined
- **修复**: 在constructor中添加 `this._deAiEnabled = false; this._textFilterEnabled = false;`

### 问题3: 去AI味按钮没有点击事件
- **位置**: renderer_v2.js 按钮绑定区域 ~L535
- **问题**: btn-de-ai按钮存在于HTML中，deAiProcess()方法也写好了，但没有任何地方绑定onclick
- **修复**: 添加 `var _btnDeAi = document.getElementById("btn-de-ai"); if (_btnDeAi) _btnDeAi.addEventListener("click", function() { self.deAiProcess(); });`

## CDP验证 (源码版, 非安装版)
1. 方法论注入条件式: hasConditional=true, isNowSafe=true [PASS]
2. _deAiEnabled初始化: false, type=boolean [PASS]
3. _textFilterEnabled: false [PASS]
4. 文本过滤复选框: checked=false [PASS]
5. 去AI味按钮点击: toastCalled=true, 显示"stats: 81 (去掉2处句首他; 压缩61处感官描写; 合并4处短段落; restructure 14 paras)" [PASS]

## 关键教训
1. 之前所有测试都连接到了安装版(D:\小说工坊\writing-assistant\写作助手.exe)而非源码版，导致修改不生效
2. 必须用 `Get-Process | Select Path` 确认运行的是源码electron.exe还是安装版写作助手.exe
3. 安装版用的是打包时固化进app.asar的旧代码，源文件修改不会影响它
4. 修改后必须重新封装才能让安装版生效
