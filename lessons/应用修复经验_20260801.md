# 应用三Bug修复经验 (2026-08-01)

## 修复概要
修复了三个用户报告的应用bug，全部通过CDP行为验证。

## Bug 1: 大纲编辑器确认后不同步到流水线

### 根因
存储键不匹配：
- ProjectManager.update() 把大纲存到 wa_projects 索引数组
- _plLoadOutline() 从 _getProjectData() 读取，即 wa_project-{id} 单独键
- 两个不同的存储键，_plLoadOutline 永远读不到大纲

### 修复
1. pipeline-manager.js _plLoadOutline: 增加从 ProjectManager.get() 回退读取
2. panels.js lockOutline: 增加同步大纲文本到 project-{id} 数据 (_pLock2.outline)
3. 还增加了从 _pipeline.outlineText 回退读取

### 经验教训
跨管理器的数据同步必须检查存储键是否一致。ProjectManager 和 _getProjectData 用不同的键存数据，导致跨管理器读取时数据"消失"。

## Bug 2: 上下文深度保存后被重置

### 根因
JavaScript falsy 值陷阱：
- parseInt("0") 返回 0
- 0 || 20 在JS中等于 20（因为0是falsy）
- 用户设为0（无限），保存时被覆盖为20

### 修复
1. renderer.html: 默认值从 value="20" 改为 value="0"，placeholder改为"0=不限制(默认无限)"
2. renderer_v2.js: 保存逻辑从 `parseInt(val) || 20` 改为 `var d=parseInt(val); return isNaN(d)?0:d;`
3. renderer_v2.js: 加载默认从20改为0，新建默认从20改为0

### 经验教训
JavaScript的 `||` 运算符对0有陷阱。任何 `parseInt(x) || defaultValue` 的写法在x="0"时都会出错。正确写法是 `var d = parseInt(x); return isNaN(d) ? 0 : d;`

## Bug 3: 设定层缺少确认进入下一层的按钮

### 根因
HTML结构缺失：
- Step 1（大纲层）有"确认大纲，保存并进入下一步"按钮
- Step 2（设定层）只有"AI 生成设定"和"保存设定到合集"按钮
- 没有"确认设定，进入卷纲层"的确认按钮
- 用户在设定合集里选择启用项后，显示在流水线设定层，但无法确认进入卷纲层

### 修复
1. renderer.html: 在设定层pl-actions中增加 btn-pl-confirm-settings 按钮
2. pipeline-manager.js: 增加 _plConfirmSettings 函数（保存设定、标记settingsConfirmed、跳转step 3）
3. pipeline-manager.js: _plBindEvents 绑定新按钮的onclick
4. pipeline-manager.js: _plGoNext 更新为支持 settingsConfirmed 标志
5. pipeline-manager.js: _plData 初始化增加 settingsConfirmed: false

### 经验教训
流水线的每一层都需要有明确的"确认并进入下一层"按钮，不能只依赖导航按钮。导航按钮"下一步"如果没有确认逻辑，用户会卡在某一层无法前进。
