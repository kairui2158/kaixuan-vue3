# 20260803 全维度检查经验

## 最严重发现: CSS"只加不删"是应用最严重的系统性问题

### 问题描述
style.css 共有 128 个重复选择器。其中 11 个是非媒体查询的真冲突——同一选择器在非 @media 块中被重复定义，后面的覆盖前面的，旧定义成为死代码。

### 最严重的案例
- `.pl-steps` 被定义了 9 次（含媒体查询内变体）
- `.pl-step` 被定义了 9 次
- `.pl-step-num` 被定义了 8 次（含子选择器变体）
- `.pl-skill-bar` 被定义了 5 次
- `.pl-step-status` 在非媒体查询中被定义了 3 次，3 个版本属性不同，只有最后一个生效
- `.msg-btn` 连续 3 行定义同一个选择器（L542、L543、L553），属性分散在三处

### 根因分析
每一轮"美容"或功能迭代时，开发者在 style.css 中新增规则但不删除同选择器的旧定义。这和 PACKAGING_LESSONS 教训 #2 早在 v2.0.0 就记录的"先删后改"规则完全一致——但一直在违反。

CSS 层叠机制下后面的定义覆盖前面的，旧定义仍然存在于文件中，造成：
1. 文件体积膨胀——style.css 达到 249KB / 7330 行
2. 属性覆盖不可预测——如果有人把新定义移到旧定义前面，样式立刻崩
3. 调试困难——开发者看到某个选择器的样式不对，找到第一处定义以为是生效版本，但实际生效的是后面的
4. 属性丢失风险——合并时容易漏掉旧定义中独有的属性（如 scroll-behavior:smooth 差点丢失）

### 修复
本轮合并了 11 个非媒体查询真冲突，将分散的属性合并到最后一处定义，旧定义替换为注释。合并后花括号平衡仍为 0。

### 必须变成 GATE 门禁的规则
1. **禁止 CSS 叠加**: 修改任何 CSS 选择器的属性时，必须先找到该选择器的所有定义，合并到一处，删除其余
2. **新增前先搜**: 新增 CSS 规则前，先用全文搜索确认该选择器是否已存在。已存在则修改原定义，不允许新增第二处
3. **CSS 修改三步法**: (1) 全文搜索选择器 (2) 找到所有定义 (3) 合并到最后一处、删除前面的
4. **封装前检查**: 每次封装前必须运行重复选择器检测脚本，非媒体查询真冲突必须为 0

### 剩余问题
114 个重复选择器中大部分是不同布局区域的同名 class 重新定义（CSS 层叠机制下最后一个生效）。彻底合并这些需要逐个人工判断保留哪些属性，风险高，不在本次封装中处理。但理想状态下应该全部合并。

## 删除的死代码
1. _plSupplementChapters (pipeline-manager.js L1479-L1507): 旧的全量补全逻辑，被分批生成_plGenChaptersBatched取代
2. _syncChapterEdit (panels.js L1254-L1280): 定义了但无任何调用

### 死代码根因
功能重构时（如从全量生成改为分批生成），新方法写好了、调用方也切换了，但旧方法忘了删。旧方法不会报错（因为不被调用），但占用代码体积、增加维护成本、可能被误认为是可用接口。

### 死代码教训
重构功能后，必须扫描旧方法是否还有调用方。App.prototype 方法扫描是找死代码的有效方式——127 个方法中 2 个未被调用，精准定位。

## 检查方法论（可复用）
1. **语法检查**: node --check 对所有核心 JS 文件
2. **CSS 花括号平衡**: open={ count - close=} count = 0
3. **CSS 重复选择器**: 正则提取所有选择器，统计非 @media 块内的重复
4. **死代码扫描**: 提取所有 App.prototype.X，搜索 .X( 调用，无调用的即为死代码
5. **HTML 引用完整性**: 提取所有 getElementById 的 ID，对比 HTML 中的 id 属性，缺失的检查是否动态创建
6. **文件间方法冲突**: 对比 renderer_v2.js / panels.js / pipeline-manager.js 的 App.prototype 方法列表
7. **CDP 行为验证**: 启动应用后用 Playwright CDP 验证功能正常（不只是检查元素存在）

## 核心教训总结
1. **CSS"只加不删"是反复违反的系统性问题**——教训#2早就写了但一直在犯，必须变成 GATE 门禁
2. App.prototype方法扫描是找死代码的有效方式
3. getElementById引用的ID不在HTML中不等于bug，需要检查是否动态创建
4. CSS冲突合并后必须检查花括号平衡，容易因插入/删除行导致选择器丢失
5. 根目录废旧文件不影响应用运行但影响git仓库整洁和开发效率
6. 功能重构后必须扫描旧方法调用方，无调用的立即删除
