# 三Bug修复经验：去AI味供应链 + DiagLogger API + multi-step按钮
# 日期: 2026-08-07
# 版本: v2.7.55 -> v2.7.56

## 问题清单

### 问题1：更改供应商用途后，去AI味界面AI验证AI状态不更新
**根因**: ProviderManager.add() 不保存 purpose 字段。新建供应商时传入 purpose，但 add() 的对象字面量只包含 id/name/baseUrl/apiKey/models/createdAt，purpose 被丢弃。
**修复**: 在 provider-manager.js 的 add() 方法中补充 purpose/streamMode/temperature/maxTokens/systemPrompt 字段。
**验证**: CDP确认 ProviderManager.add.toString().includes('purpose') === true，getVerifyProvider() 返回正确供应商。

### 问题2：去AI味模式卡片里，添加SKILL按钮点击后无法加载（multi-step模式）
**根因**: 前一个模型已添加 deai-skills-list-ms 容器渲染逻辑，但 deAI设置页未打开时 select 未被 renderDeAiSettings() 填充。renderDeAiSettings 调用后 opts 从1变为18。
**修复**: 确认 _renderDeAiSkillList() 已处理 containerMs 克隆渲染；补充 multi-step 按钮的 DiagLogger 错误日志。
**验证**: CDP确认 btn/sel/list 全部存在，renderDeAiSettings() 触发后 opts=18（17个技能+1占位符）。

### 问题3：按钮无效等操作错误时，日志没有记录
**根因**: 7处 DiagLogger.log("deai", msg) API调用全部错误。DiagLogger.log(level, cat, msg) 第一个参数是 level（error/warn/info/debug），但代码把 category 当 level 传了。日志虽然写入 buffer 但 cat 变成了消息文本，按 deai 分类筛选找不到。
**修复**: 全部改为 DiagLogger.info("deai", msg)。
**验证**: CDP确认 _updateVerifyProviderStatus() 触发后，DiagLogger.read() 返回的日志中 cat=deai 的条目正确出现。

## 深层教训

### 教训1：DiagLogger API 签名混淆
DiagLogger 有两种调用方式：
- log(level, cat, msg, detail) — 需要传 level 字符串
- info(cat, msg, detail) / error(cat, msg, detail) / warn(cat, msg, detail) — level 已内置
错误用法：DiagLogger.log("deai", "message") — 把 category 当 level
正确用法：DiagLogger.info("deai", "message") — level 内置，category 在第一位
**规则**: 永远用 info/error/warn/debug 方法，不用 log()。

### 教训2：CDP验证脚本的结构陷阱
CDP Runtime.evaluate 的响应结构是 {id, result: {result: {type, value}}, exceptionDetails?}，不是 {id, result: {value}}。
正确提取值：r.result.result.value 或 r.result.value（取决于CDP版本）。
returnByValue:true 在简单表达式上有效，但 awaitPromise:true 只对返回 Promise 的表达式有效，对普通表达式会导致 undefined。

### 教训3：闭包私有变量不可外部访问
DiagLogger._buffer 是闭包私有变量，不暴露为 DiagLogger._buffer。必须用 getStats() 和 read() API 访问日志数据。
验证日志正确性：DiagLogger.read() 返回日志数组，按 entry.cat 筛选。

### 教训4：PowerShell转义地狱
含引号的 Node.js inline 脚本在 PowerShell 中无法正确传递。解决方案：
1. 用 Write 工具写临时 .js 文件
2. node _temp.js 执行
3. 执行后删除临时文件
禁止：node -e "含嵌套引号的脚本"
