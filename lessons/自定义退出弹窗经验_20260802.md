# 自定义退出确认弹窗经验 (2026-08-02)

## 需求
将退出确认弹窗从 Windows 原生 dialog.showMessageBoxSync 替换为应用内自定义 HTML/CSS 弹窗，匹配深色主题视觉风格。

## 实现架构

### 异步 IPC 通信链
1. main.js close 事件 -> e.preventDefault() -> 发送 app:requestClose IPC 到 renderer
2. renderer 收到 app:requestClose -> 显示自定义弹窗
3. 用户点击按钮 -> renderer 发送 app:closeChoice IPC 回 main（choice: 0/1/2）
4. main 收到 choice -> 执行对应操作（保存退出/直接退出/取消）

### 关键设计决策
- 使用 ipcMain.once + removeAllListeners 防止重复监听器
- 每次 close 事件先 removeAllListeners("app:closeChoice") 清除旧监听器，再注册新的 once
- 防止用户快速多次点关闭按钮导致多个监听器堆积

### contextBridge 冻结对象限制
- contextBridge.exposeInMainWorld 返回的对象是 Object.isFrozen() === true 的
- 无法在 renderer 端 monkey-patch 替换 respondCloseChoice 来拦截测试
- 测试方法改为：验证 modal 隐藏（证明 handler 执行）+ 直接调用 respondCloseChoice（证明 IPC 可达）

## 经验教训

1. contextBridge 对象是 frozen 的，不能在测试中 monkey-patch。验证 IPC 需要用间接方法（检查副作用而非拦截调用）
2. ipcMain.once 只触发一次就自动移除，但 close 事件每次都会重新注册。用 removeAllListeners 前置清除可防止重复监听器堆积
3. 应用现有 modal 系统使用 .modal + .modal-hidden 类选择器（非 ID 选择器），新弹窗只要带这些类就自动获得样式，无需额外 CSS
4. 异步 IPC 通信链比同步 showMessageBoxSync 复杂，但视觉一致性和用户体验更好
5. 重启应用测试前必须确保旧进程完全终止，否则 CDP 会连到旧实例

## UI规格升级 (2026-08-02 第二轮)

### 发现的问题
1. Header缺少x关闭按钮（所有其他弹窗都有btn-close）
2. Footer三按钮布局不统一：保存并退出和直接退出挤在左侧，取消单独在右侧
3. 按钮顺序不符合标准模式

### 修复内容
1. Header添加btn-close按钮（class=exit-close）
2. Footer重构为标准布局：取消(btn-secondary)在左 + div.footer-right包裹直接退出(btn-secondary)+保存并退出(btn-primary)在右
3. CSS的:is(.modal-footer)>:is(.btn-secondary)规则给取消自动margin-right:auto推到左侧
4. .footer-right类触发margin-left:auto把操作按钮组推到右侧
5. div内的按钮不是modal-footer直接子元素，不触发auto margin，保持紧凑
