# 三、改动详细方案

## 3.1 硬规则层 (de-ai.js)

### 3.1.1 的/地替换 + 特例词库

**规则**: 将结构助词地替换为的, 但排除特例词

**特例词库**(按类别分组, 持续补充):

**地名/方位词**: 地上 地下 地面 地板 地毯 地图 地方 地位 地段 地区 地域 地带 地基 地震 地质 地形 地理 地球 地点 地窖 地牢 地道 地铁 基地 阵地 工地 耕地 田地 荒地 空地 草地 林地 沙地 泥地 湿地 旱地 洼地 坡地 山地 领地 封地 飞地 属地 租地 占地 用地 异地 原地 就地 当地 产地 腹地 要地 胜地 圣地 净地 谷地 盆地 高地 低地 实地 场地 目的地

**副词语**: 忽地 蓦地 陡地 猛地 倏地 骤地 顿地 猝地 暗地 私地

**固定搭配**: 似的 真的 的确 特地 故地 本地 外地 内地 随地 顺地 落地 着地 坠地 碎地 满地 遍地 一地 心地(心地善良)

**疑问/指示**: 怎样地 这么地 那么地 什么地

**实现逻辑**:
1. 扫描文本找到所有地字
2. 对每个地检查前2字+后1字是否匹配特例词库
3. 匹配则跳过, 不匹配则替换为的
4. 记录替换数量输出到控制台

**注意**: 参考一字多用原则, 的/地替换必须考虑上下文, 不能全局正则替换

### 3.1.2 顿号到逗号

**规则**: 将中文顿号、(U+3001)替换为中文逗号，

无特例, 可直接全局替换。只替换中文顿号, 不替换日文顿号

### 3.1.3 AI高频词检测标记

检测以下高频词, 标记但不删除(供S2重述师参考):

缓缓地 不禁 一抹 深邃的 值得注意的是 综上所述 与此同时 不仅...而且 然而 因此 此外 另外 总的来说 总而言之 首先 其次 最后 值得一提的是 众所周知 不可否认 毫无疑问 显而易见 换言之 简而言之 由此可见 在这个过程中 在这个背景下 随着...的发展

检测到的高频词列表附加到输出metadata, deAiProcess读取后注入S2 prompt前缀

### 3.1.4 补全连接词删除

在现有7条基础上补充: 然而 因此 另外 不仅...而且 显而易见 毫无疑问 由此可见

### 3.2.2 动态流程预览区块

新增 div#deai-flow-preview, 监听3个事件动态更新:

**串行链式模式预览**:
硬规则清洗(<1秒) -> SKILL重述(level=中, 3-6秒) -> SKILL验证(3-4秒) -> 完成
预计总耗时: 真实计算

**Agent调度模式预览**:
硬规则清洗(<1秒) -> 切分文章(<1秒, N段) -> 并行重述(level=中, 3-6秒) -> 合并(<1秒) -> SKILL验证(3-4秒) -> 完成
切分参数: 1000字/段, 浮动700-1300字
预计总耗时: 真实计算

### 3.2.3 耗时真实计算公式

根据编辑器字数和设置实时计算:

```javascript
var editorLen = editor.value.length;
var splitSize = _deAiConfig.splitSize || 1000;
var skillCount = _deAiConfig.skills ? _deAiConfig.skills.length : 1;

// 串行链式: 硬规则 + N个SKILL + 验证
var chainTime = 0.5 + (skillCount * 4) + 3.5;

// Agent调度: 硬规则 + 切分 + 并行重述(取max) + 合并 + 验证
var segments = Math.ceil(editorLen / splitSize);
var parallelTime = 0.5 + 0.5 + Math.ceil(segments / 3) * 4 + 0.5 + 3.5;

// V2版本耗时 x0.8 (保守模式更快)
if (version === 'v2') { time *= 0.8; }
```


### 3.3.2 level到temperature映射(3档)

| 档位 | level值 | V3 temperature | V2 temperature |
|------|---------|----------------|----------------|
| 轻 | light | 0.4 | 0.28 |
| 中 | medium | 0.7 | 0.49 |
| 重 | heavy | 1.0 | 0.7 |

V2 temperature = V3 temperature x 0.7

### 3.3.3 SKILL prompt前缀注入

调用SKILL时, 在用户文本前注入参数前缀:

```
[去AI味参数]
文体类型: novel
改写版本: v3
改写强度: medium (temperature=0.7)
AI高频词检测: 缓缓地(2次), 不禁(1次)

[以下为待处理文本]
{用户文本}
```

S2重述师读到前缀, 知道用什么文体策略和改写强度

### 3.3.4 风格样本注入

新建 js/deai-samples.js, 存储38个人类写作样本

deAiProcess调用S2验证师时, 自动将样本拼接进prompt:

```javascript
var samples = DeAiSamples.getAll();
var sampleText = samples.join('\n');
var prompt = skillTemplate + '\n\n[风格参考样本]\n' + sampleText + '\n\n[待验证文本]\n' + text;
```

### 3.3.5 Agent调度模式动态level

切分后的每段, 根据内容特征动态调整level:

```javascript
// 对话密集段落 -> 降一级(对话本身AI味低)
// 描写密集段落 -> 保持或升一级(描写AI味高)
// 动作密集段落 -> 降一级(动作词AI味低)
// 心理描写段落 -> 升一级(心理描写AI味高)

// 段落内容检测方法:
// 对话密集: 引号占比 > 30%
// 描写密集: 形容词/副词占比 > 15%
// 动作密集: 动词占比 > 25%
// 心理描写: 想/觉得/感到/意识到 等词频率 > 3次/100字
```

### 3.3.6 renderDeAiSettings新增控件绑定

参考教训#83: 事件监听器必须在render中绑定

新增3个控件的change事件绑定:
- deai-level: 3个radio的change事件 -> 更新_deAiConfig.level
- deai-version: 2个radio的change事件 -> 更新_deAiConfig.version
- deai-text-type: 下拉change事件 -> 更新_deAiConfig.textType

### 3.3.7 _updateFlowPreview方法

新增方法, 在任何参数变化时调用, 重新渲染预览区块HTML

### 3.3.8 _syncDeAiConfigFromDOM新增字段

参考教训#83: DOM是执行时数据源

在_syncDeAiConfigFromDOM中新增读取3个新字段
