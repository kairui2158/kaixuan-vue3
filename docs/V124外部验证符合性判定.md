# V124 外部验证符合性判定

> 判定对象：`D:\codex\还原实验\踏星\V99大纲升级\V124交接包`
> 对照目标：神意助手 `D:\codex\novel-workshop-vue3`
> 结论：**当前应用不构成 V124 原生外部验证器；必须先做章包桥接适配，否则不符合。**

## 2. 应用侧关键缺口

### 2.1 缺少 V124 章包加载器

应用正文层消费的是 `ChapterExecutionPackage`、`contextScope.closure`、章节 `title/plot` 与项目态，不识别：

```text
V124-LLM-PROSE-CONTRACT-1.0
source_sha256
card.event_chain
card.causal_order
card.required_sentence_types
card.prev_state
next_hint
generation_contract
```

全仓检索 `source_sha256|V124-LLM-PROSE-CONTRACT|前章状态|生成合同|chapter_pack|交接包` 无命中。因此应用当前不能把 V124 章包作为唯一事实源直接送入正文层。

### 2.2 直接导入 V107 会触发应用原生再分配，偏离 V124

`V107大纲_全书_自包含.md` 约 47,244,105 字节、325,920 行。它可以导入大纲工作台，但应用会按自身链路提取设定、生成或校验卷纲、分配章节。

这与 V124 协议冲突：

- V124 已经固化 224 个章包，章卡应当是正文层唯一执行事实。
- 不允许应用重新发明章节结构。
- 不允许下游把 `next_hint` 当成可改写的章纲。

### 2.3 V107 大纲缺少应用正文闭包作用域

应用 `outlineContextScope.ts` 需要如下结构：

```markdown
## 剧情单元 U001：xxx
> 作用域：单元级 U001｜章节范围：第 1-10 章
```

V107 当前只有 `## 0` 至 `## 11` 顶层段落，未发现 `> 作用域：` 声明。应用会判定为 legacy outline，正文闭包显式降级，只保留卷概要和当前章细纲，不能提供 V124 章包要求的全部硬约束。

## 3. 符合性结论

| 验证形态 | 判定 |
|---|---|
| V124 原生外部验证 | 不符合 |
| 直接导入 V107 后跑应用五层流水线 | 不符合，会破坏 V124 章卡权威 |
| 使用应用作为供应商/UI 执行器，但另做 V124→应用章包桥接 | 半符合，桥接验收后可用 |
| 纯外部 LLM 按 V124 协议直读章包 | 符合，这是当前最干净的路径 |

## 4. 若要用应用执行 V124，必须满足的最小桥接门禁

1. 新增 V124 章包导入器，读取 `LLM章包/*.json`，禁止导入原著。
2. 校验每包 `schema`、`source_sha256`、章节号与 `交接索引.json` 一致。
3. 将章包映射为正文层执行事实，不得经过设定层、卷纲层、章节层再分配。
4. `card.causal_order`、`required_sentence_types`、`chapter_hook`、`prev_state`、`next_hint`、`generation_contract` 必须原样进入正文 prompt。
5. `chapter_density_target` 必须转成应用 `targetWords/minWords/maxWords`。
6. 生成后必须保留 `source_sha256`、章包路径、章号、契约版本到 `generationMetadata`。
7. 输出正文不得包含标题、要点、解释、工具协议残留。
8. 外部验收继续使用 V124 的零源检查与 `_v107_compare.py` 事件命中口径。

## 5. 推荐路径

短期：直接用独立外部 LLM 消费 `LLM章包/*.json`，这是最符合 V124 协议的验证。

若必须接入神意助手：先写桥接导入器，再禁用中间三层的重分配行为，只保留正文执行、RunTrace、供应商通道和产物落盘。桥接完成后，应用可以承担执行面板和追踪器职责，但仍不是 V124 的大纲重解析器。
