## 执行总原则

1. 行为等价是最高约束，不能只改按钮表面；没有真实行为验证，不标完成。
2. 一次只修一个功能闭环，不批量改无关功能。
3. 每项执行固定模板：精准修改 → 构建 → 杀 Electron 进程 → start-electron.bat → CDP 操作 → DOM/状态/持久化递归验证 → 截图和数据日志。
4. 未通过真实 CDP 行为验证的不做 PASS；禁止用代码存在代替功能通过。
5. 不使用开发版启动器，不使用 PowerShell 临时脚本修改真实项目数据，问题优先用源文件启动器复现。
6. 每次完成阶段后更新经验文件、开发日志并提交 GitHub 私有仓库。
7. 动画/短剧板块标记为“待接入”，不列入本阶段验收完成条件。

### 每个阶段的固定执行模板

1. 读取对应源码和经验规则（`memory/rules.md`、`_audit/神意开发经验总结*.md`）。
2. 画出该闭环：输入 → 处理 → store → UI → 持久化 → 下游。
3. 只删除旧行为，再写唯一的新行为，不留双份实现。
4. `npm run build:vue`。
5. `taskkill /f /im electron.exe`。
6. 使用 `start-electron.bat` 启动源版应用。
7. CDP 模拟真实用户操作：点击、输入、检查 DOM、Pinia 状态、持久化存储。
8. 检查 DOM、Pinia 状态、项目存储和下游联动。
9. 截图保存到 `test_evidence/`，记录命令日志和验证结果。
10. 通过后更新对账表、经验文件和开发日志。
11. `git commit` + `git push`（经验规则 11）。
12. 进入下一闭环。

## P1：主编辑器记忆入口闭环

### 问题描述

审计结论：正文记忆抽取入口只存在于生成流水线正文层（`PipelinePanel.vue:2237-2320`），主页面编辑器（`EditorPanel.vue`）没有同等入口。

用户实际表现：用户在主编辑器写完正文 → 保存 → 正文存入 `ch.body` → 项目持久化；但记忆系统不动，不触发抽取、不生成审核预览、不写入记忆库。用户必须改走生成流水线正文层才能触发记忆提取，与旧架构行为不等价。

### 修复方案

把 `PipelinePanel.vue` 的 `confirmBodyWithMemory()` 完整流程抽成可复用 composable `useMemoryExtraction`，`EditorPanel` 和 `PipelinePanel` 共用，禁止复制两份。

新文件：`src/composables/useMemoryExtraction.ts`

输入：

- `chapterId: string`
- `chapterIndex: number`
- `chapterTitle: string`
- `content: string`
- `callAi: MemoryAiCall`
- `timeoutMs?: number`（默认 30000）

输出状态（全部 Ref，单一事实来源在 store）：

- `loading`：抽取中。
- `error`：中文错误信息；正文已保存不回滚。
- `previewVisible`：审核预览开关。
- `previewChanges`：合并提议变更列表，带逐条 review 状态。
- `extracted`：本次抽取原始结果。
- `extractMemory()`：正文落盘 → `extractMemory()` → `mergeMemory()` → 生成审核预览。
- `confirmMemory()`：过滤拒绝项 → 重新 `mergeMemory()` → `recordMemoryChange()` → 关闭预览。
- `closeMemory()`：仅清理 composable 状态。
- `filterReviewed(extracted, reviewMap)`：按审核结果过滤。

行为闭环（与流水线现有行为逐条对齐）：

1. 正文先落盘：`ch.body = content`、`bodyGenerated = true`、`saveProject()`、`refreshTree()`；抽取失败不撤销正文。
2. `extractMemory(input, callAi, timeoutMs)` → `ExtractionResult`。
3. 成功 → `mergeMemory(projectStore.memories, result.data, { chapterId, chapterIndex, blacklist })` → 展示 `changes`。
4. 用户逐条审核（保留/拒绝）→ 确认。
5. `projectStore.recordMemoryChange(merged.data, { chapterId, chapterIndex, reason })` → 记忆面板响应式更新 → 项目落盘。
6. 失败 → 预览区显示“记忆抽取失败：xxx。正文已保存。”

修改文件：`src/components/editor/EditorPanel.vue`

修改点：

1. 导入 `useMemoryExtraction`。
2. 工具栏增加 `#btn-extract-memory` 按钮，`v-if="isBodyMode"`（仅正文模式显示），`disabled` 绑定 loading。
3. 正文保存后按钮点亮；点击后调用 `extractMemory()`。
4. 审核预览在 EditorPanel 内以 `v-if` 渲染（先内联，不抽独立组件，避免批量重构）。
5. `PipelinePanel.vue` 改为调用同一 composable（或仅在必要时保留差异层），确保两个入口行为一致。

CDP 验收：

1. 正文模式保存 → 点击 `#btn-extract-memory` → 网络请求出现（`POST .../chat/completions`）。
2. 抽取成功 → 审核预览显示变更条数。
3. 拒绝某条 → 确认 → 记忆面板该条不出现。
4. 锁定字段 → 再次抽取确认 → 锁定字段不变。
5. 卷纲/章节模式不显示 `#btn-extract-memory`。
6. 每次点击与写入都留截图和请求体证据。

## P3：错误路径验证闭环

审计结论：抽取服务有超时/重试和 JSON 解析代码，但未做真实错误路径验证。

### P3.1 API 断网

1. 正文保存 → 点击提取记忆 → 阻断网络（或拦截 API 域名）。
2. 面板显示“记忆抽取失败：xxx。正文已保存。”
3. `ch.body` 不回滚；恢复网络后再次点击可正常抽取。

### P3.2 API 超时

1. 临时将 `timeoutMs` 设短（如 5 秒）完成验证后恢复默认。
2. 超时 → 中文错误提示 → 正文不回滚。

### P3.3 非法 JSON 响应

1. 注入返回非 JSON 文本的 `callAi`。
2. 第一次解析失败 → 自动重试一次。
3. 重试失败 → 提示“AI 返回内容不是合法记忆 JSON”。
4. 正文不回滚，记忆库不写入脏数据。

### P3.4 审核拒绝项不写入

1. 审核预览中拒绝条目 → 确认 → 记忆面板该条不出现。
2. 记录拒绝前/后 store 快照对比，证明拒绝项未进入 `memories`.

### P3.5 锁定字段不被后续抽取覆盖

1. 实体 `lockedFields` 含 `description`。
2. 再次抽取同一正文并确认 → description 不变，其他字段可更新。

### P3.6 黑名单生效

1. `projectStore.memoryBlacklist` 添加实体名。
2. 抽取包含该实体的正文 → 确认后黑名单实体不进入结果。

每个错误路径独立验证、独立截图与日志，禁止合并自称 PASS。
