# 一、生成流水线链路(核心五层联动)

## 1.1 大纲层到设定层
- 输入: 大纲全文 + 大纲基调锚点 + 叙事风格五维度
- 动作: 点击"AI生成设定"按钮
- 处理: _plGenSettings() 读取pl.outlineText, 构建约束文本, 注入SKILL/Agent配置, 调apiGenerate
- 输出: 设定JSON保存到pl.settings
- 确认: 点击"保存设定", settingsGenerated=true

## 1.2 设定层到卷纲层
- 输入: 大纲 + 设定JSON + 每卷字数分配
- 动作: 点击"AI生成卷纲"/"自动生成"/"逐卷生成"
- 处理: _plGenVolumes()/_plAutoGenVolumes()/_plContinueGenVolumes()
- 输出: 卷纲JSON数组, 每项含name/outline/summary/suggestedWords
- 确认: 点击"全部确认卷纲"
- 续生成: _plResumeGen() 从断点继续
- 增量更新: 修改某卷后只重新生成该卷, 其他卷保留

## 1.3 卷纲层到章节层
- 输入: 单卷蓝图(卷纲outline) + 本卷总章数 + 单章字数
- 动作: 点击"AI生成章节"/"自动生成章节"
- 处理: _plGenChapters()/_plAutoGenChapters(), 按卷纲字数除以单章字数=章节数
- 输出: 章节JSON数组, 每项含title/plot
- 确认: 点击"全部确认章节"
- 防断网: 每生成一章就展示+保存, 断网后从断点续跑

## 1.4 章节层到正文层
- 输入: 章节plot + SKILL配置 + Agent配置
- 动作: 点击"AI生成正文"
- 处理: _plGenBody() 注入SKILL/Agent, 调apiGenerate
- 输出: 正文文本
- 确认: 点击"插入到编辑器"到"确认正文"

# 二、供应商管理链路

## 2.1 供应商配置
- 供应商列表: ProviderManager管理, 每供应商含name/baseUrl/apiKey/models/temperature/maxTokens
- 供应商用途: generate(生成)/verify(验证)
- 多供应商: A供应商全局生成, B供应商验证(去AI味), 各自独立
- 模型获取: 点击"获取模型"到api:fetchModels IPC到主进程请求到返回模型列表到写入ProviderManager到下拉显示

## 2.2 验证供应商
- 去AI味界面显示当前验证供应商状态(已连接/未连接)
- 用户切换验证供应商后去AI味界面自动同步

# 三、SKILL链式执行链路

## 3.1 SKILL排序
- SkillManager管理, 支持上下箭头排序
- 链式执行: SkillExecutionEngine.chain() 按顺序调用
- SKILL1输出到SKILL2输入到SKILL3输入

## 3.2 三种执行模式
- 串行链式(chain): 硬规则pre到S1改写到S2验证到硬规则post
- Agent调度(split-merge): 切分到并行重述到拼接
- multi-step: 事件核提取到视角偏转到重组输出到验证

## 3.3 验证器
- first_subject_different: 首句主语对比
- zhuque_check: 朱雀AI检测
- cross_model_check: 跨模型验证(AI验证AI)

# 四、去AI味链路

## 4.1 触发
- 编辑器工具栏点击"去AI味"按钮

## 4.2 串行链式流程
原文到S1改写(在原文上)到硬规则pre到S2验证(低温0.2-0.3)到硬规则post到写回编辑器

## 4.3 Agent调度流程
本地代码切分(1000/1500/2000字, 语义溢出浮动)到Promise.all并行重述到按顺序拼接写回编辑器

## 4.4 multi-step流程
调用1(提取事件核)到代码验证(事件核数量)到调用2(选偏转视角)到代码验证(偏转方法轮换)到调用3(重组输出)到代码验证(首句主语对比)到S2验证

## 4.5 关键约束
- 执行顺序: S1先跑(原文上改写), 不是硬规则先跑
- 风格样本: 应用层按段落相似度挑2-3个注入S1, S2不拿样本
- SKILL放在system message里, 不是user message里
- S2用低温(0.2-0.3)保证最小修正
- 进度条弹窗实时显示百分比+当前步骤

# 九·补、Vue3 Electron 运行时链路

## 9.1 启动链路
- `start-electron.bat` 检查 `node_modules/electron/dist/electron.exe` 与 `dist-renderer/index.html`
- 存在 `dist-renderer` 时以 `electron.exe --remote-debugging-port=9223` 启动主进程
- `electron/main.js` 注册 `dialog/storage/diag/api/crypto/lifecycle` 各 IPC handler
- 加载 `dist-renderer/index.html`（生产模式）或 `http://localhost:5173`（`--dev` 模式）

## 9.2 渲染进程链路
- `src/main.ts` 创建 Vue App + Pinia，挂载到 `#app`
- `App.vue` 组合 SidebarNav/ChapterTree/EditorPanel/ChatPanel 及各面板组件
- Store 层：project/chapter/editor/provider/agent/skill/deai/pipeline/settings/theme
- Service 层：StorageManager/diag/logger/file-import/pipeline-manager 等
- 所有数据经 `window.electronAPI.storage*` 落盘到主进程 `userData/data/*.json`

## 9.3 打开文件链路（2026-08-13 已修复并验证）
1. `ChapterTree.vue` 点击"打开"按钮 → `dialogOpenFile()`
2. preload 同步发送 `dialog:openFile` → 主进程 `ipc/dialog.js` 弹原生选择框
3. 返回路径后 → `dialogReadFile(path)` 同步发送 `dialog:readFile`
4. 主进程 `fs.readFileSync(path,'utf8')` 读回 `{path, content}`
5. 渲染层自动新建临时项目、写入大纲前 500 字、以 `ch-body` 模式打开编辑器 Tab

> 修复记录：`electron/ipc/dialog.js` 原先漏写 `require('fs')`，导致 `dialog:readFile` 恒返回 null。
> 已于 2026-08-13 修复并通过 CDP 行为级验证（真实 Electron 进程读回测试文件内容成功）。

# 十、防断网续生成链路

## 10.1 章节生成防断网
- 每生成1章: 立即在界面展示单章框架+保存到IndexedDB
- 空等时间高于3秒: 自动重新请求API从断点处续跑
- API无反应: 持续发送启动信号(每5分钟一次)
- 续生成按钮: 用户可随时点击从已保存的断点继续

## 10.2 卷纲生成防断网
- 每生成1卷就展示+保存, 断网后从断点续跑

## 10.3 429限流应对
- 递增重试: 30s->60s->90s->120s->150s->180s->210s->240s, 共8次
- 重试期间做本地工作, 不空等
- 429解除后从断点继续, 不从头重来
